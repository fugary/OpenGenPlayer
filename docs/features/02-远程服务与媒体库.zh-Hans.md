# 模块 02：远程服务与媒体库（SMB/WebDAV/Jellyfin/Emby/Plex）

## iOS 媒体库交互一致性（2026-09-25）

- Jellyfin / Emby / Plex 首页轮播的海报、背景和文字区域打开详情；只有播放/继续按钮进入播放。剧集保持进入所属剧集详情、播放按钮续播的原语义。这是全 iOS 规则，不限定 Duo。
- Jellyfin / Emby / Plex 详情统一安全区与播放按钮宽度：普通布局左右分别避让，iPhone 窄布局填满可用内容宽度，iPad/宽布局限制最大宽度为 360。iOS 27.1+ 窄屏手机使用原生侧栏时，正文不恢复侧栏一侧的整高留白，海报和按钮按扩展后的内容区居中；横向卡片仍保留首尾安全停靠。移除 Plex 独有的额外 36 点播放按钮内缩；不调整详情的信息顺序与现有功能。
- Emby 的全屏安全区声明移到几何测量容器外，与 Jellyfin/Plex 保持同层级；三类详情的操作行按可用宽度换行，保留原动作与启用条件，避免固定间距反向撑宽内容安全区。
- Plex 分类默认直接展示当前库的类型、年份筛选与媒体列表，不在顶部常驻“项目/合集”分段控件；当前媒体库与合集的切换收口在原生视图菜单的“浏览”分区，合集模式显示“合集”标题，菜单中可返回原媒体库。合集仍限定在当前库，不合并不同库或删除合集功能。筛选使用服务器返回的选项和值，不从已加载第一页推断全库选项；查询、筛选、排序和分页隔离过期响应，合集不沿用电影/剧集筛选，也不显示影片库总量。
- macOS/tvOS 的页面与交互不跟随本次 iOS 对齐调整；现有共享服务调用的默认请求保持不变。
- Duo「查看全部」按用户最新选择保留原靠右位置；横向卡片可延伸，不据此让固定交互按钮绕过安全区。未实现基于原生侧栏按钮实际范围的动态位置移动。
- Plex 筛选遵循[官方媒体库查询说明](https://developer.plex.tv/pms/)：保留服务器选项值，解析相对/绝对 key 或 fastKey 的筛选字段，在当前库的分页请求中组合类型、年份和搜索。服务端不提供选项时保留原浏览入口；真实服务器组合筛选仍需抽样。

## Web VOD（MacCMS）内容浏览与数量语义（2026-09-14）

- 2026-09-19 后续修订：macOS VOD 直接复用 Jellyfin 大图轮播和缩略图切换，替代竖海报并列方案；一级分类合并父级直属项与子分类结果，父级非空不代表包含子分类。预览不足十二部时有界补读，完整列表独立分页去重，详见设计文档最新修订节。

- 2026-09-19 macOS：首页采用轮播及一级分类横向海报分区，轮播不标热门、竖海报保持比例；分类页提供当前一级分类的“全部 + 二级分类”筛选，查看全部进入分页网格/列表。不支持父级查询时按叶子分类独立分页聚合，只显示已加载数量；顶部与 Jellyfin 首页一致，仅保留搜索和直接刷新；分类入口位于内容分区。继续观看与多源聚合仍待后续实现，详见 `14-VOD浏览与多源聚合设计.zh-Hans.md`。

- Web VOD 的列表接口以响应中的 `total`、`pagecount` 和 `list` 为准：`total` 是服务器卡与浏览页的内容总量，`list` 是当前页实际可浏览的条目，二者不得互相替代。响应成功但 `list` 未呈现，视为客户端浏览链路缺失，而不是“服务器无内容”。
- iOS、macOS 与 tvOS 的服务器卡统一把 Web VOD 的 `total` 作为媒体摘要显示；首屏无缓存摘要时按需拉取第 1 页，避免长期停留在“尚未加载”。分类筛选页仍展示该分类结果的分页总量，服务器卡保留全库总量。
- tvOS 不复用 Jellyfin / Emby / Plex 的通用媒体库节点浏览器。Web VOD 进入专用的内容优先库页：顶部显示总量和页码，分类作为可聚焦筛选列，主体为 2:3 海报墙；详情页提供播放源与剧集/分集选择，选择分集即沿既有 tvOS 播放协调器播放。
- tvOS 海报墙必须使用显式行式焦点网格；分类、海报和分页操作各自保有可达的焦点区域。Jellyfin、Emby、Plex 的既有媒体库路由与页面不因 VOD 专用页而改变。
- iOS/macOS 搜索保留响应的 `total` 与 `pagecount`，支持后续分页；搜索中刷新仍使用当前关键词。分类、搜索与分页请求通过取消及请求标识隔离，旧成功或失败回调不得覆盖新内容或加载状态；页面离开时释放加载状态，返回可继续分页或重载未完成的首屏。
- macOS 播放源选择使用解析器保留的原始源索引，不使用过滤后的数组位置；详情的导演、主演、播放、简介及集数文案复用八语言资源。
- 本轮只补齐 VOD 响应到浏览布局的消费与计数呈现；实际视频 URL 的可播放性仍需用用户配置的真实源单独验证，不能以列表接口成功替代播放成功。

## iOS 媒体库首页与退出语义（2026-09-12）

- Jellyfin / Emby / Plex 子页面的房子按钮统一返回当前服务器全屏媒体库的导航栈根页，不调用 `onExit`；左箭头只返回上一级，只有服务器首页的退出按钮关闭整个库页。
- 分类页、搜索页、合集/文件夹页及影片/剧集详情遵循相同语义，从网络、历史、收藏或个人页进入均保持全屏库容器及当前服务器上下文。
- 本次纠正 Jellyfin / Emby / Plex 分类页及 Emby 内容详情页误用 `onExit` 的四处动作；其他已返回库根页的入口不改，共享导航工具、搜索和播放处理不改。

## iOS 扫码为电视授权（2026-09-12）

- 手机“网络”页右上角「＋」菜单按“添加服务器 → 发现服务器 → 扫一扫”排列，低频的“扫一扫”放在末尾，扫描电视授权二维码；相机权限只在进入扫描页时请求，拒绝后提供系统设置入口。
- Google Drive / OneDrive 识别电视现有局域网配对二维码，扫描页关闭后进入独立 Apple TV 授权页，通过系统 OAuth 窗口登录并将本次凭据交给电视。不读取、关联或新增手机服务器，不使用手机已保存账号授权；电视仍按现有编辑页保存流程落入本机 Keychain。
- 保留系统相机 → 电视网页 → GenPlayer 的原有入口。只接受支持的服务类型、合法局域网 IPv4 地址、端口和配对参数；二维码本身不包含账号 token。关闭会话使旧授权任务失效，已有授权页打开时不被重复链接替换。
- Plex 只打开识别到的官方 HTTPS 绑定链接，在系统 Safari 页面完成授权，电视沿用 PIN 轮询取得 token；关闭网页后可继续扫描。
- 115 授权码仅提示“请使用 115 App 扫码”，不实现官方扫码确认接口；其他二维码提示不支持，不自动打开任意链接。
- 手工回归范围：相机首次允许/拒绝与取消、两种云盘独立登录及返回电视、Plex 绑定与返回扫描、115/无效码提示。实际相机、OAuth 与双设备验证须按 AGENTS.md 3.8 获批后执行。

## iOS 顶部原生搜索（2026-09-10 确认保留独立搜索）

- **最新确认**：用户选择“保留当前原生动画和独立搜索”。不再为合并按钮背景更换动画实现。当前 `pinnedTrailingGroup` 只控制顺序，独立 UIKit 样例确认即使设置搜索占位项的 `sharesBackground = true`，搜索仍有独立背景；不能将下述实现描述为恢复了三个按钮共用背景。

- Jellyfin / Emby / Plex 首页与分类页预先安装并保留同一 `UISearchController`，点击 / 关闭由系统连续变形；通过 `pinnedTrailingGroup` 将原有操作按钮置于搜索之后，保持原入口顺序。iOS 26 采用 `integratedButton` 和 `.minimal` 搜索栏样式，材质、尺寸、关闭控件、键盘与展开 / 收回由系统呈现；`searchBarPlacementAllowsToolbarIntegration = false` 固定在顶部。iOS 15–25 从原工具栏按钮打开原生导航搜索栏。
- 不添加自定义胶囊、灰底、整屏蒙层，不修改导航栏 alpha / 交互开关；iOS 26 搜索不改变首页轮播安全区、顶部间距或透明导航栏样式。旧系统搜索期间为当前导航项配置原生不透明背景，顶栏图标 / 标题随浅深主题切换到系统前景色；关闭恢复原导航外观，不改轮播布局。首次打开在搜索栏完成布局后激活并聚焦，详情返回不强制弹键盘。
- 未输入时保留浏览内容，近期搜索以限高列表呈现；输入后在同一页面内容区显示结果。浏览视图保留实例，清空 / 关闭恢复浏览现场。
- 保持 300ms 服务端防抖、首页全库 / 分类页库内搜索范围及结果详情导航。搜索桥接仅安装在当前页的导航项，拆除时恢复该页原配置。
- IPTV 复用此组件，分组 / 排序 / 视图切换仍使用既有处理逻辑；搜索激活时顶栏的临时布局由系统决定。不再在点击时临时安装搜索控制器，避免起始布局缺失破坏连续动画；搜索常驻，原有操作按钮以同一实例放到原生 pinned trailing group，关闭控件维持已确认的系统呈现。
- 用户最终确认“原搜索按钮位置不动，点击后出现动画搜索框”：保留已认可的顶部原生展开，恢复原搜索入口位置；框外独立关闭按钮调整停止。已撤回会将搜索移到底部的 SwiftUI 接入。
- 本地 / 文件型服务、macOS 与 tvOS 不在本轮范围。

## 1. 当前功能概览

- 服务器卡片管理：新增、编辑、删除、拖拽排序、连接校验。
- 协议支持：SMB / WebDAV / Jellyfin / Emby / Plex。
- 局域网发现：SMB / Jellyfin / Emby / Plex / WebDAV 自动发现与快速添加。
- 媒体库浏览：Jellyfin/Emby/Plex 具备独立库页与检索相关页面。
- 连接安全：敏感信息（密码、token）使用 Keychain 持久化。

## 2. 关键实现位置

- 服务器列表与入口：`ServerListView`。
- 服务器配置模型：`ServerModel`（`ServerConfig` + `ServerType` + 默认端口/URL 规则）。
- 服务层汇聚：`AppNetworkService`（服务器存储、连接、凭据迁移、级联清理）。
- 协议/媒体服务：`JellyfinService`、`EmbyService`、`PlexService`、`WebDAVManager`、`SMBDiscoveryService`。
- 远程文件/媒体库页面：`RemoteFileListView`、`JellyfinLibraryView`、`EmbyLibraryView`、`PlexLibraryView` 等。

## 3. 开发实现步骤（建议模板）

1. **明确来源类型**：先定义是协议文件浏览还是媒体库 API 浏览。
2. **扩展 `ServerConfig`**：新增字段时，先确认默认值、兼容策略、URL 拼接规则。
3. **接入 `AppNetworkService`**：处理新增字段的保存、加载、Keychain 读写与迁移。
4. **完善连接验证**：在连接前统一做超时、取消与错误文案处理。
5. **页面联动**：在 `ServerListView` 与具体库页新增入口/跳转。
6. **清理策略**：删除服务器时，确认历史与收藏等关联数据是否需要同步清理。

## 4. 近期实现补充（2026-03）

- **局域网自动发现扩展（SMB/Jellyfin/Emby/Plex/WebDAV）**
  - `SMBDiscoveryService` 扩展为多协议 Bonjour 扫描：新增 `_jellyfin._tcp.`、`_jellyfin-server._tcp.`、`_emby-server._tcp.`、`_embyserver._tcp.`、`_plexmediasvr._tcp.`、`_plexmediaserver._tcp.`、`_plex._tcp.`、`_webdav._tcp.`、`_webdavs._tcp.`。
  - `Info.plist` 的 `NSBonjourServices` 白名单同步补齐上述类型（并加入 `_http._tcp`、`_https._tcp` 作为兜底扫描入口），避免 iOS 本地网络权限层直接过滤发现结果。
  - 对仅广播通用 HTTP/HTTPS Bonjour 的设备，新增基于服务名与 TXT 记录的 Jellyfin/Emby/Plex/WebDAV 类型推断，提升跨厂商兼容性。
  - 当主机仅广播 SMB/WebDAV 等基础服务但未广播 Jellyfin/Plex Bonjour 类型时，新增“主机主动探测”补偿：按常见端点探测 `Jellyfin(8096)`、`Plex(32400)` 并自动补充发现项。
  - 发现结果补充 `type/useSSL/port`，快速添加时会按发现协议预填 `ServerConfig`，减少手动输入。
  - 发现结果按服务类型与名称稳定排序，减少刷新后列表跳动；发现超时窗口延长至 12 秒，提高慢网络下的命中率。
  - 发现列表行展示协议类型（如 `WebDAV (HTTPS)`）与地址，提升多服务混合局域网下的可识别性。

- **服务器类型选择交互优化（添加/编辑页）**
  - 类型入口由平铺胶囊切换为分组弹层选择（`File Protocols` / `Media Servers`），并增加图标与选中态，信息密度更低、误触更少。
  - 选择器与连接参数联动：在端口为空或保持旧默认值时，切换“服务类型/HTTPS”会自动更新到新默认端口。
  - 从“发现列表”进入添加页时会预填端口与 HTTPS，减少二次手输。

- **服务器导入/导出（脱敏备份）**
  - iOS 服务器页工具栏与 macOS Network 页面顶栏新增“导入服务器 / 导出服务器”入口，用于跨设备保存和恢复服务器列表。
  - macOS 端同时在顶部应用菜单栏（`File -> Import Servers... (⇧⌘I)` / `Export Servers... (⇧⌘E)`）以及设置的高级选项中提供导入导出入口。
  - 导出文件仅包含非敏感配置骨架（名称、地址、端口、协议类型、用户名、工作组等），**不包含密码、token 等 Keychain 敏感信息**。
  - 导入时按“协议类型 + 地址 + 端口 + HTTPS + 用户名/工作组”做去重，避免同一备份重复导入后出现大量重复卡片。
  - 导入完成后若缺少凭据，沿用现有行为：在进入服务器或测试连接时提示重新登录/补密码。
  - 服务器页右上角菜单（macOS 顶栏 `...` 菜单）新增“清空服务器”批量入口；该操作必须经过确认弹窗，执行后按单个删除相同的级联规则清理所有服务器、关联历史/收藏与 Keychain 敏感信息。

- **媒体库详情跳转链路统一（Jellyfin/Emby）**
  - 从历史记录、收藏、个人页以及上下文菜单进入详情时，统一为“先弹出库页，再自动定位目标详情”。
  - 关键参数链路：`selectedLibraryServer` + `targetItemIdToResolve`。
  - 目标：避免直接 stack push 导致 Tab 残留和导航层级混乱。
- **剧集解析策略增强**
  - 当目标 Item 是 Episode：先解析到 Series，再自动定位对应 Season/Episode。
  - 当目标 Item 是 Season：先解析到 Series，再自动定位到对应 Season。
  - Jellyfin 与 Emby 保持同构逻辑，减少跨服务行为差异。
- **服务器顺序一致性修复**
  - 服务器排序变更后，历史和收藏分组顺序已与 `AppNetworkService.shared` 实时同步。
  - 避免出现“服务器列表顺序已变化，但历史/收藏仍旧顺序”的问题。
- **媒体库首页标题策略收敛（Jellyfin/Emby/Plex）**
  - Jellyfin / Emby / Plex 的媒体库根页统一恢复为系统大标题进入，iPhone 与 iPad 都保持“进入时大标题、滚动后自动收为小标题”的系统行为。
  - 服务类型标识改为导航栏左上角的紧凑胶囊（品牌图标 + 类型名），大标题本身保持纯文本，不再强行把图标塞进系统大标题布局。
  - 该方案在大标题、搜索抽屉与滚动收起之间更稳定，避免出现标题重叠、滚回顶部后图标消失等系统导航栏布局冲突。
- **媒体库卡片点击命中稳定性（Jellyfin/Emby）**
  - 对封面卡片上的装饰层（渐变、进度、播放图标等）统一关闭命中测试，避免覆盖层偶发抢占点击事件。
  - 卡片容器统一设置点击形状，提升封面区域整体点击成功率，修复“部分封面看得到但点不开”问题。
- **媒体库展示模式扩展（Grid/List）**
  - Jellyfin 与 Emby 的库详情页新增网格/列表切换入口，适配不同浏览偏好与大屏阅读场景。
  - 展示模式按 `provider + serverId + libraryId` 维度持久化，下次进入保持上次选择。
- **列表模式信息密度优化（Jellyfin/Emby）**
  - 列表行增加适合纵向阅读的元信息：年份、时长、评分、分辨率、体积、分级、集数/季数等。
  - 增加简介摘要与观看进度条；当缺少 `overview` 时回退使用 `genres`，减少“列表模式内容过空”的问题。
  - 维持封面 + 文本双栏结构，强调可扫读性与快速比较体验。
  - Jellyfin/Emby 列表请求补充更多 `Fields`（如 `RunTimeTicks`、`OfficialRating`、`RecursiveItemCount` 等），降低电影条目元数据缺失概率。
- **海报墙元信息收敛（Jellyfin/Emby/Plex）**
  - 海报墙卡片维持轻量信息密度，优先展示“评分角标 + 标题下年份/分级”这类快速决策信息，不把列表模式的时长、分辨率、体积等字段直接搬进海报墙。

  - Plex 搜索场景下，单个库若因短 query 或库类型限制返回 `400/404`，应降级为空结果而不是弹出整页错误提示；空态继续由搜索页内容区承接，避免把“无匹配”误报成“搜索不可用”。
- **Jellyfin / Emby 首页分组与人物页信息层级收口**
  - Jellyfin / Emby 首页的“按类型横向 shelf”不再重复展示 `Collections / Playlists`；这两类入口继续保留在 `My Media`，避免首页先出现入口卡片、下方又重复出现同类横向分组。
  - `JellyfinPersonDetailView` / `EmbyPersonDetailView` 改为进入人物页后主动补拉人物详情，不再只展示 `name / role / type` 三项静态字段。
  - 当服务端已抓到人物元数据时，人物页现在可显示 `Biography`、出生/逝世日期、出生地与外部资料源标识；若服务器本身元数据稀疏，则页面保持精简回退，不伪造信息。
  - 人物页头部版式同步收紧：手机上改用更紧凑的名字字号、信息卡式布局与更保守的海报宽度，降低长译名演员在窄屏上把标题挤成三四行大字块的失衡感。
- **Plex 演职员卡片可下钻到人物页**
  - `PlexItemDetailView` 的 `Cast & Crew` 卡片现在支持进入 `PlexPersonDetailView`，并在人物页显示 `Known For` 作品列表，补齐和 Jellyfin / Emby 接近的人物浏览链路。
  - `PlexPerson` 模型补充 `role` 字段，详情页演职员卡优先显示角色名；没有角色名时再回退 `Actor / Director / Writer` 这类职位。
  - `Jellyfin / Emby` 的详情页人物卡也统一改为同一套文案优先级，避免服务端已提供角色名时仍只显示职位文本。
- **tvOS 媒体详情补齐相似内容与人物作品**
  - tvOS 电影/单集详情页与电视剧详情页应与 iPad 端保持同构：详情主体下方展示 `More Like This` 横向货架，演职员卡片可进入人物页，人物页展示 `Known For` 作品列表。
  - Jellyfin / Emby 使用 `PersonIds` 与 `/Items/{id}/Similar`；Plex 使用 `/library/people/{id}/media` 与 `/hubs/metadata/{id}/related`。接口无结果或不可用时不展示空货架，避免干扰电视端浏览。
  - Plex tvOS 节点需要保留 `people / genres / backdrop / rating` 等详情字段，确保从相关内容或人物页继续下钻时仍能显示演职员、海报和详情元数据。

- **远程文件列表缩略图与类型识别增强（SMB/WebDAV/FTP/SFTP/NFS）**
  - `RemoteFileListView` 与共享 `FileItemComponents` 统一接入真实缩略图预览能力，远程文件在网格/列表中可直接显示实际画面或封面。
  - 缩略图右下角补充圆形类型徽标，避免纯预览图场景下无法快速判断文件类型。
  - 远程音频/视频卡片支持基于历史记录的圆环播放进度展示，帮助快速回到上次播放位置。
  - 非媒体文件的默认图标也按扩展名细分：`PDF`、文档、表格、演示稿、压缩包、设计源文件、字体文件会显示不同的 SF Symbol 与颜色，减少大目录里“一排都是同一个 doc 图标”的辨识成本。
- **远程文件文档预览与外部打开增强**
  - `SMB / WebDAV / FTP / SFTP / NFS` 文件页中的 `PDF / Office / iWork` 文档现在会先下载临时副本，再走系统 `QuickLook` 预览，避免必须先“保存到本地”才能查看内容。
  - 远程文件若暂不支持应用内预览，下载临时副本后会展示“在其他 App 中打开”动作页，和本地文件页保持一致，不再只显示静态错误提示。
  - 收藏页与个人页中的远程文件预览链路也同步收口为“解析服务器 -> 下载临时副本 -> 统一预览路由”，减少入口差异。
- **远程 / 媒体库错误反馈统一（Jellyfin/Emby/Plex/SMB/WebDAV/FTP/SFTP/NFS）**
  - 远程与媒体库页面的普通加载失败统一回到系统原生 `Alert`，避免为连接中断、搜索失败、预览失败这类状态额外设计整页错误卡片。
  - Jellyfin / Emby / Plex 首页、库容器页、详情 resolver，以及 `RemoteFileListView` / `RemoteFolderPickerView` 的错误提示统一使用同一套标题、原始错误文案和可选 `Retry` 动作，交互更接近 iOS 原生页面。
  - 页面内部仍保留“空文件夹 / 无内容”这类真正的空态视图；只有异常错误才走系统 alert，减少层级打断和视觉噪音。



## 5. 后续迭代建议

- 抽象统一媒体库协议层（减少 Jellyfin/Emby/Plex 重复代码）。
- 将连接诊断结果标准化（鉴权失败、TLS、超时、路径错误）。
- 给服务器配置增加“健康检查”记录，便于问题追踪。

### macOS 媒体参数补充（2026-10-01）

- Jellyfin/Emby/Plex 的现有技术参数行补充服务端明确提供的 HDR/Dolby Vision、视频编码、帧率、位深；保留原字体、颜色、分隔符、行数和布局。只读取现有响应，不扫描文件或发起额外播放/逐项请求。
- Jellyfin/Emby 沿用原最高分辨率版本摘要选择，新增参数与分辨率、容器、大小来自同一版本；Plex 沿用第一 Media/Part。没有选中源的元数据时不从另一版本拼接。
- 详情页标签表示片源能力，不代表播放器或电视实际输出；仅 10-bit、BT.2020 或编码名称不推断 HDR，PQ 只保守标记 HDR，缺失参数省略。iOS/tvOS 保持现状。

### iOS 媒体参数补充（2026-10-01）

- Jellyfin/Emby/Plex 详情在原元信息下增加同风格技术文字，显示明确的 HDR/Dolby Vision/HDR10+/HLG、编码、帧率及位深；窄屏可换行，单集元信息摘要同步补充，不改变播放/导航/操作按钮。
- Jellyfin/Emby typed 模型保留 VideoRangeType、ColorTransfer、DvProfile；主详情与原分辨率/大小同取第一媒体源，单集摘要沿用首选播放源。Plex 保留第一 Media/Part 视频流的明确动态范围、DV 标志、帧率、位深，colorRange 不作为 HDR 证据。
- 与 macOS 共用只读格式判断，缺值省略；10-bit/BT.2020 不直接推断 HDR。只消费已有详情响应，不增加文件扫描或网络请求；tvOS 展示不扩展。
