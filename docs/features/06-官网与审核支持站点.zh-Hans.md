# GenPlayer 官网与审核支持站点设计

## 1. 背景

为 GenPlayer 新增一个可独立发布到公网的产品官网，用于承载：

- 产品介绍
- 功能说明
- 平台与路线图信息
- iOS 审核/上架所需的隐私政策页面
- 用户问题反馈/支持页面

由于当前仓库没有数据库、也不希望引入复杂运维链路，因此优先采用 **纯静态站点** 方案。

## 2. 目标

### 2.1 功能目标

1. 提供首页式产品介绍站点，覆盖：
   - 产品定位
   - 核心功能
   - 支持的平台与协议
   - 使用场景
   - Roadmap / CTA
2. 提供独立的隐私政策页面。
3. 提供独立的问题反馈/支持页面。
4. 支持：
   - 中文 / English 双语切换
   - 黑 / 白主题切换
   - 移动端优先响应式布局
5. 可直接静态托管到公网。

### 2.2 非目标

- 不在本期接入 CMS。
- 不接入后端数据库。
- 不实现登录、评论、工单系统。
- 不引入复杂前端框架构建链路。

## 3. 方案选择

## 3.1 选择：原生静态站点

采用以下技术组合：

- `HTML`：多页面静态结构
- `CSS`：主题、栅格、响应式布局
- `Vanilla JavaScript`：
  - 语言切换
  - 主题切换
  - 隐私/反馈页文案注入
  - 反馈 mailto 表单拼接

### 选择理由

- **零后端依赖**：满足当前“没有数据库”的限制。
- **部署简单**：可直接部署到 GitHub Pages、Cloudflare Pages、Netlify、Vercel。
- **维护成本低**：团队成员无需额外掌握复杂前端框架。
- **审核友好**：固定 URL 适合在 App Store Connect 中填写 Privacy Policy URL / Support URL。

## 4. 信息架构

### 4.1 页面结构

1. `index.html`
   - Hero
   - 产品简介
   - 核心功能
   - 支持协议 / 平台
   - 使用场景
   - 上线计划 / CTA
2. `privacy.html`
   - 数据收集声明
   - 本地/远程账号信息处理说明
   - 历史、收藏、诊断与联系信息
   - 用户权利与联系方式
3. `feedback.html`
   - 常见问题入口
   - 联系邮箱
   - Bug 反馈建议模板
   - 静态反馈表单（生成 `mailto:`，无需后端）
4. `changelog.html`
   - 面向用户可读的版本更新记录
   - 仅收录正式发布（Production）版本
   - 建议与 App 内“版本记录”入口配合使用（App 跳转到官网）
   - 页面文案必须保持“对外发布说明”语气，不展示内部信息架构、维护建议、发布流程说明或“推荐做法”之类团队视角描述
5. `404.html`
   - GitHub Pages 兜底页
   - 回到首页 / 隐私政策 / 支持页的快捷入口

### 4.2 全局组件

- 顶部导航
- 语言切换器
- 主题切换器
- 页脚
- CTA 区块

## 5. 国际化与主题

## 5.1 国际化

采用前端字典方式：

- JS 内置 `zh-CN` 与 `en` 文案对象
- 通过 `data-i18n` / `data-i18n-html` 进行页面文本替换
- 当前语言保存在 `localStorage`
- 支持从浏览器语言自动推断默认语言
- 若站点由 App 内入口打开，允许通过 URL 查询参数（如 `lang=zh-CN` / `lang=en`）覆盖默认语言；该参数优先级高于站点本地缓存，用于让官网与隐私页默认跟随 App 当前语言。

## 5.2 主题

采用 `data-theme="light|dark"` 方案：

- 默认跟随系统 `prefers-color-scheme`
- 用户手动切换后持久化到 `localStorage`
- 视觉风格采用黑白主色体系，辅以灰阶层次
- 若站点由 App 内入口打开，允许通过 URL 查询参数（如 `theme=dark` / `theme=light`）覆盖默认主题；该参数优先级高于站点本地缓存，用于让官网与隐私页默认跟随 App 当前主题。
- 页面根节点 `html` 与 `body` 都必须得到一致的主题背景，避免在 iPhone / Safari / In-App Browser 的安全区与回弹场景下出现深色主题露白。

## 6. 审核支持考虑

### 6.1 隐私政策页面

隐私政策页面是本次站点必须包含内容，用于：

- App 内设置页跳转
- App Store Connect 的 Privacy Policy URL
- 对远程服务账号、历史记录、收藏等隐私处理进行说明

隐私政策页面的视觉与信息结构要求：

- 必须沿用首页同一套设计系统，包括配色、字体层级、按钮、圆角、描边和卡片风格。
- 页面首屏应以“简洁说明 + 关键信息摘要”为主，不使用夸张的大标题排版或脱离首页节奏的视觉实验。
- 信息摘要区优先复用首页已有的 badge / feature card 语言，避免额外引入新的 icon 风格或不一致的插图。
- 正文区应保持法律/说明页面的可读性，标题层级、段落宽度和卡片密度都应明显收敛于营销页 Hero，而不是做成海报式展示。
- 隐私页、反馈页、404 页等内页允许在结构上有差异，但不能脱离首页建立新的视觉语言。

### 6.2 问题反馈 / 支持页面

问题反馈页建议作为：

- App Store Connect 的 Support URL
- 审核沟通时可提供的公开帮助页面
- 用户反馈问题的统一入口

由于无后端，本期采用：

- 公开邮箱（当前：`fufuguo86+genplayer@gmail.com`）
- `mailto:` 表单拼接
- 常见问题说明

后续若需要，可无缝升级为第三方静态表单服务（如 Formspree / Basin / Getform），无需重构站点结构。

## 7. 部署建议

优先级建议：

1. **GitHub Pages**：
   - 与仓库集成方便
   - 适合开源/半开源项目官网
2. **Cloudflare Pages**：
   - 全球 CDN
   - 自定义域名与 HTTPS 配置简单
3. **Netlify / Vercel**：
   - 拖拽部署和 Git 集成友好
4. **Aliyun OSS / ECS + CDN**：
   - 若主要面向中国大陆访问，这通常比直接使用 GitHub Pages 更稳
   - 适合作为正式对外源站，GitHub Pages 更适合作为内容发布源或备份源

建议站点目录独立为 `website/`，便于：

- 单独部署
- 后续迁移到任意托管平台
- 不影响 iOS 主工程结构

### 7.1 当前仓库的 GitHub Pages 落地方式

当前仓库采用：

- 私有主仓库继续保存 iOS 工程与 `website/` 源文件
- 单独创建公开官网仓库作为 GitHub Pages 发布仓库
- GitHub Actions 监听私有主仓库 `main` 分支上的 `website/**` 与 `website-public-repo-overlay/**`
- 将 `website/` 内容和公开仓库 overlay 一并同步到公开官网仓库的指定分支
- GitHub Pages 再从公开官网仓库的 `/ (root)` 提供静态站点

这样处理的原因是：

- GitHub Free 下私有仓库无法直接启用 GitHub Pages
- 公开官网仓库可以承载稳定公开 URL
- 主工程仓库仍可保持私有，不暴露应用代码
- 官网仍然由主仓库统一维护，不需要手工复制页面文件

首次启用步骤：

1. 先创建一个公开官网仓库，推荐：
   - `genplayer.fugary.com`
   - 或 `GenPlayer-Website`
   - 当前已落地为：`fugary/gen-player-pages`
2. 在主仓库 Actions 设置中配置：
   - `WEBSITE_PUBLISH_REPOSITORY`
   - `WEBSITE_PUBLISH_BRANCH`
   - `WEBSITE_PUBLISH_TOKEN`
3. 将公开官网仓库特有的 `.github/workflows`、`ops/` 等文件也放在主仓库的 `website-public-repo-overlay/` 下统一托管。
4. 运行一次站点同步工作流，让公开官网仓库获得站点文件和 overlay 文件。
5. 打开公开官网仓库 `Settings -> Pages`。
6. 选择 `Build and deployment -> Source = Deploy from a branch`。
7. 选择同步后的分支和 `/ (root)` 目录。
8. 等待 GitHub Pages 发布完成。

约束补充：

- `fugary/gen-player-pages` 视为主仓库生成的发布仓库，站点文件与部署基础设施文件都以主仓库为唯一事实来源。
- 公开官网仓库中的 `.github/workflows`、`ops/`、根 `README.md` 等若需要调整，应回到主仓库对应的 `website/` 或 `website-public-repo-overlay/` 修改，而不是在目标仓库手工热修。

当前默认访问地址：

- 首页：`https://genplayer.fugary.com/`
- 隐私政策：`https://genplayer.fugary.com/privacy.html`
- 问题反馈：`https://genplayer.fugary.com/feedback.html`
- 版本记录：`https://genplayer.fugary.com/changelog.html`

## 9. 验收标准

- 三个页面均可直接通过静态文件打开。
- 中英切换生效且跨页面保持一致。
- 黑白主题切换生效且跨页面保持一致。
- 移动端宽度下导航与内容可正常浏览。
- 隐私政策页面可独立访问。
- 反馈页面可在无后端情况下提供有效联系路径。
- 页面内容与当前产品定位保持一致，不虚构未上线能力。
