# 模块 08：远程媒体质量与转码选择（Jellyfin/Emby/Plex）

## 1. 背景与目标

- Jellyfin / Emby / Plex 这类媒体服务本身都支持根据客户端请求返回不同播放方案，包括：
  - 原始文件直连 / 直出（Direct Play / Direct Stream）
  - 按目标码率、分辨率、容器进行服务端转码
- GenPlayer 当前远程媒体播放链路已经具备：
  - `PlaybackInfo` 预取
  - `MediaSource` 选择
  - 播放前音轨 / 字幕预选
  - VLC 统一播放内核
- 但当前还没有“质量 / 码率 / 是否转码”的用户可见选择能力，实际行为仍以“优先直接播放原始流”为主。

本设计的目标不是把播放器做成复杂的技术面板，而是补一套**轻量、默认不打扰、需要时可控**的质量选择能力。

---

## 2. 当前现状（代码基线）

## 2.1 当前默认播放语义

- Jellyfin / Emby 当前都优先走：
  - `MediaSource.directStreamUrl`
  - 若无，则回退 `/Videos/{id}/stream?Static=true`
- 这意味着当前默认语义本质上是：
  - **优先原始文件直连/直出**
  - **并没有显式让用户选择“转码到某个质量档”**

对应实现位置：

- [JellyfinService.swift](./GenPlayer/Source/Services/JellyfinService.swift)
- [EmbyService.swift](./GenPlayer/Source/Services/EmbyService.swift)
- [JellyfinLibraryView.swift](./GenPlayer/Source/Views/JellyfinLibraryView.swift)
- [EmbyItemDetailView.swift](./GenPlayer/Source/Views/EmbyItemDetailView.swift)
- [PlexService.swift](./GenPlayer/Source/Services/PlexService.swift)
- [PlexLibraryView.swift](./GenPlayer/Source/Views/PlexLibraryView.swift)

## 2.2 当前 UI 基线

- 详情页已存在“播放前选项”入口，但只承载：
  - 音轨
  - 字幕
- 现有 `PrePlaybackOptionsSheet` 已经是比较合适的扩展底座，不建议再额外新增一层“质量设置页”。

对应实现位置：

- [PrePlaybackOptionsSheet.swift](./GenPlayer/Source/Views/Components/PrePlaybackOptionsSheet.swift)

## 2.3 当前不足

- 用户无法明确选择：
  - 原画 / 原文件
  - 1080p / 720p / 480p
  - 限码率播放
- 播放进度上报目前固定写死 `PlayMethod = DirectPlay`，后续若引入转码，需要同步改成真实方法。
- 下载中心当前语义是“正式下载原始离线资产”，不应和“在线播放临时转码”混成一套。

## 3. 产品结论

## 3.1 可以引入，而且适合引入

- 这项能力和当前 App 定位不冲突，反而是 Jellyfin / Emby 在“远程访问”“弱网访问”“蜂窝网络”“老设备解码能力受限”场景下的重要补强。
- 但它不应该成为默认打断式流程。

**结论：**

- 可以引入。
- 推荐走“默认继续一键播放，按需展开质量选项”的方案。

## 3.2 默认策略

默认建议保持：

1. `正式下载的本地文件`
2. `自动缓存副本`
3. `远程原始文件直连 / 直出`
4. `服务端转码流`

也就是说：

- **默认不是一上来就转码。**
- **默认仍应以原始文件播放为先。**
- **本能力当前只作用于 Jellyfin / Emby / Plex 这类媒体服务，不影响本地文件与 SMB / WebDAV / FTP / SFTP / NFS 等文件型服务的播放行为或菜单结构。**

原因：

- GenPlayer 当前使用 VLC，原始格式兼容性相对更强。
- 本项目定位偏“媒体中心 / 本地与 NAS 一体化”，用户对原画直连的预期高。
- 在家庭局域网、NAS 内网、千兆 Wi‑Fi 场景下，原始文件通常是最优体验。

## 4. 推荐交互设计

## 4.1 入口设计

推荐只保留两个入口：

1. **详情页播放前选项**
2. **播放器内 `More` 菜单中的“切换质量”**

不建议：

- 在剧集行尾常驻塞一个清晰度按钮
- 在首页 / 列表卡片上直接暴露质量标签入口
- 在导航栏再增加一个独立“质量”图标

原因是这会明显增加认知噪音。

同时补充一条范围约束：

- `Playback Options` 中的“播放质量”分区，以及播放器 `More -> Playback Quality` 菜单，只在媒体服务条目里出现。
- 本地文件、下载后的离线文件，以及 SMB / WebDAV 等文件型来源继续保持现有菜单结构，不额外出现“播放质量”入口。

## 4.2 详情页交互

详情页主播放按钮保持简单：

- `播放`
- 若离线命中则 `播放（离线）`

在详情操作区继续使用一个小图标入口，但将现有“播放前选项”升级为统一面板：

- `播放质量`
- `音轨`
- `字幕`

推荐信息结构：

```text
Playback Options

Quality
  Auto (Recommended)
  Original
  1080p
  720p
  480p

Audio
  ...

Subtitles
  ...
```

这样可以避免播放器前有两个小入口分别管“轨道”和“质量”，信息架构更干净。

补充交互约束：

- 详情页上的“播放 / 继续播放 / 从头播放 / 剧集行点击”等直接播放入口，必须复用当前已选的播放质量，不允许只有显式打开 `Playback Options` 后才生效。
- 也就是说，用户一旦在当前媒体详情里切到 `720p`，后续从该详情直接点 `播放` 或 `继续播放`，仍应沿用 `720p` 对应的媒体服务协商参数。

## 4.3 播放器内交互

播放器运行中，在 `More` 菜单增加：

- `Playback Quality`

点击后进入质量列表。

但这里要明确语义：

- **切换质量会重建播放 URL，并从当前时间附近恢复播放**
- 不承诺“无缝瞬切”

因此首次实现建议做成：

- 选择后轻提示：`Switching to 720p`
- 从当前进度重启播放

而不是假装像自适应 HLS 一样无感切换。

另外补充一个服务协商规则：

- `Auto / Original` 允许继续优先尝试 `Direct Play / Direct Stream`。
- `1080p / 720p / 480p` 这类受限档位不应继续放开 `Direct Play / Direct Stream`，否则服务器可能直接返回原始流，导致用户感觉“选了画质却没有变化”。

播放器内还需要提供最小可验证信息，避免用户只能靠肉眼猜：

- `Media Info` 的 `General` 区至少展示：
  - `Requested Quality`
  - `Play Method`
  - `Playback Resolution`
- `Playback Resolution` 优先使用播放器当前实际解码出来的分辨率；拿不到时再回退服务端返回的流分辨率。
- 该信息展示只作用于媒体服务会话，不改变本地文件或文件型服务的菜单结构。

## 4.4 浏览页如何显示

推荐只做轻量表达，不在卡片上提前灌满技术信息：

- 详情页主信息区可显示当前源的最高可用规格：`4K · HEVC · 18 Mbps`
- 若用户本次手动选了非默认方案，可在详情页播放按钮下方或选项入口旁显示：
  - `Current: Auto`
  - `Current: Original`
  - `Current: 720p · 4 Mbps`

不建议在网格卡片上常驻显示“当前播放质量”，因为那是会话态，不是内容固有属性。

## 5. 默认档位设计

## 5.1 第一阶段推荐只提供少量预设

不要一开始给太多自定义滑杆。建议先做固定档位：

1. `Auto`
2. `Original`
3. `1080p`
4. `720p`
5. `480p`

可选补充：

6. `Audio Only`（仅对音频 / 后台收听类场景开放，视频先不做）

## 5.2 各档位语义

- `Auto`
  - 默认档
  - 优先原始文件直连 / 直出
  - 当用户后续开启“蜂窝省流量”之类全局策略时，再允许它映射为限码率策略
- `Original`
  - 尽量关闭转码，强烈偏向 Direct Play / Direct Stream
  - 如果服务端确认无法直出，再提示回退 `Auto`
- `1080p / 720p / 480p`
  - 语义不是“精确输出到某个绝对分辨率”，而是“以该档位为目标上限请求服务端返回合适方案”

## 6. 服务层设计

## 6.1 新增统一播放选择模型

建议新增统一模型，例如：

```swift
struct RemotePlaybackProfile {
    let id: String
    let kind: Kind
    let title: String
    let maxStreamingBitrate: Int?
    let maxWidth: Int?
    let maxHeight: Int?
    let enableDirectPlay: Bool
    let enableDirectStream: Bool
    let enableTranscoding: Bool
}
```

其中 `kind` 建议至少包含：

- `auto`
- `original`
- `transcodePreset`

## 6.2 PlaybackInfo 请求扩展

当前 `getPlaybackInfo(...)` 发送的是空 body。

后续应扩展为支持带入：

- `MaxStreamingBitrate`
- `MaxWidth`
- `MaxHeight`
- `AudioStreamIndex`
- `SubtitleStreamIndex`
- `EnableDirectPlay`
- `EnableDirectStream`
- `EnableTranscoding`
- `MediaSourceId`

Jellyfin / Emby 都走同构封装，避免一端先做、一端漂移。

## 6.3 服务端返回解析

`MediaSource` / `PlaybackInfo` 解析层需要补齐：

- 实际采用的是 `DirectPlay / DirectStream / Transcode`
- 服务端返回的转码 URL（若存在）
- `PlaySessionId`
- 实际输出容器 / 码率 / 尺寸

最终对上层暴露统一结果：

```swift
struct ResolvedRemotePlayback {
    let url: URL
    let playMethod: PlayMethod
    let mediaSourceId: String?
    let playSessionId: String?
    let displayQualityText: String?
    let displayBitrateText: String?
}
```

## 6.4 进度上报修正

当前 `reportPlaying / reportProgress / reportStopped` 的 `PlayMethod` 不能再固定写死 `DirectPlay`。

引入质量选择后必须按真实链路上报：

- `DirectPlay`
- `DirectStream`
- `Transcode`

否则 Jellyfin / Emby 服务器侧会出现播放统计与真实链路不一致的问题。

## 7. UI 组件改造建议

## 7.1 `PrePlaybackOptionsSheet` 升级为统一播放面板

建议从“仅音轨/字幕”升级为：

- `Quality`
- `Audio`
- `Subtitles`

并允许某个 section 不可用时自动隐藏。

这样保留当前入口密度，不再新增新的 toolbar 图标。

## 7.2 Player 内菜单

`PlayerMenus` 新增一项：

- `Playback Quality`

放在：

- `Audio`
- `Subtitles`
- `Speed`
- `Aspect Ratio`
- `More`

这组能力附近即可，不建议放到顶部单独按钮。

## 7.3 文案建议

用户可见文案建议控制得非常短：

- `Playback Quality`
- `Auto`
- `Original`
- `Requested Quality`
- `Play Method`
- `Playback Resolution`
- `Switching Quality`
- `Restarting stream from current position`

新增文案必须同步接入多语言资源，至少覆盖：

- `en`
- `zh-Hans`

其余现有语种需补同 key。

---

## 8. 与下载中心 / 离线播放的关系

这部分必须强约束，避免概念混淆：

- **在线播放质量选择** 是“当前会话的流媒体策略”
- **下载中心** 是“正式离线资产管理”

第一阶段不建议做：

- 下载 720p 转码副本
- 把临时转码流视为“已下载”
- 把当前选择的在线播放质量直接绑定到下载质量

继续保持：

- 下载中心默认管理原始可离线资产
- 播放命中优先级仍为 `正式下载 > 自动缓存 > 远程播放`

---

## 9. 推荐实施顺序

1. 服务层补齐 `RemotePlaybackProfile / ResolvedRemotePlayback`
2. Jellyfin / Emby 的 `PlaybackInfo` 请求支持质量参数
3. `PrePlaybackOptionsSheet` 升级为“质量 + 音轨 + 字幕”
4. 详情页接入质量选择
5. Player 内增加“切换质量（重启当前流）”
6. 修正服务端进度上报中的 `PlayMethod`
7. 最后再评估“Wi‑Fi / 蜂窝默认档位”这类全局策略

---

## 10. 本轮设计结论

一句话收口：

- **可以做，而且建议做；但默认仍应保持原始文件优先播放，质量选择作为按需展开的播放前/播放中能力出现。**

更具体地说：

- 默认：`Auto = 原始文件优先`
- UI：复用现有 `Playback Options`，不要新增一排杂乱图标
- 播放中切质量：允许，但以“从当前时间重建播放”实现
- 下载中心：不与在线播放质量绑定

这套方案和当前项目已有的 VLC、下载中心、媒体库详情结构兼容性最好，也最不容易引入新的交互噪音。
