# 音轨生成字幕（macOS / iOS / iPadOS Beta）

状态：2026-09-13 已接入 macOS、iOS / iPadOS 26+ 分段生成和持久缓存，须通过设备与语言支持检测；真实语音识别及 App 交互尚待实机验证。tvOS 不启用此功能。

## 1. 产品目标

用户在没有文字字幕、只有图片字幕或现有字幕不合适时，主动选择某条音轨，将其中的对白识别为带时间轴的原文字幕。生成结果可以作为主字幕、第二字幕，或导出 SRT；可以直接自动翻译，并分别选择原文与译文显示在主字幕或第二字幕，同位置自动合并双语；成为主字幕后，也可继续使用现有“翻译主字幕”。

这条链路是“音轨 → 语音识别 → 原文字幕 → 可选翻译”。它不能恢复图片字幕的排版、画面标牌或原字幕措辞；歌曲、多人重叠对白和背景音乐中的人声效果需实测。已有文字字幕仍可直接读取和翻译，读取失败不自动开启音频识别。

## 2. 首期范围与阶段

| 阶段 | 提供的能力 | 进入下一阶段的条件 |
| --- | --- | --- |
| 技术验证 | macOS 26+ 的本机识别；本地样本的指定音轨解码、时间映射、长音频转写 | 对白准确率、时间误差、速度、内存及与 VLC 并行播放实测可接受 |
| 首版 Beta | 本地文件、已完成下载及 Jellyfin 点播；分段生成与即时显示、取消、缓存恢复、SRT 导出、接入主字幕翻译 | 完成长视频、切片、取消及原字幕回归 |
| 后续增强 | 其他远程源、多音轨的受控读取；评估旧 macOS 的本地模型方案 | 音轨映射、网络负载、分块拼接和任务恢复通过验证 |

首版按实际探测结果支持格式，不以扩展名或“VLC 能播放”承诺可以转写。纯音频文件可以生成和导出字幕，沿用原音频窗口；不因此切换成视频播放器。首期不包含直播、自动批量扫描、OCR、说话人分离、字幕编辑器、云端识别或跨设备任务同步。

## 3. 入口与使用流程

- macOS 字幕菜单提供独立的“从音轨生成字幕…”，不要求当前存在主字幕；已有“翻译主字幕”继续只面向可读取的主字幕。生成和导出不依赖第二字幕 Beta，只有把结果用于第二字幕时沿用该开关。
- 点击后在当前播放器窗口打开原生 sheet：选择音轨、确认对白语言、查看处理范围与本机处理说明，再点击“生成字幕”。优先处理当前播放位置附近，随后补齐整段媒体。
- 音轨默认对应当前播放音轨，但必须完成源音轨标识映射；不能把 VLC 音轨 ID 直接当作容器 stream index。映射不确定时展示探测到的源音轨供选择，不静默识别另一条音轨。
- 语言优先采用可靠的音轨元数据，缺失时要求选择；只列出引擎当前支持的语言。首期不承诺自动识别语言或中途自动切换多语言。
- 状态页使用系统进度控件，分别展示“准备语言资源 / 读取音轨 / 生成字幕 / 整理字幕”。可计算时显示已处理媒体时长与总时长；最终整理完成前不显示任务完成，ETA 仅在采样稳定后提供。
- 允许继续播放、关闭状态 sheet；字幕菜单保留查看进度和取消入口。首版任务归属当前播放器，关闭播放器或切换影片即取消，暂停播放不暂停转写。再次打开同一媒体时，恢复用户选中的生成字幕并立即读取缓存，启用状态下仅补齐缺失片段。
- 每段完成后立即保存并展示字幕及时间，可选择“用作主字幕”“用作第二字幕”或“导出 SRT”。不自动替换当前字幕。导出使用系统保存面板，默认 `<媒体名>.<语言>.generated.srt`。
- 切换播放音轨不自动重启任务；任务页持续标明识别的是启动时选定的音轨。需要更换识别音轨时，由用户取消后重新生成。

以上文字是设计示例，实施时必须接入本地化并同步全部八种已发货语言。

## 4. 技术路线

### 4.1 识别引擎

首选 macOS 26+ 的 `SpeechAnalyzer + SpeechTranscriber`。Apple 提供本机长音频识别、模型资源管理及按音频时间关联的结果；本地 SDK 的声明也确认这些 API 从 macOS 26 起可用。入口除检查系统版本，还需检查 `isAvailable`、支持语言和模型资源状态，不能只判断系统版本。语言资源首次使用可能需要联网下载。[Apple 官方介绍](https://developer.apple.com/videos/play/wwdc2025/277/)

较旧 macOS 首版保留正常播放和原字幕能力，仅说明生成字幕不可用，不抬高整个 App 的最低系统版本。后续可评估 `whisper.cpp` 的本机兼容方案；其提供 Apple Silicon / Metal / Core ML 路径，但增加模型下载、存储与依赖维护成本，实际设备和语言效果另行比较，不承诺比系统方案更快或更准。[whisper.cpp 官方仓库](https://github.com/ggml-org/whisper.cpp)

### 4.2 音轨读取是首要技术关卡

- 现有 `SharedLocalEmbeddedSubtitleExtractor` 抽取容器里的文字字幕，不提供语音识别，也不能直接用作通用 PCM 音频解码器。
- 首期为系统可解码的本地媒体建立独立的 AVFoundation 读取路径，输出识别器支持的 PCM 格式；不得截取扬声器输出或麦克风，也不占用主 VLC 播放器的音频回调。
- 系统无法读取本地 MKV/MKA 时，由内置 libVLC 独立实例探测并复制选中的 AC-3/AAC 压缩音轨到临时 M4A，再按需用 AVFoundation 解码。准备阶段首次扫描文件，复制时不播放声音、不输出视频、不改变正在播放的音轨，也不安装外部解码依赖。DTS 使用独立 VLC 解码为保留源采样率的单声道 PCM WAV，再交由 AVFoundation 分段转换为识别格式；TrueHD 及其他组合仍保留不支持状态。
- Matroska 音轨按容器顺序与探测结果对应，读取第一音频块的媒体时间并补回准备音轨的起点归零偏移；非零 CodecDelay 暂不支持。临时音轨副本最多保留两条，每条上限 512 MiB、准备超时 120 秒，取消或失败清理未完成文件；退出后遗留临时文件由系统回收。字幕结果仍独立持久缓存，已有完整结果无需再次准备音轨。
- 多声道转单声道要保留对白，不能简单只取左声道；重采样使用识别器兼容格式。解码使用有界缓冲和背压，禁止把整部电影解码为内存中的完整 PCM。
- 音频源 PTS、非零起点、容器时间偏移和重采样后的样本位置需映射到统一媒体时间。输出时间不使用任务启动时间、墙上时钟或播放器倍速。

### 4.3 实现模块边界

| 模块 | 职责 |
| --- | --- |
| `MacAudioSubtitleJob` | 单播放器任务状态、取消、代际与资源回收 |
| `MacAudioSubtitleSource` | 探测音轨、源身份、授权访问、PCM 与媒体时间映射 |
| `MacAudioSubtitleRemux` / `GenPlayerVLCAudioReader` | MKV/MKA 压缩音轨复制、取消及临时副本复用 |
| `MacMatroskaAudioOrigin` | 容器音轨顺序和媒体起点读取 |
| `MacAudioSubtitleEngine` | 系统能力检查、模型准备、识别与最终结果输出 |
| `MacAudioSubtitlePlan` | 分句、断行、时间轴校验、SRT 序列化 |
| `MacAudioSubtitleStore` | 已完成结果、来源关联、版本与清理 |

这些模块首期放在 macOS 条件编译范围内，不把系统识别引擎依赖加入 iOS / tvOS 路径。可复用现有字幕解析、外挂挂载和翻译入口，但不改写共享字幕选择语义。 `GenPlayerVLCBridge` 使用显式 `include/module.modulemap` 导出视频、PiP 与音轨桥接头文件，新增公开接口时同步维护该列表；包清单标明此约定，使已有 Xcode 包配置重新加载，避免旧 umbrella 目录缓存漏掉新头文件。

## 5. 时间轴与字幕质量

- 只把最终识别结果写入字幕；不把可能继续变化的临时结果作为正式 cue。
- 按词语时间信息、标点和停顿划分字幕，并结合语言控制每屏文本量；时间信息不足时保留较粗的识别片段，不伪造精确逐字时间。
- cue 必须满足时间有限、起点非负、终点大于起点且不越过媒体边界。分句不能为了缩短显示时长而任意截断实际对白。
- 保存原始媒体时间轴。主字幕与第二字幕的显示偏移沿用各自已有设置，导出默认不烘焙用户偏移，避免重新导入后二次偏移。
- seek、暂停、倍速只影响字幕查询，不改变转写时间；首版未完成时不反复重挂 SRT，生成字幕通过 macOS 本机时间轴显示；seek 只调整缺失片段的优先级。完整 SRT 可导出后走已有外挂字幕路径。
- 纯静音识别完成但无文字时显示“未识别到对白”，不生成空字幕轨；音乐、噪声和低质量对白需专门抽样，不能以“有输出”作为成功质量标准。
- 分块优先生成必须定义原始时间偏移、重叠上下文和重复句去重；不能简单按回调先后拼接文本。

## 6. 与已有字幕、翻译的衔接

生成字幕提供独立的 macOS 主字幕与第二字幕标识；分段结果直接接入媒体时间轴，避免每段反复挂载 VLC 字幕轨。生成主字幕通过稳定 cue 标识增量交给 `MacSubtitleTranslation`。导出的完整 SRT 仍可使用现有串行外挂挂载流程。窗口内生成字幕不承诺同步进入 PiP，使用 PiP 时可导出并加载完整 SRT。

用户选择原文为主字幕后，可在第二字幕中开启“翻译主字幕”；关闭主字幕仍关闭翻译。若原文被选作普通第二字幕，则与现有翻译模式互斥，首期不提供第三层字幕或“翻译第二字幕”。翻译失败只影响译文，已生成原文继续可用。

任务完成、字幕挂载、语言资源准备等异步回调必须同时核对任务代际、媒体身份和播放器当前选择。用户在等待挂载期间改选字幕、关闭字幕或切片时，旧回调不能抢回选择。PiP 是否能显示生成字幕须沿当前外挂字幕路径实际验证，不以窗口 overlay 代替验证。

- 同一生成来源追加字幕片段时复用现有翻译会话，由翻译循环增量读取新 cue 和缓存；不得仅因片段完成、seek 或播放进度更新而重建系统语言下载窗口。首次确定语言后保持选择稳定；来源、原文/目标语言或显式重试改变时才撤销旧会话。下载失败/取消保留手动重试状态，新字幕到达不自动重新弹窗。

## macOS SMB MP4 按需读取试用（2026-09-24）

- 本轮范围为 macOS 的 SMB 普通 MP4/M4V/M4A、内嵌 AAC 音轨及简单时间编辑；混合编码文件仅列出可读取的音轨，保留其原始轨道编号、容器顺序与语言，不因另一条非 AAC 音轨拒绝整片，也不将不支持的轨道请求改读其他轨道。iOS 后续接入见下文；tvOS、MKV、分片 MP4 和其他协议保持原行为。打开音轨生成面板后才读取索引，普通播放不额外启动 SMB 读取。每次只取当前 30 秒识别块（含上下文、解码预滚）所需音频，不读取整段视频或整部文件。
- 生成使用专用 SMB 会话及持续打开的只读文件句柄，在后台串行队列通过现有 libsmb2 执行按位置读取；账号沿用现有 AMSMB2 的 `域;工作站\用户名` 解析约定，不修改共享依赖或播放/浏览连接。合并相邻样本及小间隙（额外读取不超过选中音频量），单次至多 1 MiB，每段输入至多 32 MiB，限制时间和请求次数。
- 校验文件大小、修改时间、轨道索引与范围边界；支持省略 AAC 预滚标记、无编辑列表、零起点及一个前置空白加一段正常音频的编辑列表。按源文件时间表定位，不因缺少可选标记强加固定编码延迟；已有预滚标记须完整且符合单包预滚约定。拒绝加密、外部数据引用、分片及复杂编辑列表，不回退下载或识别其他轨道。身份排除凭据；seek、取消、切片沿用现有任务隔离和片段缓存；同一服务器目录恢复音轨生成偏好。
- 验证覆盖压缩音频包、原片与片段 PCM 时间对齐、双音轨、头/尾索引及异常输入，另做纯构建。真实 NAS 带宽、播放并行与语音识别须单独验证，不以本地范围模拟证明 NAS 提速。
- 临时 M4A 写入明确的 AAC 预滚及裁切标记；先按原采样率解码，需要转换识别采样率时使用单个连续转换器，避免系统音频混合读取器因媒体块边界变化而产生重采样差异。标准样本核对 44.1/48 kHz 原采样率和 16 kHz 转换；缺少可选标记、零起点与前置空白使用变化波形和独立 FFmpeg 参考核对开头、中段及片尾，不以同一系统解码器的隐式裁切作为源时间轴依据。

## iOS / iPadOS SMB 接入（2026-09-25）

- iOS / iPadOS 26+ 视频播放器接入同一 SMB MP4/M4V AAC 按需读取链路，仍须通过设备与语言能力检测；仅打开音轨生成配置页时开始索引，普通播放和主字幕翻译不启动 SMB 音轨读取。音频播放器和 tvOS 不扩展。
- 复用专用只读 SMB 会话、读取预算、域账号解析与原始轨道/时间轴校验。iOS 的地址解析与连接在读取器后台队列进行；凭据仅用于连接，不进入媒体/同目录偏好或字幕缓存身份。
- 保留原文/译文位置、缓存恢复、同目录偏好、seek/切片失效与前后台暂停生成的既有语义；不改主播放器音轨、音频会话或 PiP。iOS 使用本设备处理说明，SMB 连接失败不显示 Jellyfin/Emby 转码权限提示。

## 文件服务范围读取扩展（2026-09-25）

- iOS/macOS 将 WebDAV、FTP、SFTP、NFS 与原文件 HTTP 地址接入现有 MP4/M4V AAC 选读；macOS 继续允许 M4A，iOS 音频播放器和 tvOS 不扩展。只在进入生成配置后建立读取会话，不改变主播放、浏览或下载连接。
- WebDAV/HTTP 使用有界响应接收，要求精确 `206`、范围、总长度及未压缩的内容；复用 HTTP 会话并检查强 ETag/有效 Last-Modified，一旦返回整部响应、范围错误或版本变化立即取消。重定向保留范围限制，跨站移除认证和 Cookie，拒绝 HTTPS 降级。
- FTP 独立控制连接逐项验证登录、二进制传输及 REST；使用单个 256 KiB 对齐窗口复用相邻小范围，窗口内可包含视频数据，避免为每个音频包反复启动至文件末尾的传输。每次关闭数据连接后同步控制响应，并统计网络层接收量；每段累计超过 32 MiB 停止（最后一个在途窗口可能越过阈值），不再发起后续传输。SFTP/NFS 使用独立会话及文件句柄按偏移读取；限制每次读取、等待及取消，不能以截取整部下载结果替代范围读取。
- AList、115、OneDrive、Google Drive 使用现有认证解析原文件请求（115 不进入视频流回退，Google Drive 绕过播放代理），再进入严格 HTTP 范围读取；不将转码/播放清单当作原文件，不把临时签名、密码或 token 写入缓存身份。地址过期可重开配置重试；无法提供可靠范围与版本信息时明确失败。
- 已知文件服务沿用服务器与原始路径作为身份，签名地址更新不影响缓存；普通 HTTP 或缺少原始路径的条目保留完整查询参数参与哈希，不猜测参数是否仅用于认证，避免不同文件共用字幕。凭据及 fragment 排除，地址与参数不明文落盘；普通 HTTP 的未知签名参数变化可能生成独立缓存。
- 校验以本地协议服务/传输模拟、MP4 解码及双端纯构建为主；实际服务器兼容性、认证、并行播放、语音识别和 GUI 另行验证，未获批准不操作 App/模拟器。

## 7. 状态、存储与远程边界

- 状态流：`idle → preparing → transcribing → finalizing → completed`；任一运行状态可进入 `failed / cancelled`。同时只运行一个转写任务，其他播放器说明已有任务运行，首期不引入持久队列。失败提供原因和重新生成，不自动循环重试。
- 已完成片段与来源关联以 JSON 时间轴保存在应用支持目录 `GenPlayer/GeneratedSubtitles-v1`，导出时转换为 SRT。交给识别器的每次临时 PCM 最多覆盖 34 秒媒体（DTS 准备阶段会先生成有大小上限的整条 WAV），片段结束或取消后删除；异常退出遗留文件由系统临时目录回收。结果提供已缓存时长与删除入口；不放入下载中心，不标记媒体“已下载”，不自动写回远程服务器。
- 来源键包含媒体稳定身份、版本信息、源音轨身份、对白语言及引擎/分句算法版本。远程身份使用服务器标识与媒体 id/path 的摘要，排除密码、token、签名 URL；本地身份结合资源标识、大小和修改时间，无法确认一致时不复用。
- 完成结果采用临时写入后原子发布，`version = 1`；未知版本或损坏文件不自动挂载，允许重新生成。失败保留已有可用片段，已完成范围（含静音片段）原子保存，未完成任务不伪装为完成。
- 导出文件由用户管理，重新生成或删除应用内结果不删除用户已导出的文件。本地源文件访问沿用沙盒授权，处理期间持有授权，任务结束释放。
- 首版本机转写不上传音频；下载语言资源与读取远程媒体属于不同网络行为，界面分别说明。音频内容、字幕全文和带凭据地址不进入诊断日志，生成文件首期不自动跨设备同步。
- 远程点播优先使用有效的正式下载本地文件；未下载的 Jellyfin 单音轨媒体由用户启动生成后按段请求纯音频转码，具体边界见下文。上述文件服务按范围读取普通 MP4；其他格式或缺少范围/版本能力的远程来源提示先下载，下载完成后检测解码能力；不自动下载整部电影，不能假定任意 SMB/WebDAV/媒体服务器 URL 都能交给系统读取器。

## 8. 验证与交付条件

技术验证必须覆盖本地短音频、双音轨视频、至少一段 90 分钟以上媒体，以及目标用户常用的 MKV 组合；记录实际支持范围、处理时长、峰值内存和播放并行时的资源占用。没有测量前，不承诺实时生成、固定准确率或每小时处理耗时。

纯逻辑验证覆盖源音轨映射、非零 PTS、重采样时间换算、cue 边界、SRT 往返解析、结果复用隔离、取消与旧结果回填。代码实施后执行 macOS 与项目要求的 iOS 纯构建，确认平台隔离。

获用户批准操作 App 后，最小手工回归按四组执行：

1. 无字幕本地媒体 → 生成 → 主字幕播放 → 翻译，并导出/重新导入核对时间；抽查开头、中段和片尾的 20 句人工参照字幕，记录错词、漏句及起止时间误差，再确定 Beta 的质量门槛。
2. 双音轨选择正确，生成中切播放音轨、seek、暂停、倍速不污染结果；已有主字幕、普通第二字幕及 PiP 保持各自行为。
3. 模型首次下载、取消、资源不可用、不支持格式、磁盘不足与长视频处理；失败不影响播放或已有字幕。
4. 多播放器竞争、切片、关闭窗口、取消后立即重试及等待挂载时改选字幕；旧任务不挂载字幕、不恢复旧播放。

实现使用 30 秒固定片段，读取时前后各带最多 2 秒上下文；按词时间中点分配片段归属，缓存记录包含已处理的静音区间。seek 取消旧位置尚未完成的片段，优先识别新位置；未完成片段不记为完成。逐段保存采用原子写入，再次打开立即读取匹配的已完成片段；用户关闭生成字幕时不自动补齐。

识别源键包含本地资源身份、修改时间、大小、音轨、语言、识别适配版本及系统版本；不以 VLC 音轨 ID 猜测系统音轨，多个源音轨由用户显式选择。单进程只允许一个识别任务，删除缓存也受该限制保护；异步缓存恢复遵从后续手动字幕选择。

纯文件与逻辑检查由 `bash scripts/check_audio_subtitles.sh` 编译并运行；通过 `--media <本地MKV/MKA路径>` 可额外检查不超过 10 分钟的片源。默认从已缓存的 GenPlayerBuild 中读取 VLCKit，也可设置 `GENPLAYER_VLC_FRAMEWORK_DIR` 指向 macOS 框架目录；无需启动 App、播放声音或下载识别模型。

包含《小杰克的攻击 (2005)》284.576 秒 MKV/AC-3 的 56 项纯文件/逻辑检查、macOS 双架构与 iOS Simulator SDK 纯构建通过：原片开头、中段、片尾分段 PCM 与连续解码参考的媒体时间一致，复制音轨途中取消清理未完成文件；另验证 AAC/MKV 短样本、双音轨所选内容及 2 秒/4 秒起点补静音。该片压缩音轨准备单次约 0.23 秒，此数字不代表识别耗时。字幕缓存、重采样与注入识别结果的任务生命周期检查保持通过。真实语音识别精度、更广泛容器/编码组合、长视频速度/内存、实际译文及播放器交互未验证。原始音轨与所选语言不变时复用字幕，改变后使用独立缓存。

Apple 系统资源首次准备可能联网下载；文件输入使用 `SpeechAnalyzer`，未请求麦克风或旧版服务器识别授权。[Apple 对授权适用范围的说明](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition)
## Jellyfin 远程音频分段扩展（2026-09-13）

- macOS 26 上支持已保存 Jellyfin 服务器的单音轨点播媒体；本地及已下载媒体继续使用原有解码路径。直播、其他远程协议暂不扩展；多音轨见 2026-09-15 扩展。
- 每个识别块为 30 秒，附带两侧最多 2 秒上下文。请求 Jellyfin 纯音频渐进流，从当前块起点转为单声道 48 kHz / 96 kbps AAC；流式读取完整 ADTS 帧，读够本块即取消请求，不等待整条音轨，不下载视频。每块先落临时音频，再交给本机 SpeechAnalyzer。
- Jellyfin 将 seek 起点限制在片尾前 5 秒；请求起点取目标范围起点与 `max(0, 时长 - 5 秒)` 的较小值，读取至原目标终点，再按实际请求起点裁剪 PCM。61 秒媒体的末块因此读取 56–61 秒，裁剪为所需的 58–61 秒上下文，保持片尾内容和时间对齐；单次仍不超过 34 秒。远程识别缓存使用新的 seek 适配版本，旧结果重新生成，源身份及音轨/语言/显示偏好保持；本地缓存不受影响。
- 使用独立的 DeviceId / PlaySessionId；成功、失败、seek 和取消均停止本次字幕转码。服务端可能提前编码更多音频；请求结束后尽力停止，网络断开时由服务端清理。
- Jellyfin 的纯音频路由未显式映射 AudioStreamIndex，因此首版拒绝多音轨，避免错误识别其他语言。媒体版本须精确匹配，不静默选用另一版本。
- 复用当前播放位置优先、缺块补齐、空白块完成标记与字幕持久缓存。身份包含服务器、条目、媒体版本、时长、大小、修改信息和音轨属性；不包含 token。音频临时文件随块清理，字幕缓存可再次打开复用，不进入下载中心。
- 分段处理不保证跟得上播放速度；实际延迟由服务器转码、网络与 Mac 识别速度决定。验证须覆盖取消、seek、缓存重开、鉴权失败、多音轨拒绝及本地播放；GUI 操作遵守 AGENTS.md 3.8。
- 生成字幕在主字幕和第二字幕菜单统一显示为 `(生成)原音轨名称`，名称缺失时回退 `音轨 N`；保留媒体原始轨道名称，不以转码后的声道/编码覆盖它。
- 接口依据：[AudioController](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/AudioController.cs)、[EncodingHelper](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Controller/MediaEncoding/EncodingHelper.cs) 与 [HlsSegmentController](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/HlsSegmentController.cs)。渐进音频路由在读够 AAC 帧后取消；独立转码停止接口同时携带 DeviceId 和 PlaySessionId。

## 配置页稳定性与 DTS 适配（2026-09-13）

- iPhone/iPad 音轨配置改为独立 `NavigationStack + Form`，音轨/对白语言/显示位置使用原生列表选择页，完成按钮固定在导航栏，正文按安全区滚动；不再套用 Mac 的纵向弹窗布局。选择区域与进度/缓存状态隔离，配置页不随播放时钟更新预览，根呈现按模型身份保持稳定。既有播放器 UIMenu 展开冻结规则及翻译会话标识不变。

- MKV/MKA 的 DTS 音轨由独立 VLC 转成保留源采样率的单声道 PCM WAV 临时文件；准备完成后按原媒体时间分段读取、识别和缓存字幕。AAC/AC-3 保留原压缩音轨复制路径。准备过程只输出文件、不播放声音、不改变播放实例，取消/失败清理未完成文件；临时缓存最多两条、每条 512 MiB、单次准备限时 120 秒。DTS 长媒体可能达到准备时间/空间限制，失败保留原播放与已完成字幕。

保留 DTS 原采样率是时间同步要求：当前 VLCKit 的回退重采样器按包取整，直接将 48 kHz 转为 16 kHz 会在 477.739 秒样本中累计丢失约 1.87 秒。后续重采样仍使用 AVFoundation 分段转换；48 kHz / 16-bit 单声道临时音轨约 5.76 MB/分钟，长片可能触发上述大小限制。

iOS 字幕状态交接：显式开启翻译使待完成的生成字幕显示恢复失效，防止覆盖手动选择；无手动干预时仍按原偏好恢复。后台仅暂停翻译工作，保留手动原文语言、来源和已译结果，前台继续未完成的文字字幕加载。关闭/删除生成主字幕立即清理它的翻译来源并重新检测当前主字幕，不依赖播放时钟回调，也不清理仍在使用的普通主字幕翻译。

- 普通主字幕翻译在第二字幕仅显示译文，不再提供显示内容选择；音轨生成仍按目标位置组合双语并保留顺序选择。

- 待生成音轨/语言的显示配置与当前缓存的生效位置分离，只有应用对应缓存时才切换。仅缓存生成不占用显示位置，也不关闭已有主字幕翻译；普通主字幕翻译入口显式切换翻译来源。
