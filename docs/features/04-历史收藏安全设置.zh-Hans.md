# 模块 04：历史、收藏、安全与设置

## 1. 当前功能概览

- 历史记录：区分本地与远程记录，支持续播位置、音轨/字幕选择记忆、按服务器清理。
- 收藏能力：支持本地/远程项目收藏，删除服务器时联动清理对应收藏。
- 安全能力：应用锁（PIN / 复杂密码）+ 隐私空间 + iOS 生物识别解锁，凭据与 PIN 从 UserDefaults 迁移到 Keychain；tvOS 端仅提供密码解锁，不接入生物认证。
- 全局设置：主题、语言、播放偏好、历史开关、缓存清理等。
- 个人页聚合：历史与收藏聚合展示，并可直接进入播放。

## 2. 关键实现位置

- 历史服务：`HistoryService`。
- 收藏服务：`FavoriteService`。
- 安全服务：iOS 使用 `SecurityService` + `KeychainService`；tvOS Shell 使用密码-only 的 `TVSecurityService` 并复用同一批 Keychain / UserDefaults key。
- 设置页：`SettingsView` + `AppSettings`。
- 聚合页面：`ProfileView`、`RecordListView`、`FavoritesListView`。

## 3. 开发实现步骤（建议模板）

1. **明确数据边界**：先确定是“播放态数据”还是“用户偏好数据”。
2. **服务层扩展**：在 `HistoryService` / `FavoriteService` / `SecurityService` 扩展模型与存储。
3. **持久化与迁移**：设计好 UserDefaults 与 Keychain 的迁移、回滚和兼容策略。
4. **页面绑定**：在 `ProfileView` 与 `SettingsView` 接入新增开关/入口。
5. **删除级联验证**：服务器删除、记录清理、收藏清理需一致。
6. **隐私回归**：验证关闭历史记录开关后不会落库敏感行为。

  - 根据设备类型（iPhone/iPad）自适应按键尺寸与间距，提升横屏可读性与触控命中。

  - 设置页在开启生物识别前，先校验设备是否已配置且当前可用；若系统未录入 Face ID / Touch ID、设备不支持，或当前被系统锁定，则不允许开启并给出明确提示。
  - 锁屏页的生物识别按钮改为仅在“当前真的可用”时显示，不再只依赖用户偏好开关，避免出现“按钮存在但点击无效”的假入口。
  - 对已保存但已失效的生物识别偏好（如系统移除了录入）会自动清理回退到 PIN 解锁，减少状态漂移。

## 7. iCloud 配置同步设计（Phase 5 修订）

> 结论先行：**优先同步服务器列表（非敏感配置）与隐私空间标记快照**。历史/收藏/播放偏好默认保持“仅本机”，避免跨设备污染与语义错配。

### 7.1 为什么先只同步服务器列表与隐私标记

- 服务器地址/类型属于“连接入口”信息，多设备复用价值高。
- 隐私空间标记本质上是对服务器 / 文件夹 / 相对路径的保护规则，跨端保持一致可以避免 Apple TV 已同步服务器后仍暴露 iOS 端已标记的私密入口。
- 历史、收藏、下载状态、播放偏好往往与当前设备使用场景强相关：
  - A 设备（iPad）和 B 设备（iPhone）的观看进度、下载可用性、交互偏好可能明显不同。
  - 跨设备强行合并容易引入“误覆盖/误恢复”。
- 结合当前阶段目标（Phase 5），先落地低风险同步面更稳妥。

### 7.2 同步范围（修订）

- **允许同步（服务器配置骨架 + 隐私标记快照）**：
  - `ServerConfig` 的非敏感字段：`id`、`name`、`type`、`host`、`port`、`basePath`、`useSSL`、排序索引等。
  - `PrivacySpaceService` 的标记集合快照：服务器 UUID、相对本地路径、`serverUUID|normalizedRemotePath` 远程文件夹标记。
- **禁止同步（必须继续本机/Keychain）**：
  - `passwordSecret`、`accessToken`、PIN、生物识别状态。
  - 历史记录、收藏记录、下载任务状态、播放偏好参数。

### 7.3 设置页建议（最小开关）

- 设置首页不直接铺开 iCloud 同步配置，而是在 `Advanced` 分组提供 `iCloud Sync` 入口，进入二级页后再配置 `Sync Server List via iCloud`（默认关闭）。
- 开关说明文案明确：
  - “仅同步服务器基础信息与隐私空间标记，不同步账号密码、Token、历史与收藏”。
- 可选辅助按钮：`Sync Now`（手动触发一次拉取/推送）。
- 同步入口应保持“设置页原生密度”：
  - 设置首页只保留单行入口，避免在一级设置页直接展开大块同步配置。
  - 二级页内优先使用标准分组行样式承载开关、状态与手动同步动作，不要做成占满一大块的仪表盘式大卡片。
  - 状态信息需收敛到 1 个紧凑状态行中，重点表达当前状态、同步结果和上次同步时间；敏感信息仅本机的说明放在辅助文案或 footer。
  - `Sync Now` 点击后必须出现立即可见的进行中反馈，并在完成后明确展示结果，避免“点了像没反应”。
- iOS 14 兼容要求不变：仅用现有 `Toggle` + `Alert`。

### 7.4 技术方案建议（按复杂度）

- **首选：`NSUbiquitousKeyValueStore`**
  - 保存轻量服务器列表快照（建议压缩字段）。
  - 适合“少量配置 + 低频变更”的场景。
- **后续可选：CloudKit 私有库**
  - 仅在服务器条目数量和协同复杂度上升时引入。
  - 记录类型可先收敛为 `GPServerProfile`，不扩展到历史/收藏域。

### 7.5 冲突与数据一致性

- 当前最小实现采用**时间戳驱动的 `latestWins`**：
  - 远端 payload 的 `updatedAt` 新于本地时，才允许覆盖本地服务器列表。
  - 本地较新时保持本地列表，并在同步开启/手动同步时反推回 iCloud，避免旧远端快照误覆盖本机。
  - 本地服务器列表除了保留现有 `UserDefaults` 快照外，还必须额外镜像一份“`updatedAt + servers`”原子文件快照；启动恢复与 iCloud 回推时应以本地持久化来源里版本号更新的那一份为准，避免编辑后用户立刻强杀 App 时，又因为 `UserDefaults`/KVS 尚未完全落盘而回退到更老的服务器列表。
  - 为避免设备时钟漂移或历史异常时间戳导致“旧远端快照反向覆盖本地新编辑”，本地每次推送到 iCloud 时，`updatedAt` 必须按 `max(本地候选时间, 当前远端 updatedAt + 1)` 生成，保持版本号单调递增，而不是完全依赖单机墙钟时间。
  - 若远端 payload 的 `updatedAt` 明显超出当前设备时间（当前实现按“超过当前时间 24 小时”视为异常），必须将该快照视为不可信，不得继续拿它覆盖本地服务器列表；此时应优先保留本地列表并反推回 iCloud，清理被旧版本遗留的异常未来时间戳。
- 删除语义：
  - 当前实现仍以“最新列表快照”为准，远端较新的删除会落地到本机。
  - 远端同步导致的服务器移除，必须执行与手动删除服务器一致的级联清理（历史 / 收藏 / Keychain / 缓存），不能只替换数组。
- 与本地安全约束保持一致：
  - 同步到新设备后，若缺少本机 Keychain 凭据，服务器显示“需重新登录/补凭据”。

### 7.6 权限与审核影响

- iCloud/CloudKit 本身通常不触发运行时权限弹窗（用户需系统登录 iCloud）。
- Capabilities 开启：`iCloud`（及方案需要时的 Key-value storage）。
- 审核风险较低；关键是**隐私说明与实际行为一致**（仅同步服务器基础配置，不含凭据）。

### 7.7 后续扩展门槛（何时再考虑同步历史/收藏）

仅当以下条件满足再评估：

1. 已有清晰跨端合并策略（进度、去重、冲突可解释）。
2. 用户可按域开关并可一键回滚。
3. 下载中心“本地文件缺失”语义和修复流程已稳定。

### 7.8 当前落地状态（2026-03）

- 已完成最小实现：设置首页新增 `iCloud Sync` 入口，二级页内提供 `Sync Server List via iCloud` 与 `Sync Now`。
- 设置页已进一步收口为更接近系统原生设置页的层级：首页只保留入口，详细同步配置放在二级页，减少首页纵向占用，也为后续增加更多同步数据预留空间。
- 服务层已接入服务器列表自动推送/手动同步；同步内容包含服务器非敏感字段与隐私空间标记快照。
- 凭据类字段继续仅走 Keychain，不进入 iCloud 负载。
- 工程已补齐 iCloud Key-value Storage entitlement，可在开发者账号签名下进行真机联调。
- 应用启动、回到前台和 `NSUbiquitousKeyValueStore` 外部变更通知都会尝试拉取较新的远端快照，减少必须重启应用才能看到另一台设备改动的情况。

## 8. 应用图标设置补充（2026-03）

- 设置页中的应用图标候选预览应保持接近桌面图标的统一视觉尺寸，避免预览图过大导致与实际系统图标尺寸脱节。
- 备用图标切换除了资产目录中的 `AppIcon*.appiconset` 外，还必须保证 `Info.plist` 中存在 iPhone / iPad 对应的 alternate icon 声明，避免设置页可点选但系统切换无效。

- 当前主图标基线调整为 `Aurora`，设置页图标选择器需要同时覆盖主图标、旧主图标与所有已注册 alternate icon，并优先使用网格卡片展示，避免候选增多后横向滚动难以查找。

## 9. 问题反馈与关于页补充（2026-03）

- 设置首页 `Advanced` 分组提供独立的 `Send Feedback` 入口，默认面向开发者邮箱发起问题反馈；不再放在“关于”页内部。
- 反馈链路**不引入 SMTP 服务**，统一复用系统能力：
  - 首选 `MFMailComposeViewController` 在应用内唤起邮件编辑器。
  - 若设备未配置系统 Mail，则退化为 `mailto:` 打开外部邮件客户端。
  - 若当前设备没有任何可用邮件能力，则提示用户先配置 Mail 或安装邮件客户端，避免误以为应用内已经发出反馈。
- 邮件正文应预填最小诊断信息：App 版本、构建号、iOS 版本、设备类型、主题、应用语言、系统语言、时间戳；不拼接账号、服务器地址、Token、密码等敏感信息。
- “关于”页仅保留应用简介、官网、版权与开源许可等静态信息，避免和反馈动作混杂。
- 随着“关于”页内容增多，设置首页的 `About` 入口应改为标准 `NavigationLink` 二级页面，而不是独立 `sheet` 弹窗；保持和 `Storage`、`Advanced` 等设置子页一致的导航层级，避免长内容在弹窗语义下显得局促。
- “关于”页中的官网入口必须指向当前公开站点 `https://genplayer.fugary.com/`，并额外提供隐私政策直达入口 `https://genplayer.fugary.com/privacy.html`，便于用户和审核链路在 App 内直接访问公开信息页。
- “关于”页里的官网 / 隐私政策 / 开源许可入口应采用统一的卡片行样式（图标 + 标题 + 辅助副文案 + 右侧指示），避免多条链接视觉黏连；不直接在行内裸露完整 URL，点击后优先使用应用内浏览器打开。
- “关于”页中的开源许可清单必须跟随工程当前真实依赖同步更新；新增 FTP / SFTP / NFS / PiP 等能力后，至少补齐 `VLCKitSPM / MobileVLCKit`、`FilesProvider`、`libssh2`、`NFSKit` 等对应条目，避免展示内容落后于实际使用库。

## 9.2 存储页信息架构补充（2026-03）

- 设置首页保留独立的 `Storage` 二级入口，位置放在 `Send Feedback` 之前；不再把存储相关能力继续塞在 `Advanced Settings` 内部，降低查找成本。
- `Storage` 页统一承载三类内容：
  - `Downloaded Content`：展示下载中心正式下载占用，并提供“清空已下载内容”入口。
  - `Image Cache / Remote File Cache`：继续展示容量并提供清理动作。
  - `Device Storage`：系统总容量 / 可用空间概览卡固定放在页面底部，不再插在下载中心列表顶部。
- 从 `Storage` 页清理下载内容时，必须复用下载中心同一套删除链路：同时移除下载记录、正式下载文件和残留临时文件，避免“设置里删了，下载页还有残留”。

## 10. 下载中心与本地文件联动补充（2026-03）
- 下载中心的“已完成 / 失败”记录按创建日期分组展示，组头通过菜单区分“按日期删除文件 / 删除记录”；真正执行前必须经过确认，且应与单任务 `more` 菜单保持一致语义。
- 本地文件列表对被下载中心追踪的离线文件显示下载标记，与收藏五角星保持同层级提示，便于快速区分普通本地文件和离线缓存文件。
- 用户若绕过下载中心直接删除本地下载文件，下载记录不能继续显示为“已完成”；应用内对已下载文件执行重命名或移动时，应同步更新追踪路径，避免误判为文件丢失。
- 收藏中的本地路径与本地文件持久化路径应优先使用相对 `Documents` 的相对路径；版本升级或沙盒根路径变化后，仍应能恢复到同一文件/文件夹。
- 下载中心的已完成任务应提供“在文件夹中显示”一类的直接跳转入口，并应直接展示当前离线文件所在的相对目录；点击记录本身也应能快捷跳转到该目录。
- 下载任务持久化中的本地文件路径同样应优先使用相对 `Documents` 的相对路径，避免升级后沙盒根路径变化导致下载记录丢失定位。

## 11. 开屏与首次引导补充（2026-03）

- 启动流程采用统一根容器控制：`Splash -> Onboarding -> MainTabView`。
- 首次引导完成状态通过 `onboardingCompletedVersion` 持久化；后续如引导内容更新，可通过升级版本号触发重新展示。
- 首次安装且尚未显式选择语言时，`appLanguage` 必须默认保持 `system`，不能在其他设置层写入英文等硬编码默认值。
- 设置页 `General` 分组中的语言项必须提供明确可见的独立入口，并在入口右侧展示当前语言摘要；不应只依赖行内小菜单承载多语种切换。
- 当 `appLanguage == system` 时，启动应读取当前系统首选语言，并只映射到应用已支持语言集合；当前稳定开放 `zh-Hans / zh-Hant / en / es`，其余未开放语种统一回退到英文。
- “跟随系统”模式不得把解析后的语言再次持久化为 `AppleLanguages` 覆盖值，否则会导致后续系统语言切换后应用仍停留在旧语言。
- 语言切换不得通过根视图 `.id(...)` 强制重建 `MainTabView` 来刷新文案；应保持 `TabView` 选中态与各 tab 的导航栈不被重置，避免用户在设置页切换语言后被自动跳回前一个 tab 或根页面。
- 多语言扩展继续采用“分阶段可回滚”策略；当前设置页稳定开放 `繁体中文 / 西班牙语` 及既有 `英文 / 简体中文` 入口；`日语 / 韩语 / 法语 / 德语` 资源包若出现编码或翻译损坏，必须先修复后再重新开放入口。
- “东亚主流语种”在本项目中的优先候选定义为：`日语(ja)`、`韩语(ko)`，第二梯队可按用户来源再评估 `泰语(th)`、`越南语(vi)`、`印尼语(id)`；若未达到翻译覆盖阈值，不提前进入设置页可选项。
- “西语大盘”按产品国际化常规拆分为：`西班牙语（西班牙）es-ES` 与 `西班牙语（拉美）es-419`；若首期只上线一个版本，默认优先 `es-419` 以覆盖更多拉美地区用户。
- 开屏仅承担品牌与启动过渡，不承载权限弹窗和重业务逻辑，避免阻塞主流程。
- 引导内容聚焦五类高频认知：产品定位、媒体源接入、隐私空间、离线下载路径、播放手势与播放前选轨能力。
- 隐私空间页需要明确说明三件事：
  - 入口在 `Settings -> Privacy Space`。
  - 真正加锁动作发生在服务器或文件夹菜单里的“添加到隐私空间”。
  - 安全边界属于 GenPlayer 应用内访问控制，不应表述成替代系统级设备加密。
- 设置页 `General` 分组提供“重新查看引导”入口，允许已完成用户手动重放引导，降低文档依赖。
- 引导页面默认跟随应用当前语言与主题：文案继续使用本地化资源，视觉配色按浅色/深色模式自适应，避免在深色主题下仍强制显示纯浅色引导界面。
- 引导视觉升级为“品牌进度头部 + 功能预演主画面 + 行动说明底部卡片”的沉浸式结构，不再只用单张静态文案卡承载全部信息。
- 引导页面必须按设备尺寸做响应式收口：窄屏手机保持纵向单列阅读，iPad/宽屏优先使用双列分栏，并保证演示卡与说明卡在宽屏下顶部、底部基线稳定，避免出现一边高一边低或内容被垂直居中的观感回退。
- 每一页除标题与摘要外，还应明确展示：
  - 用户能立刻感知到的能力点（如统一浏览、离线可用、播放前选轨）。
  - 对应入口路径（如 `Network -> Add Server`、`Details -> Download`、`My -> History/Favorites`）。
  - 一条低负担的建议首步，帮助首次安装用户快速进入主流程。
- 媒体源页需要覆盖当前已支持的文件协议与媒体服务集合（SMB / WebDAV / Jellyfin / Emby / Plex / FTP / SFTP / NFS），并显式提示“自动发现 + Keychain 凭据保护”这两个新版卖点。
- 离线下载页需要基于最新下载中心能力描述：任务分组、状态流转、完成后“在文件夹中显示”、播放优先命中本地文件，不再停留在早期 MVP 级表述。
- 播放与回看页除了手势外，还应说明历史 / 收藏可回到对应详情、详情页支持播放前音轨 / 字幕预选，突出“浏览、回看、播放”已经是一条连续链路。

## 12. 赞助支持与 VIP 限定应用图标（2026-09）

- **国内商店赞助支持（Donation & StoreKit）**：
  - 针对国内 App Store 用户的自愿赞助支持体系：提供「请喝咖啡（¥6）」、「请喝好茶（¥6）」与「终身支持者（¥12 超值）」三档 In-App Purchase 赞助。
  - **合成机制**：用户若分别购买了「咖啡」与「茶」，系统自动合成升级为「终身支持者」（Lifetime Supporter）身份。
  - **跨设备双向同步**：通过 `NSUbiquitousKeyValueStore`（iCloud KVS）结合本地 `UserDefaults` 实现多端赞助状态同步（iOS 购买后 Mac 自动解锁，Mac 购买后 iOS 自动同步）。
  - **海外商店策略**：海外用户直接按付费下载交付，海外 Storefront 默认直接享有终身支持者专属权益。
  - **核心功能完全开放**：赞助遵循自愿原则，所有核心播放、媒体库及下载功能均 100% 开放，不受赞助状态限制。
- **VIP 尊享限定应用图标（VIP App Icons）**：
  - 推出「曜黑金（Midnight Gold）」与「皓白金（Ivory Gold）」两款尊享限定金属质感图标。
  - 尊享图标绑定终身支持者身份，未解锁时卡片展示 👑 徽标，点击自动引导至赞助支持页面或弹窗；解锁后可自由切换。
  - **macOS 多端适配**：
    - macOS 端通过 `NSApplication.shared.applicationIconImage` 实现原生 Dock 图标动态无缝更换与恢复默认；
    - 针对 macOS Dock 设计规范，自动对 1024x1024 原图进行连续圆角（Continuous Squircle 22.5%）平滑裁切；
    - 持久化配置至 `macSelectedAppIcon`，在 App 启动与激活阶段自动重新应用。
