# iPhone Duo 自适应布局

## 目标与边界

- 外屏保持现有 iPhone 浏览与播放入口；内屏和分屏根据当前窗口、容器宽度及 size class 调整布局，不按设备名称判断。
- 展开、合拢和窗口缩放只改变布局，不重建导航、媒体库请求或播放会话；保留当前页面、搜索、播放进度、暂停、字幕与缩放状态。
- 本轮先完成 iOS 自适应基础。iOS 15 兼容路径保持，macOS/tvOS 壳层与共享数据服务不变。不新增用户文案。
- 使用 Xcode 27.1 / iOS 27.1 SDK 构建以启用 Duo 完整显示区域；不提高最低系统版本、不强制全局切换开发工具链。
- 正式版 Xcode 27.0 可构建发布：27.1 专用侧栏、网格扩宽与播放器遮挡读取通过 SwiftUI 模块版本 `8.0.85.27` 进行编译期隔离，并保留运行时版本判断。旧 SDK 沿用原安全区/网格/工具栏分支，窗口自适应基础仍保留；正式包不包含这些 27.1 专用增强。两套 Xcode 的 Swift 编译器版本相同，不使用 `compiler` 条件区分。

## 布局方案

| 页面/链路 | 本轮处理 |
| --- | --- |
| Jellyfin / Emby / Plex / VOD 首页轮播 | 从视图所属窗口读取当前尺寸，展开、合拢及分屏时重新计算高度，保留轮播选中项 |
| Jellyfin / Emby / Plex 首页与影片详情、VOD 首页 | 首页内容分别恢复左右安全区；三类详情仅窄屏手机侧栏场景释放侧栏一侧的正文留白。首页退出使用系统关闭语义，避免将侧栏留白复制到另一侧 |
| Jellyfin / Emby / Plex「我的媒体」与详情按钮 | 卡片图片严格限制在网格列宽内；iOS 27.1 详情返回和首页放在同一原生导航组，按返回、首页排列并允许侧排；旧系统保留原组装方式 |
| 媒体库 / IPTV / VOD 原生搜索入口 | 沿用原生 UISearchController / integratedButton，由系统处理按钮与输入框展开，不给搜索项指定侧排轴或额外工具组；旧系统保留原搜索路径 |
| 媒体库分类、历史、收藏、服务器网格 | 保留原生导航与已有容器/size class 自适应，不改数据与导航结构 |
| 本地/远程文件网格、演职员详情 | 宽窄布局根据当前 size class 选择密度，Duo 内屏能使用宽布局，窄分屏回到紧凑布局 |
| 视频播放器 | 控制层依据可用宽度选择完整控制组，窄窗口将播放键与菜单分两行避免重叠；分别处理四边安全区；手势使用当前容器尺寸，亮度使用播放器所属屏幕；尺寸变化撤销未提交的拖动预览及双指手势，播放实例保持 |
| 悬浮音频播放器 | 在已避让安全区的容器内计算水平停靠，不重复扣除左右安全区；安全区变化时重新限制位置，保留收起/展开阈值 |

## 媒体库侧边工具栏与内容留白

- Duo 外屏及内屏横向的返回/关闭控件遵循系统侧边工具栏；服务器首页退出使用 `cancellationAction` 表达关闭语义，由系统决定位置，不硬编码在屏幕左侧。普通横向导航栏保持系统前导位置。
- Jellyfin / Emby / Plex 首页与影片详情、VOD 首页分别恢复左右安全区，禁止将 `max(left, right)` 同时用于两侧。首页轮播背景继续铺满，下面的分区在安全区域内保留常规内容边距；不铺满的首页不再重复添加安全区。详情的窄屏手机在 iOS 27.1+ 原生侧栏环境下例外：正文不再恢复侧栏一侧的整高留白，海报、文字、播放及操作区按扩展后的内容宽度排布，另一侧和顶部避让保持。普通横向导航、iPad 与宽布局仍恢复原有两侧安全区。
- Jellyfin / Emby / Plex 首页的继续观看、接下来播放、收藏、最新内容，以及详情的演职员和相关推荐横向列表，在系统侧栏场景下将视口扩展到页面边缘；VOD 首页分类分区采用同一规则。滚动首尾停靠边距与正文实际恢复的边距分别传递：正文已延伸的详情不再重复扩宽视口，末张卡片仍可滚到工具栏内侧。不取消原生按钮材质，不把整条安全区当作不透明侧栏。
- Jellyfin 剧集详情的“接下来播放”卡片根据父容器剩余宽度收缩，最多 560；不能用未扣除边距的外层几何宽度固定卡片，再叠加安全区使页面与背景整体撑宽、偏移。
- 分类、合集及演职员作品的纵向海报网格保留系统安全区，避免固定列的条目滚入侧栏后无法横向移出。仅在 iOS 27.1+ 系统侧栏场景下让海报宽度跟随实际网格列宽，保留既有最小列宽、列间距和演职员页最大列宽；旧系统及普通横向导航继续使用原海报尺寸。三类媒体库的搜索结果列表和缩略图网格已填满安全区内的列宽，不额外扩展到按钮后方。VOD 分类/搜索结果的海报与缩略图也有固定卡宽，接入相同的侧栏专用列宽计算。
- 保留退出回原入口、返回上一级、房子回当前服务器首页的原有处理函数；分类/搜索页沿用系统安全区，外层网络页与 Tab 不改动。
- Jellyfin / Emby / Plex「我的媒体」卡片的背景图按网格实际分配的宽高裁切，不允许图片固有比例撑宽列或覆盖列间距；保留既有列数、卡片高度与点击入口。
- 「查看全部」保留靠右及原安全区，不紧贴分区标题。卡片视口可延伸，但固定入口尚不跨越原生按钮区域；此处按用户选择暂不改动。三类详情的安全区测量层级与播放按钮宽度另按[媒体库一致性规范](02-远程服务与媒体库.zh-Hans.md)统一，影响全部 iOS，不仅是 Duo。
- 三类媒体库的影片详情在 iOS 27.1 使用与分类页相同的 `navigation` 原生组，内部按返回、首页声明并允许侧排；不混用 `cancellationAction` 与 `navigationBarLeading`，避免系统按位置优先级重排。旧系统保留 Jellyfin/Emby 的横向组合与 Plex 的独立按钮。返回只退一级，首页只回当前服务器根页。
- 搜索会从图标展开为宽输入框，不能按普通图标按钮强制侧排。保留常驻原生 UISearchController / integratedButton，不设置搜索项 axisBehavior、不把 searchBarPlacementBarButtonItem 注入 trailingItemGroups；系统负责展开与收回。共用组件覆盖媒体库、IPTV、VOD，查询、键盘与离页恢复需运行抽样。
- 使用共用原生搜索的页面在 iOS 27+ 明确关闭导航栏滚动收起（`toolbarMinimizationBehavior(.never, for: .navigationBar)`）。仅设置 `hidesSearchBarWhenScrolling = false` 不约束整条导航栏的收起行为；标题与搜索不应在向下浏览时一同消失。Jellyfin/Emby/Plex 首页及分类、IPTV 播放列表、VOD 首页采用同一规则；iOS 15–26、文件页搜索及 macOS/tvOS 不迁移。仍使用同一个原生搜索控件，不改变展开动画、键盘、查询、结果详情和关闭后的浏览现场。
- 抽样范围：Duo 外屏的分区标题/首张卡片/详情操作区与右侧工具栏，内屏及普通 iPhone 横竖屏；确认关闭顺序、返回/房子/退出、搜索与滚动现场。纯构建不能证明实际位置。

## 半折叠与保留行为

- 本轮不根据宽高比猜测折痕位置、不硬编码 Duo 分辨率或半屏尺寸。自定义播放控制仅使用 reserved regions 判断侧边区域能否释放；半折叠下的专门视频/控制区布局，需要结合 Device Hub 的真实布局继续确认。
- 背景和视频可铺满容器；原生工具栏由系统避让，常规页面控件遵循安全区。上文窄屏详情允许正文滚过浮动工具栏下方，保留原生按钮的覆盖和命中；不以整页固定留白代替局部遮挡。保留原生搜索、菜单、sheet 和 Alert 的呈现方式。
- 全屏视频的中部、底部自定义控制在 iOS 27.1+ 侧栏场景下按实际占用区域避让：读取所属窗口的相机等 occlusion 区域和状态栏矩形，只有与控制区不相交时才释放侧栏一侧的水平安全区；顶部按钮行也独立使用实际遮挡判断，时间/电量行及另一侧保留原边距。存在活动折叠 division 区域时保留原避让，不借此宣称完整半折叠支持；普通设备、横向导航和旧系统走原路径。仅调整布局，不改变视频比例、播放、seek 或菜单动作。
- 保持视频全屏、音频 sheet/浮窗入口；不改变自动续播、seek 松手提交、PiP、生成字幕和手动字幕选择语义。
- 仅 iOS 27.1+ 的 regular 宽度且 regular 高度手机布局暂缓按影片比例自动旋转；普通大屏 iPhone 横屏的 regular 宽度/compact 高度和旧系统仍遵循原旋转设置，不能只凭宽度阻止旋转。

## 后续规范检查与版本隔离

| 检查范围 | 静态检查结论与处理 |
| --- | --- |
| Jellyfin / Emby / Plex 首页 | 继续观看、接下来播放、收藏、最新内容共用的横向列表扩展视口，标题及首尾卡片保持安全停靠；「我的媒体」网格继续避让工具栏 |
| Jellyfin / Emby / Plex 分类、合集及演职员作品 | 保留纵向网格安全区，仅侧栏场景下卡片填满实际列宽；演职员作品保留最大宽度。分页、排序、grid/list 切换及详情导航不变 |
| Jellyfin / Emby / Plex 搜索 | 主结果为可点击的全宽列表，保留原安全区；Jellyfin/Emby 独立搜索的顶部建议是原生横向列表，未套用首页手动恢复安全区的容器，不额外添加负边距。原生搜索入口、查询历史与键盘行为保持 |
| Jellyfin / Emby / Plex 影片详情 | 窄屏手机的原生侧栏环境下，正文及操作区释放侧栏一侧的整高留白；横向视口不重复扩宽并保留首尾停靠。普通横向导航、iPad 与宽布局保持原安全区 |
| VOD 首页 / 分类 / 搜索 / 影片详情 | 首页分类横向分区扩展视口；分类/搜索结果网格按实际列宽调整。详情仅侧栏场景逐侧避让，普通横向导航与旧系统保持原边距 |
| 原生媒体库 / IPTV / VOD 搜索 | 撤掉强制侧排轴和额外搜索工具组，恢复原生集成按钮路径；避免把宽输入框挤入固定宽度侧栏。未改搜索控制器生命周期、查询与结果导航 |
| 本地 / 远程文件网格与拖放 | 常规工具项彼此独立；侧边栏场景的拖放空白区改用当前浏览容器高度，旧系统及普通横向导航仍走原屏幕高度分支 |
| 网络 / 个人 / 历史 / 收藏 / 下载中心 / 设置 | 常规内容沿系统安全区，导航为原生控件，未发现与本次截图相同的横向多按钮包装；不顺带更换既有交互或布局 |
| 文件夹选择 / 预览 / 信息与配置弹窗 | 原生文字操作仍可留在横向栏，标题与有意义的文字不强制图标化；未根据静态猜测改动弹窗尺寸或呈现方式 |
| 播放器 / 浮窗 | 视频中部/底部控制按实际遮挡区释放侧边留白，顶部按钮行独立按实际遮挡避让，时间/电量行与浮窗保持前序适配；专门的半折叠与硬件保留区域尚未实测，不宣称完整支持 |

- 侧边栏专用内容边距/高度逻辑必须同时满足 iOS 27.1 API 可用和系统当前有侧边栏环境；图标工具组的轴偏好交由系统决定实际方向。不按设备名或宽高比猜测，旧系统保留原有工具组结构。
- 用 iOS 15 最低部署版本纯构建检查 API 兼容，实际旧系统交互与姿态变化仍需批准后的设备抽样；编译通过不是运行验证。

## 验证与交付标准

1. 静态检查和 iOS 27.1 SDK 纯构建；纯构建不代表折叠或播放验证通过。
2. 下载完成且用户批准操作后，在 Duo 外屏 → 内屏 → 窄分屏 → 外屏抽样检查媒体库轮播/详情/搜索现场；本地或远程文件网格与演职员页无裁切。
3. 播放中和暂停中各切换一次显示形态，检查进度、主/第二字幕、缩放与控制可达性；拖动预览中缩放窗口不误提交 seek，随后仍能正常拖动。
4. 检查不对称安全区下的控制层、悬浮音频停靠；抽样普通 iPhone 竖横屏与 iPad，确认旧行为。半折叠及 PiP 单独记录实际结果。
5. 三类媒体库首页/详情及 VOD 首页的横向列表在侧边空白区域可见、可滑动，末张卡片仍能滚回工具栏内侧并点击；分类/合集/演职员作品及 VOD 结果网格填满安全区内的列宽。抽样宽度恰好增减一列、旋转和浅深主题，检查列间距、海报比例、上下行文字对齐及返回后的浏览现场；旧系统与横向导航保留原卡宽。
6. 播放器状态栏下方的进度条及中部/底部按钮利用空闲宽度。旋转/分屏、状态栏显隐和内外屏切换后重新避让；正在拖动进度条时若宽度改变，撤销旧坐标的预览，不误跳播放位置。
