# 10 多端适配（macOS / tvOS 壳层与原生交互基线）

> 目标：在不回退 iOS 已有交互与播放器链路的前提下，为 macOS 和 tvOS 建立可持续演进的应用壳层、导航模型和播放器抽象，为后续正式引入新 target 做准备。

> iPhone Duo 的 iOS 自适应范围、页面覆盖和待验证姿态见 [iPhone Duo 适配](17-iPhone-Duo适配.zh-Hans.md)。

## 1. 当前阶段结论

- `GenPlayerCore` 已经完成首轮抽取，可承载共享模型、下载中心、历史、收藏、Keychain、网络浏览与服务器配置等核心能力。
- App 层目前仍保留大量 `UIKit` / `UIApplication` / `UIDevice` / `UIScreen` 直接依赖，尤其集中在：
  - `GenPlayer/Source/App/GenPlayerApp.swift`
  - `GenPlayer/Source/Services/VLCPlaybackService.swift`
  - `GenPlayer/Source/Views/*` 中的播放器、搜索栏、窗口/方向管理、浮层与状态栏逻辑
- 这意味着“直接把当前 iOS target 复制成 macOS / tvOS target”风险较高，容易在初次接入阶段引入大面积编译失败与交互回退。

## 2. 本轮落地范围

### 2.1 平台入口拆分

- `GenPlayerApp.swift` 调整为平台感知入口：
  - `iOS`：继续使用现有 `StartupFlowRootView`
  - `macOS`：进入 `MainSplitView`
  - `tvOS`：进入 `TVMainView`
- iOS 专属的 `AppDelegate`、界面刷新与安全校验保持只在 `#if os(iOS)` 下启用，避免把 UIKit 生命周期强绑到其他平台。

### 2.2 新增平台壳层

- `MainSplitView.swift`
  - 使用 `NavigationSplitView` 建立 macOS 的“边栏 + 内容 + 详情”结构。
  - 左侧优先承载：本地、服务器、历史、收藏、设置，以及服务器快捷入口。
  - 中间列展示当前选中分组的概览信息。
  - 右侧详情列先提供稳定占位，后续再逐步接入真正的浏览器、媒体详情与播放页。
- `TVMainView.swift`
  - 使用顶层 `TabView` 承载 tvOS 主导航。
  - tv 端信息架构当前收口为 `Network / My / Settings`：
    - `Network` 负责承接服务器管理、发现与媒体库直达，不再和“本地文件”共用一个模糊的浏览入口。
    - `My` 承接 `History / Favorites / Downloads` 以及下载后的离线内容回看，避免把 Apple TV 端并不存在手动导入能力的本地沙盒单独包装成一个根 tab。
    - `Settings` 承接统计概览与清理类维护动作，不继续照搬 iOS 的密集分组表单。
  - 文件型能力以“可聚焦卡片 + 可下钻浏览器”为基线，不直接复用 iOS 上的触屏式列表交互。
- 壳层代码不再继续留在 `GenPlayer/Source` 主 app 目录中独立演进：
  - 已进一步抽出到 `GenPlayerCore` 包内的新 target `GenPlayerShell`
  - 该 target 负责承载 `MainSplitView`、`TVMainView`、共享导航模型、播放器包装接口与多语言资源
  - 这样后续新增 `macOS / tvOS` app target 时，只需要极薄的 app wrapper，而不必把整棵 iOS 源码树纳入 target membership

### 2.3 共享导航模型

- 新增平台壳层专用的导航选择模型，避免在 macOS / tvOS 壳层里继续散落魔法字符串和分叉状态。
- 静态入口（本地、服务器、历史、收藏、设置）与动态入口（具体服务器）共用一套 `Hashable` 选择值，便于后续把内容列与详情列拆成更细的 feature view。

### 2.4 VLC 包装层起点

- 新增 `VLCPlayerWrapper` 接口骨架，统一“平台原生承载视图类型”的概念：
  - `iOS / tvOS` 对应 `UIView`
  - `macOS` 对应 `NSView`
- 本轮先定义接口、配置和占位视图，不在同一轮里强行迁移现有 iOS 播放器实现，避免把 PiP、亮度、手势、方向锁定等高风险逻辑一起卷入。
- 相关抽象同样收口到 `GenPlayerShell` 中，而不是继续散落在 `GenPlayer` App target 内。

### 2.5 新 target 现状

- `GenPlayer_macOS` 与 `GenPlayer_tvOS` app target 已创建，并已接入：
  - `GenPlayerCore`
  - `GenPlayerShell`
- 当前两端都采用“thin wrapper target -> shell root view”的结构：
  - `GenPlayer_macOS` 通过 `GenPlayer_macOSApp.swift -> GenPlayerMacRootView -> MainSplitView`
  - `GenPlayer_tvOS` 通过 `GenPlayer_tvOSApp.swift -> GenPlayerTVRootView -> TVMainView`
- 部署目标当前固定为：
  - `GenPlayer_macOS`: `macOS 12.0`
  - `GenPlayer_tvOS`: `tvOS 16.0`
- 两个 target 现阶段都以“能编译、能启动壳层”为第一目标，尚未把现有 iOS 业务页与播放器完整迁入。

## 3. 平台设计约束

### 3.1 macOS

- 优先遵循桌面原生信息架构，而不是把 iPad 双栏布局直接平移到 macOS。
- `NavigationSplitView` 是当前推荐基线：
  - 侧边栏负责“信息架构”
  - 内容列负责“当前容器”
  - 详情列负责“媒体详情 / 播放占位 / 下一步动作”
- 主导航支持三档可持久化显示模式：
  - `完整`：默认模式，保留约 `240pt` 宽度及现有“图标 + 横向文字”布局。
  - `紧凑`：宽度约 `120pt`，主入口采用“图标在上、文字在下”的纵向排列，为主内容区留出更多空间。
  - `收起`：完全隐藏侧栏；内容区左上角必须保留恢复侧栏的入口。
  - 任一模式下，当前选中、悬停、下载任务角标、隐私空间锁定和正在播放入口必须继续可用；不得因切换布局而退化为没有可访问名称的交互。
- 多窗口播放暂不在本轮实现；先保证单窗口导航壳层与播放器接口抽象稳定。
- macOS 横向媒体卡片行统一使用共享组件 `MacHorizontalShelf`（`GenPlayerCore/Sources/GenPlayerShell/MacHorizontalShelf.swift`）：悬停时在行两端浮现 `‹ ›` 翻页箭头，点按翻动约 90% 视口；行不足一屏或在端点时隐藏对应箭头。箭头垂直中心对齐卡片海报区（接入点传入 `artworkHeight`，演员等自带内边距的卡片再传 `artworkTopInset`），不按含标题/元信息的整行居中。触控板双指横滑与页面纵向滚动语义不变，不劫持滚轮。适用范围为媒体卡片行（首页分区、媒体库预览分区、历史/收藏分组卡带、详情页演员/相似行、VOD 演员行）；季/源标签、分类筛选芯片、面包屑等短行不接入。

### 3.2 tvOS

- 优先保证“可聚焦、可远距离阅读、可快速进入内容”。
- tvOS 不延续 iOS 底部 TabBar 语义；以 `TabView` 顶层分类 + 网格卡片为基线。
- 不在本轮把 iOS 的手势、sheet、悬浮播放器、复杂 context menu 直接迁移到 tvOS。
- tvOS 二级页 / 详情页必须显式承接 Siri Remote 的 `Menu/Back` 返回语义：优先在应用内 pop 到上一级，而不是直接把退出命令交给系统桌面；根级 tab 页继续保留系统默认退出行为。
- tvOS 浏览壳层保持“内容优先”的轻文案基线：
  - 常规页面头部与 shelf 尽量只保留标题，不默认铺满解释型 subtitle。
  - 文件 / 媒体卡片与详情页避免长期展示整条 URL、绝对路径和过长文件名；视频 / 音频 / 图片默认优先显示去扩展名后的展示名。
- tvOS 播放器的 Siri Remote 唤出语义保持轻量：
  - 播放中控制层隐藏时，`Up / Select / Down` 只负责唤出播放控制，不直接打开完整 `Playback Options` 大抽屉。
  - 控制层右侧 `Audio / Subtitles / Speed / Display` 使用系统 `Menu` 承载快速选择，让焦点和菜单样式跟随 tvOS 原生呈现；`Playlist` 进入结构化播放列表抽屉，完整大抽屉统一从 `More` 入口进入。
  - 完整大抽屉保留 tab 结构，但 tab 切换应有清晰过渡动画，避免电视端看起来像整块内容瞬间替换。
  - 第二字幕开启后，Jellyfin / Emby 可导出的字幕流和外挂文本字幕应保持可选；VLC 已扫描到但当前 tvOS 侧无法抽取的本地内嵌字幕轨也应在第二字幕列表中可见并置灰，不应误显示为没有字幕轨道。
- `GenPlayer_tvOS` target 必须维护有效的 `App Icon & Top Shelf Image` brandassets，确保模拟器、系统桌面与 Top Shelf 不出现空白图标。

#### 3.2.1 tvOS 与 iOS 功能映射

- 本地文件：
  - tv 端当前不再保留独立 `Local` 根 tab；避免在 Apple TV 上制造“可以手动添加本地文件”的错误预期。
  - 下载中心管理的离线文件统一从 `My -> Downloads` 进入，并继续支持播放与记录管理；不在 tv 端继续复刻 iOS 的本地导入、编辑、移动、批量操作入口。
- 服务器：
  - 已保存服务器在 tv 端保留独立 shelf，继续复用 `AppNetworkService.shared.savedServers` 作为唯一顺序来源。
  - `Network` 根页即使在“无服务器”状态下，也应继续保留 `Add Server / Discovered Servers / Sync Now` 这类可直接操作入口，避免 Apple TV 端只能等待 iOS 预配置后再使用。
  - tv 端现已支持基础服务器管理：新增、编辑、删除、局域网发现，以及连接测试；其中 Jellyfin / Emby / Plex 的编辑 / 测试 / 删除 / 隐私标记应收口在 `Network` 页服务器卡片的同级管理路径里，不再作为进入媒体库后的默认首页内容。
  - tv 端现已把媒体库服务器入口收口为“直达内容”语义：Jellyfin / Emby / Plex 从服务器卡片进入后直接显示媒体库海报墙 / 媒体卡浏览，不再先落到带 `Browse` / `Settings` 维护动作的独立首页壳层。
  - 若媒体库根层返回多个顶级分类，tv 端根页应优先采用 Apple TV 式 section shelf：纵向按分类分区，横向直接陈列该分类下的海报预览，并保留进入该分类的入口；不要把这些分类退回成文件系统风格的文件夹卡首页。
  - Jellyfin / Emby / Plex 的电视剧详情页应优先在当前详情页内完成“选季 -> 看当前季剧集”的浏览，不再要求用户先进单独的季页面才能看到集列表；海报列表卡片不再用 `Browse` 角标标记可下钻项，优先显示年份、评级、评分、季/集数量等真实媒体元信息。
  - SMB / WebDAV / FTP / SFTP / NFS 这类文件型服务器，tv 端应从服务器卡片直接进入根目录文件浏览页，以文件夹 / 文件网格或按类型分组为主体；编辑、测试连接、删除、隐私标记等维护动作收口在服务器列表的 context menu 或同级管理路径，不作为进入后的默认首屏。文件浏览页中，视频 / 音频应可从卡片直接进入播放，图片应可进入电视端沉浸式预览，而不是只能停留在文件详情占位页。
  - tv 端文件预览以平台可稳定承载的类型为边界：图片进入沉浸式预览，文本 / 字幕读取后以电视端文本视图展示；PDF / doc / docx / ppt / xls / iWork 等 iOS 依赖 PDFKit 或 QuickLook 的文档在 tvOS 上显示不可预览提示，并保留下载入口。
  - Jellyfin / Emby / Plex 这类媒体库服务器，tv 端当前仍不强拷 iOS 的复杂详情页与触屏交互，但入口与浏览语义必须尽量对齐 iOS 的“内容优先”模式，优先展示海报墙、结构化元信息和清晰的媒体层级，而不是文件系统式卡片。
  - tv 端添加 / 编辑 Plex 服务器时支持从 Apple TV 直接发起官方 PIN 授权：页面优先显示二维码，并保留 `plex.tv/link` + 短验证码作为兜底；用户在手机或电脑完成授权后，Apple TV 轮询获取 token 并自动回填访问令牌字段。
  - Plex 授权得到的 token 继续保存到 `ServerConfig.accessToken`，由 `AppNetworkService` 按敏感数据规则写入本机 Keychain；服务器列表 / iCloud 快照仍不明文同步 token。手动粘贴 `Access Token` 继续作为兼容路径保留。
- 历史：
  - tv 端继续复用共享 `HistoryService`，并按“本地 -> 已保存服务器顺序 -> 遗留未匹配远程项”的分组规则展示。
  - 继续观看入口在 `My` 首页与历史详情页两处同时可达，保证大屏快速回到最近内容。
- 收藏：
  - tv 端继续复用共享 `FavoriteService`，分组顺序与历史一致。
  - 文件型条目仍以“进入文件夹 / 回到上级浏览器”为主；媒体库型条目先展示条目概览与所属服务器，不伪装成已完成的原生详情页。
- 下载：
  - tv 端继续复用共享 `DownloadCenterService`，展示 `active / completed / failed` 三类 job group。
  - 支持在 job 级别执行 `pause / resume / cancel` 等基础动作，并提供离线文件入口。
- 设置与维护：
  - tv 端设置页以“状态概览 + 维护动作”为主，优先承接清空历史、清空收藏、清理下载内容、清空服务器等可复用能力。
  - tv 端设置页已接入可被当前播放器会话实际消费的播放默认项：默认视频解码器、默认视频 / 音频倍速、画质切换 Beta、默认字幕 / 音频延迟，并继续复用与 iOS 一致的 `UserDefaults` key。
  - tv 端设置页已补齐适合 Apple TV 的存储与安全入口：已下载内容占用、下载中心跳转、清理已完成离线文件、设备存储概览，以及独立 `Security Settings` 二级入口。
  - tv 端安全能力采用密码-only 语义：应用锁与隐私空间都支持简单 4 位 PIN 和复杂密码；不暴露 Face ID / Touch ID 等生物认证入口。
  - tv 端隐私空间复用共享隐私标记模型，服务器和远程文件夹可加入隐私空间；未解锁时可隐藏锁定项、拦截受保护内容访问，并可选择让隐私内容不写入历史记录。
  - tv 端拥有独立首次引导：首次启动时介绍 `Network / My / Settings`、Siri Remote 返回语义与内容优先浏览路径；完成状态继续使用 `onboardingCompletedVersion` 记录，设置页提供“重新查看引导”入口，方便二次学习。
  - tv 端设置页已补齐关于 / 版本 / 开源许可入口：根页可直接看到当前版本摘要，关于页展示版本、版权、官网、隐私政策、版本记录与主要开源依赖许可，不依赖 iOS 的 Safari / 邮件 / 分享能力。
  - 生物认证、邮件反馈 / 分享、App Icon、触屏手势、截图保存到照片、低电量 / 通知规则、iOS 第二字幕 Beta 等 tvOS 当前没有对应消费路径或不适合电视端的能力，不作为 tvOS 设置页 parity 目标；后续只有在播放层或 tvOS 平台能力真实接入后才暴露开关。
  - 不在本轮迁移 iOS 的触屏表单、邮件分享、应用图标和生物认证等平台不合适的设置细项。

### 3.3 共享服务

- 平台壳层新代码优先直接依赖 `GenPlayerCore` 中可复用的模型与服务协议，而不是继续扩大 App 层对 `AppNetworkService.shared` 的硬编码范围。
- 旧 iOS 页面暂不在本轮大规模重写；迁移遵循“新代码先协议化，旧代码逐步替换”的顺序。

## 4. 暂不在本轮完成的内容

- 把现有 `JellyfinLibraryView`、`EmbyLibraryView`、`PlexLibraryView` 原样迁到 tvOS（当前已完成内容优先的基础海报墙浏览入口，但尚未完整迁入 iOS 端的大型详情页与触屏交互）
- 真实 VLC 播放器包装层与遥控器播放控制
- Jellyfin / Emby 的完整登录流
- CloudKit 多端同步正式开关
- macOS 多窗口播放
- tvOS 完整播放器遥控器手势、焦点和播放中 HUD 细化

> 原因：当前 tv 端已经适合先把“浏览、历史、收藏、下载、维护”这些共享数据驱动能力接通，并把媒体库入口先收口到内容优先的海报墙浏览；而完整媒体库详情页、登录流和播放器仍然强依赖 iOS App 层中的大型服务与 UIKit 逻辑，需要继续往 `GenPlayerCore / GenPlayerShell` 下沉后再接入。

## 5. 后续建议顺序

1. 把服务器列表、历史、收藏等“纯数据驱动”页面先迁到共享视图模型，并优先接入 macOS / tvOS 新 target。
2. 继续把 Jellyfin / Emby / Plex 的媒体库服务能力下沉到 `GenPlayerCore`，让 tvOS 能拿到真正的媒体库浏览数据，而不是只停留在服务器概览。
3. 为播放器建立平台分层：
   - 共享播放状态
   - 平台渲染视图适配
   - 平台手势 / 遥控 / 菜单层
4. 最后再把 PiP、方向控制、亮度、状态栏、系统手势这些 iOS 专属能力拆成条件编译模块。

## 6. 回归关注点

- iOS 根启动链路仍必须保持 `Splash -> Onboarding -> MainTabView`
- tvOS 首次引导与设置页重放入口必须可达，并且不改变根层 `Network / My / Settings` 退出语义
- iOS 现有 `AppDelegate` 打开文件与界面刷新逻辑不能回归
- 新增用户可见文案必须同步全部语言资源
- 任何平台壳层文案调整都要在 `docs/tasks/dev-log/YYYY-MM.md` 中简要记录最终结果与验证结论（月份索引：`docs/tasks/daily_dev_log.md`）

## 7. macOS 端特殊适配

### 7.1 macOS 文件管理与操作
- macOS 的本地和远程文件浏览器（SMB/WebDAV 等）已重构，统一采用 `macLocalToolbar` 和 `macServerToolbar`，保持了与 iOS 端高度一致的外观和功能（网格/列表切换、排序菜单、新建文件夹、刷新等）。
- 文件网格 (`MacFileGridItemCard`) 和列表 (`MacFileListItem`) 支持一致的图标、样式、悬停高亮动画及完整的右键上下文菜单。
- 已全面实现了针对本地和远程服务端的新建文件夹、重命名、删除操作，并通过 `FileManager.default` 和 `AppNetworkService` 提供底层支持，确保这些跨平台行为的统一性。
