# macOS mpv 播放内核

## 2026-10-01 原生 ASS/SSA 第二字幕

- 已挂载到 mpv 的独立 ASS/SSA 第二轨交给 libass 原生绘制，保持 `secondary-sub-ass-override=no`，保留脚本字体、样式、绘图、卡拉 OK 和动画。固定 mpv 0.41.0 的 ASS 适配器只在 iOS/macOS 原生第二轨启用，读取实际绘制边界，并通过 mpv 的 BGRA 字幕层整体平移/缩放；主轨、普通文字及 tvOS 未启用该变换。
- 调整激活时恢复原有整行宽度，高度和纵向位置跟随原生内容边界；有内容时不叠加“第二字幕”占位提示。空白时段保留上一位置的整行透明命中区域，拖动期间仍可调整；悬停/点击激活、位置记忆、延迟和原有手势限制保持。iOS 区分整个输出视口与视频区域，并保留横竖屏独立位置。
- 恢复第二字幕独立大小入口，正常档尊重脚本字号，其他档位缩放整套第二字幕图形，不改变主字幕。放大后的清晰度、复杂动画边界与画布裁切仍需片源验收；同轨双字幕沿用纯文字镜像，第二份镜像不保留特效。普通文字、翻译和生成字幕继续使用原显示层。
- 原生 ASS 已进入视频像素，截图与 PiP 不重复叠加文字副本；全文浏览/搜索保持独立，不改轨或启动生成/翻译。源读取失败时仅提供已观察对白并标明部分内容。

- macOS 从 mpv 切回 VLC 时清理旧画面绑定，待新 VLC 视图挂入窗口并完成有效尺寸布局后再播放；延迟回调核对视图和播放会话，退出或再次切片不启动旧媒体。进度、暂停与主/第二选轨继续通过原会话恢复流程交接；真实切换仍待 App 验证。
- 本轮只启用 iOS/macOS ASS 原生显示，tvOS 保留原路径。纯构建与模型检查不代表效果验收；字体/动画、拖动、主次互换、延迟、PiP 及截图待按 AGENTS.md 3.8 获批操作或用户验证。

状态：mpv 已作为默认播放内核；未保存过内核选择的用户使用 mpv，已有明确保存的选择继续生效。播放器实播、设备兼容与分发条件仍需按发布要求验收。

- 设置 → 高级增加 macOS 播放内核选项，默认 mpv；后续已将共用引擎扩展到 iOS/tvOS，平台入口和边界分别见 [iOS mpv 内核](22-iOS-mpv试用内核.zh-Hans.md) 与 [tvOS mpv 内核](23-tvOS-mpv试用内核.zh-Hans.md)。
- 覆盖本地及 HTTP(S) 视频/音频、HTTP(S)/RTSP/RTP/UDP 直播，以及 SMB/FTP/FTPS/SFTP/NFS 文件播放，复用窗口、控制栏、播放列表、续播、历史、服务端进度与原生失败提示。未覆盖协议、显式 VLC 帧桥请求及视频虚拟机渲染继续走 VLC。失败不自动循环切换内核，用户可回设置选择 VLC 后重新打开。

## 使用方法

1. macOS 设置 → 高级设置 → 播放内核选择 mpv，重新打开视频或音频。默认设置对新播放生效；当前点播可在播放器的视频或音频设置中切换，见下文 2026-09-29 更新。
2. 播放器的视频设置显示实际内核。选择音轨、主字幕；开启原有第二字幕 Beta 后，可选择第二轨并在字幕设置调位置与延迟。
3. mpv 下可使用截图、实况文本、字幕浏览、画中画与字幕智能。文字第二字幕可在画面内拖动并调字号；图片第二字幕保留位置/延迟设置，不提供独立字号。字幕智能沿用既有来源、音轨、模型与系统版本限制；不会因切换内核自动开始生成或下载模型。

## 实现边界

- 同一条文字字幕可同时作为主/第二字幕：主字幕保留 mpv 渲染，第二字幕独立读取时间轴并复用应用显示层；全文不可读时回退已解码片段，尚未解码的未来字幕无法提前显示。同一图片字幕不能同时占用两路，其冲突选项置灰；不同图片轨道仍可分别选择。选轨结果按引擎实际返回确认，旧请求不能回写新选择。
- 画中画片尾重播或自动下一集时先恢复所属播放器窗口，再关闭旧画中画；直接关闭播放器仍结束播放，不重新唤出窗口。
- 采用 MPVKit 1.0.0 的 libmpv 接口，渲染参考其 macOS Metal 示例：gpu-next → Vulkan/MoltenVK → CAMetalLayer。HDR 色彩提示在初始化时设置；界面诊断中的传递函数和硬解状态不等同于显示器已正确输出 HDR。
- 加载和导入字幕采用异步命令，状态在后台串行队列读取；关闭与切片使旧结果失效。普通文字第二字幕由 mpv 解码并按其延迟取当前文字，关闭原生副字幕绘制后使用既有 SwiftUI 显示层；独立 ASS 第二轨、主字幕和图片第二字幕使用原生渲染。
- 本轮不提供三条及更多字幕，Jellyfin/Emby 按当前媒体版本核对轨道，补挂服务端外挂文字字幕；版本明确时也补挂播放流缺失的可提取文字字幕。内嵌映射须核对数量、顺序和元数据，含糊版本不猜配。主/音轨沿用已有服务端名称偏好；补充 mpv 独立的逐影片音轨/主字幕/第二字幕选择，按轨道名称、语言、编码与外部来源摘要匹配，不把 mpv 编号写入 VLC 字段。匹配缺失或存在歧义时不猜配；手动导入的外部字幕需在下次播放时仍可用，本轮不增加外部文件的长期授权书签。
- 原生渲染实际耗电、掉帧、HDR/SDR 色彩、ASS/图片字幕重叠、网络中断恢复、播放结束切集和窗口关闭时的资源释放都需要实测。上游 Metal 示例提示 HDR 与 Metal API Validation 的兼容问题；本轮未修改项目调试诊断设置。
- mpv 默认值调整本身不代表已完成发布验收。MPVKit 普通预编译包为 LGPL-3.0，静态链接及随包组件的正式分发条件需要在发布前单独确认；“非 GPL 发行品”不代表免除许可证义务。

### 本轮补齐的实现与边界

- 截图请求使用独立异步命令编号，最多四个待完成请求；超时仅回调一次，保留临时路径直到命令回复或内核销毁后清理。关闭/切片核对播放代次，旧帧不会被保存为新影片截图或弹出新影片的实况文本。主动截图和实况文本不捕获桌面；IPTV 另沿用频道自动缩略图能力。
- mpv 轨道偏好独立命名空间、按影片隔离；键与外部来源使用摘要，不持久化鉴权 URL/密码/token。不跨内核复用轨道编号；外部字幕晚到时延后匹配，手动改轨或关闭字幕撤销待匹配。内容 URL 的影片查询参数保留在摘要身份中，已知鉴权参数不参与身份。
- 外部字幕先加载、后按最新请求选择；再次手动选轨后，旧导入不得强制选回。关闭主字幕时仍可独立选择第二字幕。
- 浏览读取独立于主播放连接，本地元数据核对数量/编码/语言/标题顺序，不读取 VLC 的当前轨道编号；远程 MKV 在 mpv 提供源轨道号时逐一核对。保留已有读取上限与部分索引提示，不下载整片；切片/关闭使旧读取结果失效。
- 验证：112 项 mpv 路由/时长/偏好/映射/读取/逐句字幕/PNG 检查、84 项字幕浏览/远程读取检查、两套八语言一致性检查通过。macOS Debug 纯构建与成品依赖检查通过。未执行 App、截图或录屏操作；这些测试不证明真实截图、字幕显示、网络和 HDR 已通过。
- 最小手工回归：① 同一 MKV 切音轨/主/第二字幕、关闭主字幕、重开恢复；② 主/第二字幕浏览搜索并点击回看，暂停状态与延迟正确，图片字幕提示明确；③ 主动截图/实况文本、连续导入字幕后手动换轨、快速切片/关闭；④ 回 VLC 检查字幕/PiP，以及 mpv 同片源 HDR/SDR、窗口与全屏。Agent 操作前继续遵守 AGENTS 3.8。

### 画中画、字幕智能与远程协议补齐

- 画中画复用现有 macOS 原生 PiP bridge，把同一 Metal 视图从稳定宿主移入画中画。原播放器窗口仅隐藏，返回原窗口时不重建解码器；播放、暂停、seek 与关闭按所属会话处理。生成字幕、译文与文字第二字幕提供画中画显示层。桥接依赖项目既有私有 PIP.framework，本轮未另行解决其正式分发风险。
- 字幕智能绑定既有本地/媒体服务器/范围读取来源。VLC 提取器与 mpv 播放编号按原始音轨序号核对，数量/序号不一致时不猜配默认音轨；手动选择主/第二字幕各自释放生成位置，旧异步结果随播放代次失效。远程 MKV 翻译沿用有界索引读取，结果可能不完整，字幕浏览明确显示部分来源；不因翻译整片下载。
- 音频无需视频 Surface 即可初始化；HTTP(S) 直播从当前位置打开，不恢复历史起点。RTSP（含 RTSPS）、RTP、UDP 也走 mpv，固定依赖中的对应 demuxer/protocol 已核对；直播协议不应用续播起点。不可 seek 来源不开放跳转；支持哪些实际服务器和直播格式仍以实测为准。
- SMB/FTP/FTPS/SFTP/NFS 主媒体通过 libmpv 的只读 `stream_cb` 接入现有独立读取器。单次预读最多 1 MiB，支持跨块/回退 seek、EOF 与短读校验；关闭时先唤醒阻塞读取，再销毁 mpv，等待最多 30 秒兜底。未改浏览/下载连接，也未启用 GPL Samba。远程外挂字幕独立准备，旧任务不能回填，临时文件在内核退出后清理。
- 截图以 mpv 当前窗口画面为底图，包含原生字幕与黑边，再合成生成/文字第二字幕；实况文本复用该结果。实际截图与 HDR 色彩仍未验证，不能据纯构建宣称导出的 HDR 保真。
- 最小实机回归：① 同一 MKV 首次播放、缩放/全屏、暂停 seek、文字第二字幕字号/空白拖动；② 画中画播放/暂停、返回、关闭、多窗口对应关系；③ 生成主/第二字幕、翻译、手动切换其中一处、切片取消与缓存重开；④ 本地音频、HTTP 直播和现有 NAS 文件的播放/seek/断网/退出，以及回 VLC。按 AGENTS 3.8 获批后执行，不默认截图或录屏。

## 2026-09-27 翻译、截图与周边功能修补

- 主字幕翻译保留能读取全文的路径；独立读取失败或为空时，改用 mpv 当前所选主轨的 `sub-text/sub-start/sub-end` 逐句翻译。字幕时间采用未加延迟的源时间，沿用主/第二字幕延迟；按会话和轨道清空，重复轮询不重复字幕，seek 保留稳定 ID，缓存最多 2000 句。此回退不会启动 ASR、选别的字幕轨或下载整片，可能等待当前句出现及翻译完成；浏览器明确标为部分结果。
- 截图和实况文本改用 `screenshot-raw window rgba` 读取完整渲染帧，在下一条 libmpv 事件前复制像素，由 ImageIO 写 PNG；原生字幕随帧导出，再沿既有坐标合成生成/第二字幕。失败显示本地化提示；实际保存失败不再报告成功，切片/关闭丢弃失效查看请求。合成像素测试核对 PNG 尺寸、RGBA 通道及带填充的行间距，未执行真实屏幕捕获；HDR 映射仍待实测。
- 服务端读取按媒体版本 ID 选择，缺失或含糊时不取第一版；服务端 Index 与 mpv sid 分开，内嵌字幕核对数量、语言、编码与顺序后映射。播放加载完成后补挂服务端外挂文字字幕，版本明确时补挂播放流遗漏的可提取文字轨，使用 auto 标志不抢当前选择。保留 VLC 原查询分支。
- 媒体信息读取 mpv 的艺术家/专辑标签；本地音频封面异步读取并随播放代次取消。IPTV 播放后从 mpv 取帧生成最长边 480 像素的频道预览，保存成功才通知刷新；快速切频道丢弃旧结果。系统媒体播放/暂停命令改为控制当前内核。

## 2026-09-27 初始化退出修复

## 2026-09-27 Metal 尺寸断言与左上角小画面

- MKV 截图中的 `renderTargetHeight 1204 > attachment height 1156` 指向输出尺寸竞争：UI 修改活动 `drawableSize` 时，旧交换链还可能在绘制。因此使用普通 AppKit backing layer 承载独立 Metal 子图层，只在启动前设置初始纹理尺寸，后续由渲染线程更新。
- 后续左上角小画面暴露出另一环：MPVKit 1.0.0 的 `moltenvk` context 只在视频 reconfig 时更新尺寸，窗口 control 一律返回 `VO_NOTIMPL`。交换链虽然变大，gpu-next 的视频/字幕目标矩形仍是旧尺寸，仅修改 Swift 布局不能补齐该事件链。
- 初版新增 macOS 依赖的 `GenPlayerMPVBridge`：提供同名静态 context 符号，替代原 archive 中的 context 对象；使用固定 mpv 0.41.0 私有头文件及 MPVKit 自带 libplacebo 头文件。Swift 布局发布目标像素尺寸并唤醒 VO，VO 在线程内调用 `ra_vk_ctx_resize` 更新交换链及 `dwidth/dheight`，发送 resize/expose 事件使 gpu-next 重算视频/字幕区域并在暂停时重绘。退出时在同一锁下解绑 VO 指针。
- 保留 Metal 校验、HDR 配置、视频比例、播放会话及 VLC 回退；后续 UIKit 接入复用此适配并重新核对 iOS/tvOS 的 arm64 字段偏移。此适配依赖私有 ABI，已核对 arm64 原二进制字段偏移并加入编译期断言；升级 MPVKit 必须同步复核，不能独立升级包。来源与许可见 `GenPlayerCore/Sources/GenPlayerMPVBridge/README.md`。
- `scripts/check_mac_mpv_resize.sh <macOS Build/Products/Debug>` 直接测试适配事件处理：首次尺寸、Retina、缩小、全屏尺寸、连续布局合并、失败重试、无效尺寸、无帧唤醒及解绑。GPU/VO 使用替身，测试不创建窗口、不读媒体；该检查不证明真实 Metal 时序或全屏交互通过。成品检查额外核对修复适配已链接，避免只验证编译成功。
- 验证：macOS arm64 Debug/Release 纯构建及成品链接检查通过；25 个 mpv 私有头文件与 v0.41.0 原文逐一比对一致，尺寸事件检查和原有 18 项路由/时长检查通过。未运行播放器。
- 最小实测：同一 MKV 首次播放/自动适配窗口、连续放大缩小、进入/退出全屏、暂停后缩放再继续、跨不同缩放倍率屏幕、主/第二字幕位置、关闭重开及回 VLC。仍需用户复测，或按 AGENTS 3.8 获批后操作 App；尚未验证真实播放、HDR 或 GPU 断言是否完全消除。
