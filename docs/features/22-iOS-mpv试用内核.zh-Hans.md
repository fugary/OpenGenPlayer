# iOS mpv 播放内核

## 2026-10-01 原生 ASS/SSA 第二字幕

- 已挂载到 mpv 的独立 ASS/SSA 第二轨交给 libass 原生绘制，保持 `secondary-sub-ass-override=no`，保留脚本字体、样式、绘图、卡拉 OK 和动画。固定 mpv 0.41.0 的 ASS 适配器只在 iOS/macOS 原生第二轨启用，读取实际绘制边界，并通过 mpv 的 BGRA 字幕层整体平移/缩放；主轨、普通文字及 tvOS 未启用该变换。
- 调整激活时恢复原有整行宽度，高度和纵向位置跟随原生内容边界；有内容时不叠加“第二字幕”占位提示。空白时段保留上一位置的整行透明命中区域，拖动期间仍可调整；悬停/点击激活、位置记忆、延迟和原有手势限制保持。iOS 区分整个输出视口与视频区域，并保留横竖屏独立位置。
- 第二字幕独立大小同时覆盖 iOS 15 浮层和 iOS 16+ 原生菜单，正常档尊重脚本字号，其他档位缩放整套第二字幕图形，不改变主字幕。放大后的清晰度、复杂动画边界与画布裁切仍需片源验收；同轨双字幕沿用纯文字镜像，第二份镜像不保留特效。普通文字、翻译和生成字幕继续使用原显示层。
- 主/第二字幕菜单优先使用已匹配的服务端显示名称；没有名称时过滤请求地址、查询参数与凭据，通用 Stream 文件名回退为字幕编号。轨道身份及实际认证 URL 不变。
- ASS 显示不触发全文/索引读取；打开字幕浏览时独立加载原来源，失败回退已观察对白并标为部分内容。读取核对当前播放尝试及选轨，保持取消与旧结果失效语义。原生 ASS 已进入视频像素，截图与 PiP 不重复叠加文字副本。
- VLC/mpv 切换保留第二字幕来源、位置与大小偏好；VLC 仍使用文字层，不能保留第二字幕的 ASS 特效。统一 macOS 普通第二字幕的延迟/浏览时间映射；读取回填核对当前会话，切核清理原生边界，iOS 清除旧内核的外挂轨道编号映射，防止新内嵌轨被误判。
- 本轮只启用 iOS/macOS ASS 原生显示，tvOS 保留原路径。纯构建与模型检查不代表效果验收；字体/动画、拖动、主次互换、延迟、PiP 及截图待按 AGENTS.md 3.8 获批操作或用户验证。

2026-09-27：已接入首版可选后端；当时默认 VLC。后续已将 mpv 调整为默认内核。该版本不是三端功能完全对齐，也尚未通过真机播放验收。

## 入口与范围

设置 → 高级设置 → 播放内核 → mpv，对下一次打开的音视频生效。播放器的媒体信息 → 通用显示实际使用的 mpv 或 VLC。

| 场景 | 当前路径 |
| --- | --- |
| 本地音视频、HTTP(S) 音视频、HTTP(S)/RTSP/RTP/UDP 直播 | MPVKit 1.0.0 LGPL 产品 |
| iOS 模拟器 | mpv 软件渲染预览；最长边 1280 像素、软件解码最多 4 线程，保留相同的媒体路由范围 |
| SMB、FTP/FTPS、SFTP、NFS 音视频 | 独立只读连接接入 mpv stream_cb；支持读取、定位与取消 |
| 音频入口 | 可选 mpv，保留原浮窗链路，见 [音频对齐](24-iOS-tvOS-mpv音频对齐.zh-Hans.md) |
| 画中画 | SDR/PQ/HLG 使用 mpv 连续帧与公开 AVKit，HDR 在 CPU 映射至 SDR，包含应用文字/生成/翻译字幕；实际呈现待验收 |
| tvOS | 已独立接入可选音视频内核，见 [tvOS 范围](23-tvOS-mpv试用内核.zh-Hans.md)；未完成设备验收 |

播放中可从“更多 → 播放内核”切换当前点播视频，重建播放器并恢复当前进度与暂停状态；会短暂重新加载，不是无缝切换。选择仅对当前影片生效，不修改高级设置的默认内核。准备中、失败状态、画中画、不可 seek 或无时长的来源及首版不支持的协议禁用切换；同一片源的内嵌音轨、主字幕及普通第二字幕按容器顺序与轨道数量核对后恢复，关闭状态单独传递，外挂按来源 URL 恢复；数量不一致时不猜配。原生菜单和旧系统浮层提供同一入口。

暂停切回 VLC 使用媒体级 `:start-paused`，不再通过固定延迟暂停新播放器；内部重试保留暂停意图，后台延后准备的显式“播放”则解除暂停。该选项由 [VLC 输入循环](https://github.com/videolan/vlc/blob/3.0.x/src/input/input.c) 在开始输出前处理。切到 mpv 时，明确关闭主字幕会同时取消旧查询、轨道序号、mpv 偏好和外挂字幕的待选恢复，避免首次加载重新开启；加载后仍可手动选字幕。

播放失败由现有播放器原生 Alert 呈现，可直接选择“使用 VLC 播放”，沿用当前影片、最后进度和暂停意图，不依赖成功加载后的时长/可 seek 状态；保留原重试/关闭，不自动循环切换引擎。

初始化失败与媒体播放失败分别提示，不再把所有 MPV 错误归因为服务器/网络故障。控制台 `[MPV] failure` 仅记录阶段、选项名和错误码/固定错误描述，不记录播放地址、请求头或选项值。

模拟器改用 MPVKit 已编入的 `vo=libmpv` / `MPV_RENDER_API_TYPE_SW`，绕过此前报错的 MoltenVK 路径，不再因为模拟器身份切换为 VLC。独立渲染队列轮询更新，64 字节对齐的像素缓冲最长边 1280；主线程只接收有界的最新画面。退出先释放 render context，再销毁 mpv。截图读取软件渲染结果，再叠加应用字幕；设置页说明预览限制。iOS/tvOS simulator 视频启用；音频直接输出、不经过软件画面，真机与 macOS 视频保留 GPU 路径。

这是模拟器功能调试路径，不能用于验收 HDR、真机画质或性能，4K/高码率软件解码仍可能卡顿。此前截图中的 371662848 字节 Vulkan 分配超过 268435456 字节限制，且 `vo` 线程停在 `_xpc_api_misuse`；绕开该路径不等于修复 MPVKit/MoltenVK 本身，二者完整因果链仍未由调用栈证实。软件渲染实际播放尚待获批验证。

## 已接入代码

- 复用 macOS 的串行 libmpv 引擎与像素尺寸适配，真机 UIKit 持有同一 Metal 画面层，模拟器持有同一软件显示层；旋转、缩放和视图重新挂载不会重新创建播放会话。
- 主播放、暂停、seek、速度、静音、比例、硬软解选择、历史与远程进度接入原控制层。暂停重建从暂停状态启动；退出、重试和切片丢弃旧回调。失去前台时停用视频输出，后台暂停策略仍由原设置控制，回前台不自动解除用户暂停。
- iOS 普通文字主字幕使用 VLC 的视频相对字号，并按内置思源黑体的实际字体度量换算到 libass；禁止进入黑边，保留 ASS 原排版及图片字幕自身坐标。两内核共用一次字体注册，重复打开不因“已注册”而切换字体；macOS/tvOS 调用路径不变。字形与位置仍需相同片源/时刻的 VLC 对照验证。
- 原生音轨与主字幕由 MPV 选择；文字第二字幕、翻译、生成与浏览沿用既有独立时间轴/应用显示层及系统版本限制。内嵌字幕按数量、顺序和元数据核对，不把 MPV 的编号当成服务器流编号；生成字幕的 VLC 提取轨道也须通过原音轨顺序映射。不能读取的来源保持不可用，不假装具备全文。
- 用户选择以独立的语义轨道偏好保存，MPV 数字轨道 ID 不写入 VLC 历史字段。MPV 音轨/主字幕偏好支持逐影片保存与同剧、同本地目录、具有明确服务器路径的文件目录继承；逐影片选择优先。继承按语义签名核对，外挂字幕不跨影片继承，普通 HTTP 播放端点不猜成目录，离线媒体库电影也不按下载目录混用偏好。各内核持久化偏好仍独立，跨内核传递仅用于当前片源重建。
- 截图与实况文本异步读取 MPV 原始帧，叠加应用字幕；切片、退出后的结果丢弃并清理临时文件。拖动 seek 的首张预览异步读取 MPV 当前帧，并核对手势会话及目标时间；目标时间缩略图仍沿用独立的原有预览生成路径，不连续 seek 主播放器。
- iOS/tvOS 加入与 macOS 同样的依赖链接优先级；固定 mpv 0.41.0 的 Metal 私有 ABI，核对三端 arm64 原始 context 的字段偏移。更新 MPVKit 必须重新检查成品导入表和适配 ABI。
- MPVKit 的 iOS 真机/模拟器构建没有 Lua 选项；共用初始化仅在“关闭脚本功能”且返回 `MPV_ERROR_OPTION_NOT_FOUND` 时允许跳过。macOS 仍显式禁用内置脚本，其他配置错误继续终止初始化，防止忽略必需的渲染或网络配置。

## 远程 MKV 主字幕读取

当原有本地/服务端/外挂路径无法提供主字幕时，iOS mpv 增加独立的 HTTP(S)、SMB、FTP/FTPS、SFTP、NFS MKV 范围读取，用于字幕浏览和主字幕翻译。只在打开浏览或启用翻译后读取，不因普通播放时钟更新访问网络。要求来源可识别为 MKV、支持范围请求，并能核对 mpv 原始容器轨道编号及顺序；排除外挂，无法核对时拒绝猜配。沿用已有文件读取器的认证及响应校验，Jellyfin/Emby/Plex 优先保留原服务端字幕路径。

- 共用既有 Matroska 解析器，支持 UTF8/ASS/SSA/WebVTT 文字，图片、压缩/加密轨保持明确不可读；不改变原播放器音轨、字幕选择或连接。
- 每次解析最多读取 64 MiB、16384 次数据请求；读取前后核对文件版本，支持取消，不自动下载整片。不支持范围请求或超限时保留播放并报告读取失败。
- 当前播放尝试最多缓存四份字幕文档，按轨道、原始编号及文件版本隔离；浏览与翻译复用已完成的文档。切片/停止释放当前缓存，换轨、取消及切换内核后的旧读取不回填。
- 按字幕索引提取的结果可能不完整，浏览标为索引覆盖部分，译文浏览也保留部分内容标记。全文读取失败或没有可读字幕来源时，使用当前 mpv 轨道已解码的文字兜底；第二字幕可从原生解码文字起步，完整或索引读取作为补充，见下节。

最小设备回归：iPhone/iPad 使用带两条文字字幕的 HTTP MKV，选主字幕后浏览、搜索、点击回看并启用翻译；读取中换轨/切片/关闭，核对无旧结果；抽查图片字幕、不支持范围请求和读取失败重试。保留本地/媒体服务器、生成字幕、暂停 seek、跨内核切换与 PiP 行为。实际网络及系统翻译验收待按 AGENTS.md 3.8 获批后执行。

## 普通文字第二字幕与 NAS 外挂

iOS mpv 第二字幕菜单补充内核可解码的文字轨，不再只限可范围读取的 HTTP MKV。保留容器返回顺序；本地/服务端/外挂已映射的轨道不重复添加。SubRip、ASS/SSA、WebVTT、mov_text/tx3g 等文字可选。2026-09-30 起，可识别的图片轨接入 mpv 原生第二槽渲染，未知格式仍禁用；图片不进入文字提取。全文读取仍要求原始容器编号和顺序可核对；直接解码只使用当前内核的实际轨道 ID，不把缺少全文映射当成无法显示。

- 普通文字选轨后先启用隐藏的 mpv 第二解码槽，将文字和源时间戳交给既有应用字幕层，继续提供字号、延迟、位置拖动、空白时段命中、截图叠加与浏览。后台尝试既有全文/索引读取；完整文档成功后停止第二槽，部分索引保留解码补充，不因读取失败中断主播放。2026-10-01 起 ASS/SSA 改用原生显示，见下节。
- 主次字幕统一串行选轨，先释放冲突槽再选择，并核对实际返回值。同轨时镜像主轨已解码文字；主次交换、关闭主字幕、生成主字幕及快速 A→B→A 均使旧选轨回调失效。不会把另一语言的主字幕当成第二字幕。
- 第二字幕延迟沿用旧 iOS 的“播放时间 + 主延迟 + 第二延迟”，向 mpv 传相反符号的展示延迟；转码时间加上原片偏移。字幕观察按当前播放尝试与选轨隔离，每轨最多 2000 条/4 MiB。只观察到的对白或部分索引在浏览中明确标注，未播放内容不是全文；同轨镜像也不能提前显示尚未观察到的未来对白。
- 选轨、关闭、关闭 Beta、切片、失败和停止撤销旧读取。mpv 专属第二轨选择独立保存，不把菜单编号写入 VLC；跨内核恢复核对容器数量/顺序、外挂来源或服务端描述身份，缺失时不猜配。VLC 临时会话无法承载的选择仍可在返回 mpv 后恢复；用户手动选轨会取消旧意图。
- SMB/FTP/FTPS/SFTP/NFS 外挂先用独立连接读取到临时文件，单个上限 8 MiB，再由 mpv 挂载；1 MiB 分块、取消/会话校验、来源 URL 映射和临时文件清理由会话管理。文件/HTTP(S) 外挂保留原路径。NAS 外挂的全文浏览仍受原读取器能力限制，不能读取时按已解码文字降级。

API 语义参考 [mpv 字幕属性说明](https://mpv.io/manual/stable/)；当前固定 iOS 成品已静态核对包含 `secondary-sub-text/start/end/delay/visibility`。实际解码、网络兼容性及显示同步仍需设备验证。

## 已解码主字幕兜底

无法读取完整文字字幕时，iOS 可使用 mpv 当前主字幕的已解码文字进行浏览、搜索、回看与逐句翻译。普通播放只记录内存中的有效文字与原始时间戳，打开浏览不会开启翻译、生成、切换字幕轨或额外 seek。原有本地/服务端/外挂全文路径优先，读取失败后才降级；取消、换片以及图片字幕错误不触发兜底。

- 只包含播放过程中已观察到的内容，不是影片全文；原文浏览使用八语言专用提示，译文浏览保留部分内容标记。seek 跳过的对白和未解码内容不会被补造。
- 每个当前轨道最多保留 2000 条、4 MiB UTF-8 文本；重复暂停帧不增加行，向前 seek 后原行身份保持稳定。使用源时间戳，字幕延迟仍由既有浏览/显示层应用。
- 全文读取中的浏览 revision 保持稳定，新增对白不会高频取消网络请求；降级后仅按新句子更新内存文档，同一失败来源不随时钟反复重读。切换字幕会清除旧观察内容与失败标记；重新关闭/开启翻译会重新尝试全文来源。
- 追加对白保留系统翻译会话和手动原文语言，切换至可读全文后停止逐句更新。换轨、关闭主字幕、切片和退出使旧读取及译文失效，后台暂停处理、生成字幕和音轨翻译仍沿用原路径。

仍需获批设备验证：HTTP 不支持范围读取时主字幕继续播放，浏览标为部分内容，翻译从实际已出现的对白开始；暂停/seek、追加对白、换轨/切片、后台恢复，以及普通完整字幕、生成字幕和图片字幕不回归。本轮纯模型检查不启动系统 TranslationSession，也不代表翻译质量或实机性能验收。

## 普通文字字幕的字号与列表顺序

字号标准采用项目现有 VLC 行为，不将不同内核的数字直接等同：

- VLCKit `setTextRendererFontSize` 对应 `freetype-rel-fontsize` 的除数；iPad 使用 22，iPhone 沿用现有 17–20 的设备档位。VLC 的普通文字 EM 字号约为视频短边 / 除数，横向影片即画面高度 / 除数，屏幕黑边不计入。
- mpv 的 `sub-font-size` 以 720 高度为参考，libass 按字体 ascent + descent 定义高度，而 VLC FreeType 使用 EM。换算为 `720 / 除数 × (WinAscent + WinDescent) / unitsPerEm`；竖向片源另乘 `视频宽 / 视频高`，尺寸变化时同步。
- 当前内置 Source Han Sans SC 的字体度量为 `(1160 + 320) / 1000 = 1.48`，从字体表读取，非写死视觉倍率。iPad 的 mpv 参数因此约为 48.44；旧值 32 漏掉字体单位换算，也没有明确统一字体。以显示高度 580 的横向画面为例，两内核目标 EM 字号均约 26.36；具体汉字墨迹高度、描边与栅格化仍有差异，不能据此宣称像素一致。
- ASS 自带排版、图片字幕、应用绘制的第二字幕/翻译/生成层有各自规则，本次不强制套用普通文字公式。模拟器预览缩小和 Retina 比例不再另乘字号。

实现依据：[VLCKit 字号映射补丁](https://github.com/videolan/vlckit/blob/3.0/libvlc/patches/0008-libvlc-add-a-basic-API-to-change-freetype-s-color-bo.patch)、[VLC FreeType 字号与竖向片源处理](https://github.com/videolan/vlc/blob/3.0.x/modules/text_renderer/freetype/platform_fonts.c)、[mpv 720 参考高度](https://github.com/mpv-player/mpv/blob/v0.41.0/sub/ass_mp.c)、[libass 字体度量](https://github.com/libass/libass/blob/0.17.4/libass/ass_font.c)。

列表顺序与自动选择是两件事，本次不修改排序：

- 主字幕：关闭 → 内核返回的轨道顺序；外挂随发现/挂载加入，生成主字幕在末尾。没有按中文、简繁体、名称或 Forced 优先重新排序，选中项只打勾。
- 第二字幕：关闭 → 可用的翻译/生成入口 → 本地容器、服务端、外挂候选，按来源原顺序去重；不是对主字幕列表直接按语言排序。
- 自动选择使用两种内核共用的应用规则：显式选轨、历史恢复、关闭状态及生成主字幕优先；开启语言偏好后按原顺序选择首个匹配项，只有一个候选时沿用单轨兜底。支持跟随应用的中、英、日、韩、法、德、西班牙语。关闭自动选择或多轨均不匹配时保留内核默认行为，因此该场景及内核元数据差异仍可能产生不同选择。旧系统自定义浮层向上展开时会反转行显示，原生菜单保持数据顺序。
- mpv 的名称/序号偏好恢复与 VLC 保持名称优先、序号兜底；加载后的轨道列表更新会重试未命中的偏好，成功后清除待恢复项。用户手动切换音轨/主字幕会撤销旧查询与序号，避免晚到外挂或轨道列表覆盖新选择。菜单延后选择校验播放尝试，不能作用于切片后的新会话；异步外挂及手动选择仍待设备验收。
- 底层容器轨道顺序还用于服务端/提取映射，不能为了菜单中文优先而直接排序底层数组。若增加语言分组，应只调整展示顺序并保留稳定轨道身份。

## 验证与剩余验收

最终纯构建、模型/读取检查、本地化和差异检查结果见当月开发日志。它们不能证明实际播放、字体观感、网络兼容性、系统翻译、色彩、性能或许可合规。macOS 私有画中画与依赖分发许可问题未由本次改动解决。

按 AGENTS.md 3.8 获批后，最小 iPhone/iPad 回归应覆盖以下四组；本轮没有启动或操作 App/模拟器，也没有主动截图或录屏：

1. **来源与失败**：本地/HTTP MKV、一个 SMB 和一个 FTP/SFTP/NFS 视频，各开播、暂停 seek、关闭重开；加载 NAS 外挂，断网后重试/切 VLC、切片，检查旧请求不回填、不残留声音。HTTP/RTSP 直播核对实际内核和原控制限制。
2. **双字幕与读取**：两条文字轨 A/B、主次同轨及互换、关闭主/第二轨、延迟和空白处拖动；无范围读取及 MP4 文字轨继续显示已解码字幕，浏览明确部分内容。核对截图、实况文本、读取中换轨/切片/关闭 Beta，无旧语言出现。
3. **重建连续性**：暂停后 VLC↔mpv、切解码器、进入/退出 PiP，核对进度、画面比例/缩放、主/第二字幕及关闭状态；外挂晚到、轨道数量变化、手动改选不被旧恢复覆盖。音轨生成和翻译启用后切内核，已有结果和显示位置保留，不重启识别。
4. **原行为与性能**：后台播放开/关、加载中切后台、回前台保持暂停、手势/进度条预览、旋转/分屏与暂停恢复；同片同设备对比 VLC 字号、HDR/SDR、CPU/内存/耗电及长时间播放。模拟器只做功能预览，不作为真机性能结论。

## 2026-09-30 独立 mpv 目标预览

- iOS SDR mpv 预览通过独立 libmpv 软件输出会话生成目标位置帧，长边限制 480 像素；禁用音轨、字幕与脚本。主播放的时间、暂停和音轨不变。服务器图片与现有缓存继续优先。
- 复用主播放的 VOD/115 请求头配置；NAS 每次请求创建独立只读流，不借用主播放连接。目标时间使用同一总时长及播放时间偏移。
- 取消/新请求使旧帧、错误及超时失效；请求结束停止解码并释放输出。6 秒未完成或明确失败退回时间文字。PQ/HLG 通过高精度 CPU 色调映射输出；未知色彩不输出误标帧，mpv 预览不再启动 VLC。
- 26 项预览/元数据接口检查验证回退、重复/迟到回调、取消与重入；iOS 纯构建通过。未打开影片或启动 App，目标帧准确性、方向/色彩、认证、NAS 请求量和连续拖动资源开销待设备验证。

## 音频标签与封面独立读取（2026-10-01）

mpv 音频使用原生标签及独立有界文件读取（含 MKA 附件封面），覆盖标题、艺术家、专辑、专辑艺术家、作者、作曲者和内嵌封面；支持的远程原始文件复用独立范围连接。AVFoundation 超过两秒时启动独立读取；文件完整读取后确实没有标签或封面，不额外启动 VLC。读取失败、不完整、格式不支持或图片无法解码时保留已有标签与封面，不创建 VLC 解析器。快速切片、重开和取消使旧结果失效；真实设备的显示、锁屏及 NAS 认证仍待验收。
