# 模块 07：文档预览与外部打开

## 1. 目标

- 为 `PDF / DOC / DOCX / PPT / PPTX / XLS / XLSX` 等常用文件提供统一预览入口。
- 对系统无法稳定预览、项目暂不内建渲染能力的文件，提供明确的“在其他 App 中打开”路径。
- 保持本地文件、远程文件、收藏、个人页入口的一致行为，避免每个页面各写一套文件类型判断。
- 优先复用系统原生能力，控制 iOS 14 兼容成本、二进制体积与维护复杂度。

## 2. 当前现状

### 2.1 已有能力

- `FilesListView`、`RemoteFileListView`、`FavoritesListView`、`ProfileView` 已统一存在 `openFile -> preview sheet` 链路。
- 现有预览分流大致为：
  - 视频：`PlayerView`
  - 音频：`AudioPlayerView`
  - 图片：`ImagePreviewView`
  - 纯文本：`TextPreviewView`
  - 其他类型：`UnsupportedPreviewView`
- 本地分享已接入 `UIActivityViewController`，可复用为“导出 / 在其他 App 中打开”的基础设施。
- 远程文件已有下载到临时文件再预览的基础能力：`RemoteFilePreviewLoader`。

### 2.2 当前缺口

- `VideoFile.FileType.documentExtensions` 目前仅覆盖 `pdf / doc / docx / rtf` 与文本类扩展名，`ppt/pptx/xls/xlsx` 尚未进入统一文档语义。
- `UnsupportedPreviewView` 只有静态提示，没有继续操作入口。
- 本地与远程的“不可预览文件”没有统一的外部打开策略。
- 预览能力判断散落在多个页面，后续继续加类型时容易漂移。

## 3. 设计结论

### 3.1 预览分层

统一把文件打开能力分为 5 类：

1. `playback`
   - 视频、音频
2. `image`
   - 图片、相册式左右滑动预览
3. `text`
   - `txt / log / md / json / xml / csv / yaml / strings / nfo / lrc` 等纯文本
4. `quickLook`
   - `pdf / doc / docx / ppt / pptx / xls / xlsx / rtf`，以及后续可纳入的 `pages / numbers / key`
5. `openElsewhere`
   - 归档、二进制、未知格式，以及项目暂不保证质量的类型

建议新增统一能力路由，而不是继续在各页面写 `if file.type == ...`：

- 新增 `FilePreviewCapability`
- 新增 `FilePreviewRouter`
- 由路由统一返回：
  - 如何打开
  - 是否需要先下载远程临时副本
  - 预览页标题与按钮文案

## 4. 推荐支持矩阵

| 文件类别 | 典型扩展名 | 默认行为 | 是否需要三方库 |
|---|---|---|---|
| 视频 | `mp4/mkv/mov/...` | `PlayerView` | 否 |
| 音频 | `mp3/flac/m4a/...` | `AudioPlayerView` | 否 |
| 图片 | `jpg/png/heic/gif/...` | `ImagePreviewView` | 否 |
| 纯文本 | `txt/md/json/xml/csv/log/...` | `TextPreviewView` | 否 |
| 常用文档 | `pdf/doc/docx/ppt/pptx/xls/xlsx/rtf` | `QuickLook` | 否 |
| Apple iWork | `pages/numbers/key` | `QuickLook` | 否 |
| 压缩包/二进制/未知 | `zip/rar/7z/iso/psd/ai/...` | 外部打开 | 否 |

说明：

- `QuickLook` 足够覆盖“看一下内容”的场景，但不保证复杂 Office 文档的 100% 高保真。
- 带宏的 Office 文件、复杂动画 PPT、大表格、多工作表公式或受密码保护文件，允许直接回落到“在其他 App 中打开”。

## 5. UI 交互设计

### 5.1 本地文件

- 点击文件时统一走 `FilePreviewRouter`。
- `quickLook` 类型进入新的 `DocumentPreviewView`。
- `openElsewhere` 类型不再只显示“不支持的文件类型”，改为动作页：
  - 标题：`Preview Not Available`
  - 主按钮：`Open in Another App`
  - 次按钮：`Share`
  - 辅助文案：说明“GenPlayer 暂不内建该格式预览”

### 5.2 远程文件

- 对 `image / text / quickLook`，继续保持“点击后自动下载到临时目录，再按本地文件路由处理”。
- 对 `openElsewhere`，不要在用户点文件时立刻开始下载：
  - 先展示“Preview Not Available / Open in Another App”提示页
  - 只有用户明确点击主按钮后，才开始下载临时副本
  - 下载完成后直接拉起系统分享/外部打开面板，不再多绕一次确认
- 远程文件点击后，仍优先做“临时副本预览/打开”，不强制用户先执行“保存到本地”。
- 若用户在下载过程中关闭预览页，当前下载任务应立即取消，避免大文件继续在后台无感下载。

### 5.3 收藏 / 个人页 / 历史

- 收藏与个人页复用同一套路由，不再各自硬编码“图片/文本/其他”三分支。
- 历史页仍以媒体播放为主；若后续历史中出现文档型条目，也应走同一套 `FilePreviewRouter`。

## 6. 技术方案

### 6.1 模型层

建议扩展 [FileModel.swift](./GenPlayer/Source/Models/FileModel.swift)：

- 扩充 `documentExtensions`
  - 增加 `ppt / pptx / xls / xlsx / pages / numbers / key`
- 新增更细粒度的能力枚举，而不是只靠 `FileType.document`
  - 例如 `previewCapability`
  - 或 `preferredPreviewRoute`

建议不要把 `ppt/xls` 拆成新的 `FileType`，继续保留 `.document`，把“怎么打开”放到能力层解决。

### 6.2 共享路由层

建议新增：

- [FilePreviewRouter.swift](./GenPlayer/Source/Views/FilePreviewRouter.swift)
- [DocumentPreviewView.swift](./GenPlayer/Source/Views/DocumentPreviewView.swift)

职责建议：

- `FilePreviewRouter`
  - 根据扩展名、本地/远程、服务器能力返回目标打开方式
- `DocumentPreviewView`
  - 包装 `QLPreviewController`
  - 提供顶部关闭按钮
  - 提供右上角 `Open in Another App` / `Share`

### 6.3 Quick Look 方案

基线直接使用系统 `QuickLook`：

- iOS 14 可用
- 对 `PDF / Office / iWork` 这类“查看型”需求足够
- 系统维护格式解析，不需要项目自己维护 Office 渲染逻辑

SwiftUI 接入方式建议：

- `UIViewControllerRepresentable` 包装 `QLPreviewController`
- 单文件模式即可，不必一次性做多文件翻页
- 预览容器仍复用现有 `PreviewSheetContainer` 的导航结构

### 6.4 外部打开方案

优先复用项目已有的 `UIActivityViewController`：

- 已在 [FilesListView.swift](./GenPlayer/Source/Views/FilesListView.swift) 中接入
- 可直接导出到 Files、AirDrop、其他支持该类型的 App
- 对用户来说已经足够接近“Open In...”

结论：

- 第一版不必额外引入 `UIDocumentInteractionController`
- 若后续用户明确希望出现更强的“Open in...”应用选择器，再评估是否追加该控制器

### 6.5 远程临时文件

建议把远程临时预览能力再收口一层：

- `RemoteFilePreviewLoader` 下载后，不直接写死 `image/text`
- 改为把临时 URL 回传给统一路由
- 临时文件目录建议按 `PreviewCache/<serverId>/...` 组织，便于后续清理

清理策略建议：

- App 冷启动时清理过期临时预览文件
- 单文件关闭预览时不立即删，避免分享面板或其他 App 打开过程中目标文件被提前移除

## 7. 交互文案建议

新增文案建议接入 `en / zh-Hans`，其他语种可先回退英文值：

- `Open in Another App`
- `Preview Not Available`
- `This file type isn't supported for in-app preview yet.`
- `Download Temporary Copy`
- `Open After Download`
- `Previewing Secure Documents May Be Limited`

对用户可见的结论要清晰：

- 不是“打不开”
- 而是“GenPlayer 不内建预览，但你可以继续交给其他 App”

## 8. 是否需要开源库

### 8.1 当前结论

当前阶段不建议为了文档预览引入新的开源库。

原因：

- 项目核心是媒体中心，不是 Office 编辑器
- 系统 `QuickLook` 已覆盖最核心的查看诉求
- 开源 Office 渲染库在 iOS 上很难同时满足：轻量、稳定、兼容 iOS 14、支持 `docx/xlsx/pptx` 高保真
- 引入 Web 渲染、LibreOffice 转换链或大型 SDK，会显著提高体积、维护和兼容风险

### 8.2 何时再评估第三方

只有在以下诉求明确出现时，再评估第三方或商业 SDK：

- 需要比系统更高保真的 PDF 标注/搜索/多页缩略图能力
- 需要 Office 文档编辑而不只是预览
- 需要复杂 PPT 动画、复杂 Excel 图表的更强还原
- 需要离线转换成图片/PDF 做自定义预览

如果未来必须增强：

- `PDF` 可单独评估 `PDFKit`
- `Office` 优先评估“继续外部打开”或服务端转换方案
- 不建议现在就引入重型第三方作为默认路径

## 9. 建议实施顺序

1. 扩展文档扩展名与统一 `FilePreviewRouter`
2. 实现 `DocumentPreviewView(QuickLook)`
3. 把本地文件页接入统一路由
4. 把远程文件下载后预览接入统一路由
5. 把收藏 / 个人页改为复用统一路由
6. 将 `UnsupportedPreviewView` 升级为“可继续操作”的动作页
7. 补齐国际化文案与回归测试

## 10. 最小回归清单

- 本地 `pdf/docx/pptx/xlsx` 可进入预览
- 本地 `zip/rar/7z/psd` 不再只显示死提示，能点击“在其他 App 中打开”
- 远程 `pdf/docx/pptx/xlsx` 可下载临时副本后预览
- 远程未知格式会先提示“在其他 App 中打开”，用户确认后才下载临时副本并拉起分享面板
- 关闭远程预览页时，进行中的临时下载会取消，不继续后台下载大文件
- 分享 / 外部打开不会误删临时文件
- `Files / Remote / Favorites / Profile` 四个入口行为一致
- iOS 14 下构建通过，且没有直接依赖 iOS 15 才可用的 SwiftUI API

## 11. 文件图标与外部打开视觉建议

- 常见办公文件不要只靠一个通用 `doc` 图标区分，建议统一使用“文件卡片 + 扩展名徽标”语义：
  - `PDF` 使用红色卡片
  - `DOC / DOCX / PAGE / RTF` 使用蓝色卡片
  - `XLS / XLSX / CSV / NUM` 使用绿色卡片
  - `PPT / PPTX / KEY` 使用橙色卡片
- `ZIP / RAR / 7Z / PSD / AI / TTF` 等未内建预览的文件，也可复用同一套卡片样式，只替换徽标文字与色彩，避免列表里全是“普通系统图标”。
- “在其他 App 中打开”页建议不要只有一颗普通分享图标：
  - 顶部主图继续显示当前文件卡片
  - 右下角叠加明显的外部打开动作标识
  - 主按钮使用动作卡片样式，直接说明“将交给 Word / Excel / 文件等其他 App 继续处理”
- 这样可以同时解决两个问题：
  - 用户在列表里一眼区分文件类型
  - 用户进入“不支持预览”页后，也能立刻理解下一步动作不是“失败”，而是“转交其他 App”
