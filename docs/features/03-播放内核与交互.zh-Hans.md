# 模块 03：播放内核与交互（VLC/手势/播放器 UI）

## 1. 当前功能概览

- 基于 `VLCPlaybackService` 统一管理播放状态、控制动作与播放器生命周期。
- 视频播放页包含顶部/侧边/底部控制条，支持进度条、清晰控制反馈与锁定状态。
- 支持音频悬浮迷你控件（主 Tab 内显示），可快速暂停/继续/关闭。
- 支持播放列表联动（上一集/下一集）与信息面板。

### iOS 慢加载与失败提示（2026-09-10）

- 正常 loading 保留既有视觉：视频使用随内容宽度布局的 13pt 小胶囊（水平 16pt、垂直 10pt 内边距），音频保留原来的纵向指示器；慢加载仅替换文案。只有达到等待操作阈值才展示操作面板。
- 已起播后，VLC 瞬时 buffering/opening 通知不直接显示 loading；用同一套实际时钟、显示帧、音频输出采样确认连续 1.5 秒无进展，再进入缓冲。定时器直接采样播放器，避免时间回调延迟导致误报；首次加载、暂停语义及既有外观保持。
- 主动 seek 使用独立的 0.3 秒等待阈值（由现有 0.5 秒轮询或播放器回调检查），超时仍未恢复才显示原紧凑 loading；目标时间跳变本身不视为恢复，后续时钟推进或音视频输出才清除等待。进度条、快进/快退共用判定，快速完成不闪现，暂停时跳转保持暂停。
- 首次加载与播放中重新缓冲均区分普通加载、加载较慢、等待用户选择；远程等待 15 秒显示慢加载提示，连续 30 秒无输入/解码进展或累计等待 60 秒提供“继续等待 / 重试 / 关闭”。本地对应为 6 / 15 / 30 秒，避免大文件索引被误判为文件损坏。
- 等待阈值不改变为失败状态，也不自动重新请求；继续等待重置观察窗口，播放恢复立即清除提示。暂停、退出与切片清除旧等待状态。
- VLC 明确错误或启动中停止经过短暂恢复宽限后仍未恢复，才显示失败；可确定的资源/准备错误及时显示。失败提示使用播放器内部的原生 `UIAlertController`，等待页面可见、转场结束及已有模态页面关闭后呈现；同一失败只呈现一次。
- 重试与切片使用独立尝试标识，旧准备任务和旧播放器回调不得覆盖当前尝试；保留音视频入口、续播、字幕及 PiP 既有语义。本次仅限 iOS，不调整 macOS / tvOS。

### macOS 原生播放失败弹窗（2026-09-11）

- 视频与音频播放器改用 AppKit `NSAlert`，作为错误所属播放器窗口的原生 sheet，系统负责布局、按钮、键盘操作及外观；保留“重试 / 关闭”动作。
- 窗口尚未可见、未获焦点、正在切换全屏或已附着其他 sheet 时等待；窗口就绪后呈现同一失败一次，恢复/重试/切片/退出清除旧提示及其动作。
- 正常 loading、播放控制及 macOS 既有加载时间判定保持原样；本次不将 iOS 的慢加载策略迁移到 macOS，不调整 tvOS。

### mpv 点播缓存与进度显示（2026-10-01）

- 范围：iOS/macOS/tvOS 的 mpv 主播放远程点播，含音视频；VLC、本地文件、直播及独立预览/辅助解码会话不改变缓存策略，不扩展 HDR 设置。
- 主播放通过 `Configuration.readAheadCache` 显式启用。目标预读 120 秒，前向数据限额 64 MiB、回看限额 32 MiB；受码率和字节预算限制，实际秒数可能更少。这是解复用数据预算，不是播放器整体内存上限，片尾可沿用 mpv 的额度借用策略。
- 引擎在原后台串行轮询中读取 `demuxer-cache-state.seekable-ranges`，逐次替换当前快照，不以下载字节数或加载百分比估算时间。绘制时拒绝无效值、裁剪到时长、合并重叠范围并保留空缺；未知时长不显示区间。
- 三端视频及 macOS/tvOS 音频在原进度条的轨道和已播放层之间绘制缓存层；iOS 音频保留原生 Slider，在下方用细线显示覆盖范围。缓存层不参与触摸、焦点和辅助功能命中。
- macOS 远程 mpv 点播在左右时间之间显示主播放读取速率与当前位置向前连续缓存秒数，窄窗口可截断并悬停查看，极小窗口隐藏。读取速率来自 mpv `cache-speed`（近一秒输入层估计值，非影片码率，也非全设备网络测速）；NAS 自定义读取含自身缓冲，不承诺与网卡计数相同。预读 idle 显示“预读暂停”，缺失统计明确显示不可用，不将旧速率或总缓存量当作当前速度/前方连续时长。macOS 单独提高缓存段对比度，不人为扩宽短缓存区间。
- 沿用原 seek 命令和拖动确认语义，由 mpv 在可能时进行缓存内跳转，不重建播放会话；缓存外仍允许正常网络读取。iOS 沿用转码播放时间偏移；切片、切核、退出清空旧范围，旧会话回调受原尝试标识限制。
- iOS/macOS/tvOS 的 SMB、FTP/FTPS、SFTP、NFS 自定义范围读取，在同一播放尝试内由主播放与独立静音预览共用最多 8 MiB 的进程内原始媒体块缓存；预览命中已预读区块时不重复请求，主播放与预览同时 miss 同一区块时合并成一次底层读取，未命中且无并行读取时仍会独立请求。换片、重试/重建及退出释放会话缓存。现有三端抽帧图像缓存按来源和目标时间复用；macOS 新增有界内存图像缓存，服务器 trickplay/章节图仍始终优先查询。
- 首次访问某个预览时间点仍需启动独立 mpv 实例、读取/定位并解码关键帧，帧图缓存只加速之后命中缓存的重复时间点；快速拖动时尚未完成的旧目标会取消。此缓存接入不代表首次预览即时显示或每次都能复用主播放预读数据。
- 共享原始块不接管或读取 libmpv 私有磁盘/网络包缓存；标准 HTTP、媒体服务器原生 URL 等未经过 `MacMPVStream` 的来源仍由独立预览会话自行读取。缓存内跳转仍可能需要关键帧解码，不能承诺零延迟或零网络请求。缓存行为依据 [mpv 官方缓存文档](https://mpv.io/manual/stable/#cache)，实际服务端兼容和三端交互依核心手工回归清单验收。

### macOS mpv 临时磁盘缓存试用（2026-10-01）

- 展示收敛：播放器时间栏仅在实际读取且速率大于零时显示 `↓ 8.2 MB/s` 一类简短速度，空闲/未知/零速率隐藏；缓存时长、磁盘占用和具体回退原因移入原播放信息侧栏的“缓存”区域。正常画面保留真实缓存进度层，预读策略仍为 180 秒，不在本轮新增积极预读档位或分段淘汰。

- 预读空闲仍显示 `0 B/s`；内存模式显示目录、空间、选项、统计或容量阈值的具体回退原因。磁盘字节从完整缓存原生节点读取，加载后连续三次缺失才回退，低空间与容量保护不延迟；日志仅记录固定原因和选项名，不包含媒体地址或凭据。

- 仅 macOS 主播放远程点播（视频/音频）尝试启用 mpv 临时磁盘缓存，预读目标 180 秒；VLC、iOS/tvOS、本地、直播、辅助预览维持原策略。
- 应用沙盒 Caches 下独立目录，创建目录权限 0700；缓存文件由 mpv 创建后立即 unlink，活动句柄仍可读写，关闭影片/退出/崩溃后由系统释放，不作为离线下载或跨次复用文件。
- 启动实际空闲空间不少于 6 GiB 才启用；每秒读取磁盘缓存实际文件字节数和卷空闲空间。单会话累计约 4 GiB、实际空闲降到 2 GiB、或无法继续核对空间/缓存统计时，关闭新增磁盘写入并恢复 120 秒及 64/32 MiB 内存策略，本会话不重新开启磁盘缓存。已有磁盘文件直到媒体关闭才释放；阈值是软保护，含轮询/并发写入超量，不是硬磁盘配额。
- 选项不支持或目录/空间不可用时从一开始使用内存模式；运行时无法执行保护回退则使用原播放失败处理关闭引擎，避免继续不受监控写盘。保留原 seek/暂停/字幕/PiP、同片恢复与会话失效规则。
- 时间栏追加磁盘占用或内存模式状态，八语言覆盖；显示范围仍只使用真实可 seek 区间。纯构建不能证明真实 NAS 读写、长片空间增长、切片清理和缓存内跳转效果，按核心手工回归清单验收。

## 2. 关键实现位置

- 播放服务：`VLCPlaybackService`、`VLCPlaybackService+Extensions`、`VLCPlayerView`。
- 视频播放器：`PlayerView` + `Views/PlayerComponents/*`（手势、菜单、进度条、反馈层）。
- 音频播放器：`AudioPlayerView` + `MainTabView` 中浮动播放器。
- 字幕与轨道相关模型：`SubtitleModel` 等。

## 3. 开发实现步骤（建议模板）

1. **先补服务层能力**：在 `VLCPlaybackService` 定义状态字段与控制方法。
2. **再补 UI 组件**：把新增控件拆分到 `PlayerComponents`，避免 `PlayerView` 过大。
3. **添加交互反馈**：关键动作（倍速、快进、轨道切换）统一走反馈组件。
4. **处理前后台与系统事件**：确保锁屏、切后台、恢复时状态一致。
5. **回归播放链路**：本地视频、远程视频、音频、字幕导入、列表切换都要覆盖。

## 4. 近期实现补充（2026-03）

- **视频播放器补充 `Fit / Fill` 屏幕适配模式（2026-04）**
  - 视频播放器右侧原“画面比例”入口继续保留，但菜单语义升级为“显示”：拆分为 `屏幕适配` 与 `画面比例` 两组，避免把“改变显示方式”和“改变画面比例”混成一组。
  - `屏幕适配` 至少包含两档：`适应屏幕`（完整显示视频，允许黑边）与 `填满屏幕`（按比例放大并裁掉边缘以铺满屏幕）；默认保持旧行为，进入新播放会话时仍从 `适应屏幕` 开始。
  - `画面比例` 继续承载 `Auto / 16:9 / 4:3 / 1:1 / 16:10 / 2.35:1` 等强制比例选项；其职责是“改变视频按什么比例渲染”，而不是“决定如何填充屏幕”。
  - 实现上要求视频实际渲染区域、字幕层、seek 预览与顶部反馈浮层共用同一套可视区域判断，避免出现视频已经 `Fill`，但字幕/预览仍按旧黑边位置摆放的分叉。
  - 在此基础上，iPhone / iPad 视频播放器补充“多指细调画面”能力：双指捏合可在当前 `Fit / Fill` 基础上继续放大画面，双指拖动仅在当前画面存在可裁切余量时才生效，用于微调裁切区域；双指双击可快速复位到当前模式的默认 framing。

- **播放器截图保存位置与首次询问**
  - `Settings -> Advanced -> Screenshots` 新增“截图保存位置”，支持 `GenPlayer 内置文件夹 / 照片` 两种保存目标，便于在“文件流管理”与“系统相册分享”之间切换。
  - 首次点击播放器截图按钮时，若用户尚未明确选择过保存位置，会先弹一次 action sheet 询问并记住选择；后续保持一键截图，不把“每次都问”变成默认干扰。
  - 保存到照片时仅申请 `Photo Library Add Only` 写入权限；若权限被拒绝或写入失败，会自动回退到 `Documents/Snapshots` 并用轻提示明确说明真实保存位置，避免截图直接丢失。

- **播放器实况文本 (Live Text) 提取与选择模式**
  - 在 iOS (16+) 与 macOS (13+) 播放器顶栏快捷操作区新增实况文本按钮（`text.viewfinder`，与 PiP 并列，避免右侧浮动栏遮挡视频内容），仅在当前设备硬件与系统版本支持 Apple VisionKit Live Text 时展示。
  - 交互边界安全隔离：普通暂停时禁止直接触发文本选择，彻底避免 QuickTime Player 等因暂停直接可选导致的控制层误唤出与手势冲突；必须点击文本提取按钮进入专属全屏选择模式。
  - 进入选择模式后，若当前正在播放会自动平滑暂停，并自动冻结当前帧预览（包含第二字幕合成与色彩校正结果），唤起全屏 `PlayerLiveTextViewer` 浮层。
  - 严格 1:1 等比呈现：自定义宿主 Image View 重置固有尺寸约束，画面与底层正在播放的视频尺寸、比例与黑边 letterbox 完全一致，绝不拉伸、放大或截断。
  - 选择层内提供系统原生划词选择、复制、翻译、快捷查询及全选操作，并通过 ESC 键或右上角关闭按钮一键退出返回播放器。

- **视频播放器长按临时加速**
  - `PlayerView` 的左/中/右手势区现在都支持“长按倍速播放”：长按约 `0.35s` 后切到临时高倍速，松手后恢复到按下前的当前倍速，不会改写会话内手动选择的常规倍速。
  - 长按手势的允许位移会刻意收紧到低于全屏拖动手势的触发阈值，优先保证亮度/音量/seek 拖动开始后能尽快取消长按加速，降低误触。
  - `Settings -> Advanced -> Gestures` 新增“长按倍速播放”设置，支持关闭与多档倍速，默认 `2x`；仅在配置值高于当前实际倍速时触发，避免当前已处于更高倍速时长按反而降速。
  - 播放器首次进入时会短暂抑制音量反馈，避免音频会话与系统音量监听初始化阶段误弹出一次音量 toast；横屏下的 toast 与 seek 预览统一贴近顶部安全区下方显示，不再额外为整块顶栏预留过大间距，减少遮挡画面主体。
  - 播放器顶栏的返回、静音、播放列表等按钮在横竖屏下共用同一套边缘视觉补偿，和底部进度条、底部控制区保持一致的左右对齐关系，避免竖屏单独显得更缩进。

- **横屏 / iPad 视频控制补齐重播与播放顺序**
  - `PlayerView` 与 `PlayerBottomBar` 在横屏或 iPad 形态下，为视频底部传输控制新增“从头播放”按钮，并固定放在现有“后退 N 秒”按钮左侧；点击后直接从 `0s` 重新拉起当前播放项，不额外弹确认框，只走轻量反馈提示，保持其作为快速传输控制的语义。
  - 同一区域新增播放顺序模式按钮，放在“前进 N 秒”右侧，按 `顺序 -> 随机 -> 单集循环` 循环切换；仅当当前视频播放列表大于 `1` 项时可用，单文件场景保持灰态，避免出现无效的随机/循环入口。
  - 视频播放列表的“下一项”逻辑会根据当前模式同步切到顺序、随机或当前项重播；锁屏 / `Now Playing` 的上一项、下一项可用态也会跟随刷新，尽量保持页内与系统远程控制语义一致。

- **锁屏/灵动岛 `Now Playing` 同步增强**
  - `VLCPlaybackService+Extensions` 在播放中按 1 秒窗口刷新 `Now Playing`，并补充 `playbackState`、真实媒体类型（audio/video）与可 seek 条件同步，减少锁屏进度条停滞或状态漂移。
  - 远程命令中心新增并统一 `togglePlayPauseCommand`，`next/previous/seek` 的回调状态改为按“是否实际执行”返回，避免系统侧显示可操作但实际无效。
  - `PlayerView` 进入/退出时会显式注册与清理视频场景的 `next/previous/seek` 回调；播放列表与当前项变化时同步上一曲/下一曲可用态，保证页内与锁屏按钮状态一致。
  - `VLCPlaybackService.togglePlayPause()` 在暂停后恢复时优先使用 `state.currentTime` 作为恢复时间，确保锁屏/灵动岛暂停状态下拖动进度后点击播放不会回跳到旧位置。
- **iPad 音频大窗高度自适应 + 小窗长标题滚动**
  - `AudioPlayerView` 的竖屏音频布局会按当前容器高度动态收紧封面、控制条字号和上下留白，优先保证 iPad sheet / 弹窗场景下底部播放主键完整可见，不再默认按“接近全屏”的固定比例布局。
  - 音频悬浮矩形小窗的超长标题改为“左右往返滚动”：只在文案实际超出可视宽度时启动，滚动区需要为右上角关闭按钮预留安全区，避免标题遮挡关闭入口。
- **主 Tab 菜单闪烁修复（播放器高频状态隔离）**
  - `MainTabView` 不再直接承接 `VLCPlaybackService` 的高频播放态刷新；音频悬浮小窗改由独立宿主视图观察播放器服务，并自己管理展开播放器与播放列表弹层。
  - 约束：悬浮播放器的进度、旋转、滚动标题等高频 UI 状态不要直接挂在主 Tab 根视图上，避免连带刷新系统菜单、导航栏或其它页面容器。
- **结束态点击播放可从头重播（音频/视频统一）**
  - `VLCPlaybackService.togglePlayPause()` 增加结束态兜底：当 VLC 落在 `ended/stopped` 且内部 media 资源不可直接恢复时，改为重建当前播放项并从 0 秒启动，避免“播完后点播放无反应”。
  - 该策略对视频播放器与音频播放器共用，减少端内两套状态机行为漂移。
- **远程媒体“已完成后重播”语义统一（Jellyfin/Emby/Plex）**
  - Jellyfin / Emby / Plex 的播放入口统一改为先通过共享 `RemotePlaybackResumeDecision` 计算续播语义：只要服务端条目标记为“已播放/已完成”，或本地详情页刚手动标记为完成，下次播放默认从 `0s` 开始，而不是继续沿用旧的 resume position。
  - 为避免出现“服务端仍显示已完成，但新的播放会话又开始写入新进度”的冲突，`VLCPlaybackService` 在重播会话第一次向服务端上报 `playing/progress` 前，会先清理远端 `played` 状态，再恢复正常进度同步。
  - 本地历史也会在进入重播时同步把断点重置到开头，避免服务端已决定“从头播放”，但播放器又被旧的本地历史断点拉回中间位置。
- **音频悬浮小窗播放态反馈与边缘吸附**
  - 悬浮小窗改为封面旋转 + 环形进度反馈，降低“暂停/播放”状态识别成本。
  - 拖拽改为 `onChanged` 实时更新位置，优先保证跟手性；松手后仅执行吸附/收纳的收尾动画，避免“松手才位移”的违和感。
  - 拖拽到屏幕边缘达到阈值后，小窗可收纳为边缘吸附图标；收纳态支持沿边缘拖动，减少遮挡主内容区域。
  - 交互层级约定：圆形收纳态点击先恢复矩形小窗，矩形小窗点击再进入音频播放页（`圆形 -> 小窗 -> 大窗`）。
- **音频悬浮小窗关闭按钮对齐修正**
  - 矩形音频小窗的关闭按钮从内容行内拆出，改为靠近右上角的浮置定位，避免按钮视觉重心偏低、与卡片边缘留白不协调。
  - 标题区为关闭按钮预留右侧空间，避免长文件名和关闭按钮相互挤压。
- **播放器关闭爆音收敛**
  - `VLCPlaybackService.stop()` 改为“先静音、短暂缓冲后再 stop”的平滑收尾路径，并增加防重入保护，降低退出播放器或关闭音频页时的瞬时爆音概率。
  - `VLCPlayerViewController` 在页面消失时不再抢先硬断 `drawable`，而是等待服务层进入空闲态后再释放渲染目标，避免 dismiss 动画期间同时发生“停播 + 断渲染”。
  - 手动暂停、退后台自动暂停，以及若干“重载后保持暂停态”的恢复路径统一改为平滑暂停，减少直接 `pause()` 带来的短促爆音。
- **视频播放器 Home Indicator 刷新补强**
  - `VLCPlayerViewController` 在进入播放页后会主动请求刷新 `Home Indicator` 与系统边缘手势延后状态，`UIApplication.refreshInterfaceChrome()` 也会递归刷新当前可见控制器链，降低 iPad 全屏视频下底部指示条长时间不收敛的问题。
- **视频 seek 预览浮层**
  - 视频播放器在“全屏左右滑动 seek”与“底部进度条拖动”两条链路上统一显示预览浮层，保持同一视觉与时间反馈语义，避免两套手势反馈分叉。
  - seek 拖动期间优先移动预览浮层与拖拇指位置，主播放器画面保持当前播放帧稳定；松手后再一次性执行真实 seek，降低远程流高频跳转造成的抖动与重缓冲。
  - Jellyfin / Emby / Plex 这类媒体库型远程视频，seek 预览优先走服务端预生成的 trickplay / BIF 缩略图，不再把 hover / 拖动预览建立在临时二次解码远程流之上；服务端未提供或请求失败时，才回退到播放器本地采样与 VLC 抓帧兜底。
  - seek 预览请求调度采用“前沿限频 + 尾沿 debounce”混合策略：拖动过程中控制远程取帧频率，但在用户停顿后必须补发最后一个目标时间的预览请求，避免尾帧缺失。
  - 若最新目标时间的缩略图尚未返回，应尽量保留上一张可用预览图作为占位缓存，并叠加轻量 loading 提示；只有在完全没有可用图片时才回退到纯 loading/时间文字反馈，兼顾“不断图”与“不过度误导”。
  - 竖屏时，seek 预览与通用反馈提示优先落在“顶部工具栏与视频画面之间的可用空带中央”；若顶部空带不足，则回退到更接近上三分之一的自然位置，避免提示长期贴着顶栏。
  - 本地文件与不支持服务端预览的来源，仍优先使用当前播放器已解码的视频帧做轻量采样；若采样失败，再回退到原有时间差文字反馈或 VLC 抓帧兜底，不能阻塞 seek 本身。
- **播放器菜单稳定性与进度条视觉升级**
  - 视频播放器进度条改为更有层次的胶囊轨道和高亮拇指，拖动反馈更清晰。
  - 菜单打开时增加“触发即标记打开、选择后主动标记关闭”的双保险，降低旧机型菜单闪烁/过快关闭。
  - 菜单打开态不再完全冻结时间刷新，改为低频保底更新；即使菜单状态回收异常，进度条也可自动恢复前进。
- **播放器菜单改为独立浮层**
  - 视频播放器与音频播放器共用的轨道/倍速/画幅/更多菜单改为自管浮层，不再把系统 `Menu` 挂在播放控制条子树内，避免控制层刷新、进度更新或滚动过程导致菜单回弹、二级菜单意外关闭。
  - 浮层菜单统一采用“背景点击关闭”的交互，打开后只受浮层自身状态控制；播放控制条继续负责触发入口，但不再承载菜单生命周期。
- **自动连播跳集修复（Jellyfin/Emby 剧集）**
  - 修复了播放结束态重复触发导致的自动连播二次前进问题，避免偶发出现 `E6 -> E8` 的跳集现象。
  - 手动“下一集”与自动连播共用播放链路，但自动连播增加了防重入保护。
- **剧集级字幕/音轨偏好记忆**
  - 新增“同剧集跨集沿用”策略：在同一 Series 内，下一集优先复用上一集使用的字幕与音轨。
  - 优先级为：URL 级历史记忆 > 剧集级偏好记忆；兼顾精确记忆与连续观看体验。

- **视频播放列表信息与来源修正（历史/个人页/Jellyfin/Emby）**
  - `PlaylistView` 行项补强为双层信息：除进度/时长外，补充容器、编码、分辨率、码率、声道/大小等技术元数据；本地文件会按需读取 `AVAsset` 与文件资源值，降低大量出现 “Unknown Duration” 的概率。
  - `PlayerView` 在未显式传入 playlist 时，本地视频会重新按“当前文件所在目录 + 同媒体类型”构建播放列表，并回填本地文件大小/修改时间；不再把音频等非目标类型混入视频播放列表。
  - 个人页历史入口不再把 `historyService.allHistory` 直接伪装成播放器 playlist；普通本地/远程文件改回按目录或季级/文件夹来源动态构建，保持与历史页、收藏页一致。
  - Jellyfin/Emby 历史重进时，远程外挂字幕候选改为“服务端最新结果优先，再合并历史候选去重”，并把刷新后的候选回写到当前播放项，降低历史入口继续观看时外挂字幕丢失或误选旧链接的概率。

- **音频播放器下滑 dismiss 与后台播放联动**
  - 音频大窗的系统 dismiss（如下滑关闭、iPad 点按 sheet 外部背景）统一视为“最小化到浮动音频小窗”，不再区分 `shouldPlayInBackground` 开关；只有显式点击左上角 `xmark` 才执行真正关闭。
  - 音频悬浮小窗在 iPhone / iPad 上都需要放宽上下拖拽边界，优先按真实安全区和当前设备形态计算保留空间，避免出现明显还能放下却无法继续拖动的情况。

- **视频画中画与后台播放降级适配 (iOS 14+)**
  - iOS 15+ 的视频画中画改为项目内自管的 `AVPictureInPictureController(sampleBufferDisplayLayer:playbackDelegate:)` 链路，不再保留第三方 PiP 桥接依赖，避免旧截图桥接方案带来的“直播”标签、黑屏或维护负担。
  - PiP 连续帧源改为 `libvlc_video_set_callbacks` 驱动的原始视频帧桥接：`VLCPlaybackService` 通过独立的 `GenPlayerVLCFrameBridge` 把 VLC 输出的 BGRA 帧直接喂给 `AVSampleBufferDisplayLayer`，不再把 `UIImage/JPEG` 截图或磁盘 snapshot 当作运行期主渲染路径。
  - 送往 sample-buffer PiP 的视频帧必须来自可跨进程序列化的 `IOSurface`/`CVPixelBufferPool` 像素缓冲；禁止继续用 `CVPixelBufferCreateWithBytes` 把普通堆内存包装成临时像素缓冲，否则系统小窗可能能拉起但只显示控制层、控制台持续刷 `FigSampleBufferSerialization` / `FigVideoQueueRemote` 错误。
  - `libvlc_video_set_callbacks` 的 `opaque` 生命周期必须独立于 Swift 层主桥接对象；即使 PiP 启动失败、控制中心打断、或 restore 回退时主桥接已 detach，视频输出线程尾部残留的 `lock/unlock/display` 回调也仍要拿到有效的 frame state，不能把 `planes[0]` 直接置空，否则 libVLC 的 `plane_CopyPixels` 可能在后台线程直接崩溃。
  - 进入 PiP 时必须先以 `libvlc_video_set_callbacks` 预挂载好的新 `VLCMediaPlayer` 重建当前播放会话，再等待第一帧原始像素抵达后才允许真正调用 `startPictureInPicture()`；禁止在“已经开播的 drawable 会话”上热切到 frame-callback 模式，否则很容易卡在 `pending=true` 但永远没有首帧。
  - PiP 启动失败时可以立刻重建回普通 drawable 播放会话；但用户点击系统“还原到 App”时，drawable 会话重建必须延后到新的 `PlayerView` 已经重新挂回可见容器之后再执行，避免在 `didStop` 当场重播导致 restore 卡死或视频输出线程崩溃。
  - PiP 活动期保留旧 `playerView` 的唯一目的，是为了在系统“恢复到应用内播放器”时把现有会话无缝接回新的全屏 `PlayerView`；禁止再依赖离屏 `UIView` 截图或轮询 VLC snapshot 维持 PiP 画面，避免再次回退到“像 PPT 一样卡顿”的伪视频桥接。
  - 小窗是“观感优先”的缩略播放，不追求全分辨率逐帧还原；连续帧桥接应优先在更小渲染尺寸上换取更高帧率，避免为 PiP 额外复制过大的视频帧导致窗口能出图但运动发涩。
  - `willResignActive` 不能再被等同于“已经进后台”：像控制中心、通知横幅、系统短暂遮罩都会触发它。无论是“非后台播放时自动 `pause()`”还是“后台态下的播放保活判断”，都必须等到 `didEnterBackground` 这类真正进后台的时机再触发，避免只是下拉控制中心就先黑一下、像卡顿一样抖动。
  - 手动点击 `pip.enter` 时，播放器 full-screen 仅能在系统 `pictureInPictureControllerDidStartPictureInPicture` 确认真正进入 PiP，或已明确退回悬浮音频面板后才允许 dismiss；禁止“先 dismiss 再赌系统 PiP 会起来”，避免出现视频仍在播但 PiP 窗口没有真正出现、用户误以为窗口消失的时序回退。
  - 系统 PiP 顶部“恢复到应用内播放器”按钮必须真正接回全局 full-screen `PlayerView` 恢复入口；不能只在 `restoreUserInterfaceForPictureInPictureStopWithCompletionHandler` 里回 `true` 却不重新呈现播放器，否则用户会看到恢复按钮存在但没有实际效果。
  - `VLCPlaybackService` 会主动拦截切后台事件：若用户开启了“允许后台播放”，则保持当前播放会话继续在后台运行，但**不会**因为切后台自动触发 PiP；PiP 仅能由播放器顶栏的 `pip.enter` 显式触发。若用户未开启后台播放，则仍按原语义在真正进入后台后暂停。
  - 对于不支持原生系统 PiP 的 iOS 14 场景，采用现有的 `AudioPlayerView` 和 `isAudioFloatingVisible` 路线作为完美降级平替。此时视频在后台/悬浮窗仅展示音频控件面板，维持极低的代码入侵性。
  - 顶部导航栏内嵌 `pip.enter` 按钮处理显式缩小触发逻辑，关闭全屏播放器时避免错误拦截停止 `stop()`，真正实现 App 内切出切入的连贯观看体验。
  - `Video Auto Rotate -> Follow Video Aspect` 必须按“当前正在播的内容方向”双向修正：横版内容进入或切换到该项时应自动转横，竖版内容进入或切换到该项时也应自动回竖；禁止只在首次进入播放器时按初始状态判断一次，导致后续播放项方向漂移。

## 5. 后续迭代建议

- 抽象播放器能力矩阵（视频/音频共性 vs 差异）。
- 统一手势配置入口（可考虑放到 `AppSettings` 的独立分组）。
- 规划播放诊断日志（首帧时间、缓冲次数、失败原因）用于质量追踪。

### iOS/macOS 网络自适应缓存（2026-10-01 修订）

- 本条替代上文 macOS 180 秒/iOS 仅内存的首版策略。两端主播放远程点播启用临时磁盘缓存；普通已连接、非计费、非低数据 Wi-Fi/有线网络设置 24 小时前向目标，前台暂停继续。实际受文件末尾、缓存元数据预算与磁盘保护限制，不保证缓存完整影片。
- 网络未知、蜂窝、系统标记计费的热点及低数据模式目标 120 秒，路径变化自动调整，不重建播放。iOS 后台播放收敛为 120 秒，后台暂停目标为 0；不承诺被系统挂起后仍能读取。网络识别依据系统路径标记，不推断所有 Wi-Fi 都免费。
- 启动至少空闲 6 GiB；累计约 4 GiB、空闲低至 2 GiB 或统计失效则单向回退 64/32 MiB 内存缓存。mpv 磁盘文件只追加、不循环复用，因此额度是整段会话累计量；轮询保护非硬配额，关闭媒体才释放旧磁盘数据。
- iOS 音视频时间行仅读取时显示简短速度。macOS 已播放改为白色，缓存灰白、底轨暗色，常态 4 pt、悬停/拖动 6 pt，保留原松手 seek/预览交互。VLC 缓存与 tvOS 策略不扩展。

### mpv HDR 信息（2026-10-01）

- 三端现有媒体信息面板仅在当前 mpv 视频报告 PQ、HLG 或 Dolby Vision 色彩矩阵时展示“色彩与 HDR”；普通 SDR、音频和 VLC 保持原信息布局。
- 只读当前播放会话，分开列出输入格式/色彩/像素格式、实际解码器、`video-target-params` 渲染目标，以及主显示层色彩空间/像素格式/EDR 请求状态。不把滤镜后的 `video-out-params` 当成最终输出。
- 渲染诊断约每秒刷新一次，不额外打开媒体或读取远程文件；当前会话退出、切片、切核时清理旧信息。显示层信息在主线程读取，tvOS 或旧系统不能读取 EDR 时显示未知。
- PQ 不直接标为 HDR10/DV，10-bit 不直接判 HDR；缺失值显示未知，线性目标不直接判 SDR。面板明确说明渲染数据不能确认电视最终 HDR/Dolby Vision 模式；不改变任何色彩或播放选项。
- macOS HDR 视频在左上角标题下增加轻量状态条，随控制层隐藏；仅 PQ/HLG 渲染目标轻微点亮小图标并显示白色“HDR”，不使用黄色底框；SDR 目标显示“HDR → SDR”，目标未知时显示低强调“HDR · 片源”。完整状态放入悬停提示和辅助功能描述。点击打开信息侧栏；HDR 详情位于封面、缓存与基本信息之后、流信息之前，不置顶遮住封面。宽窗口附带实际 HW/SW、编码、分辨率、容器标称帧率，窄窗口优先保留 HDR 状态。tvOS 仅补信息面板，不迁移桌面布局。

- iOS HDR 视频在现有顶部按钮行下方增加紧凑状态条，与标题左沿对齐并随控制层隐藏，锁定时不展示。复用同一 mpv 快照，HDR 目标亮青色太阳图标、SDR 目标显示 HDR → SDR、未知目标显示 HDR 片源；附加 HW/SW、编码、分辨率及标称帧率，窄屏优先保留 HDR 状态，点按打开原媒体信息页。音频、VLC 与 SDR 不增加该状态条，不更改播放或色彩参数。
