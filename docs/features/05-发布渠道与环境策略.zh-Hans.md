# 05 发布渠道与环境策略（测试/生产双轨 + 国内/海外差异化）

> 目标：让测试包与正式包可同时安装在同一设备，并支持根据发布区域默认启用不同商业化模式（广告/付费）。

## 1. 双应用标识方案（同机安装测试 + 生产）

### 1.1 总体原则

- 采用 **Target + Build Configuration + xcconfig** 的组合，而不是在代码里硬编码环境判断。
- 至少维护两个可发布目标：
  - `GenPlayer`（生产）
  - `GenPlayer QA`（测试/预发布）
- 两个目标必须拥有不同的：
  - `PRODUCT_BUNDLE_IDENTIFIER`
  - `PRODUCT_NAME`（建议 UI 名称包含 QA 标识）
  - App 图标（避免误点）

### 1.2 推荐命名示例

- 生产：
  - Bundle ID: `com.acme.genplayer`
  - Display Name: `Gen Player`
- 测试：
  - Bundle ID: `com.acme.genplayer.qa`
  - Display Name: `Gen Player QA`

### 1.3 配置分层（建议）

- 新增配置文件：
  - `Config/Base.xcconfig`
  - `Config/Prod.xcconfig`
  - `Config/QA.xcconfig`
- 示例变量（离线 App 推荐）：
  - `APP_ENV=prod|qa`
  - `APP_REGION_DEFAULT=cn|global`
  - `APP_MONETIZATION_DEFAULT=ads|subscription|oneTimePurchase`
  - `APP_FEATURE_FLAGS`（可选，本地功能开关）

## 2. 代码层环境注入（避免散落判断）

### 2.1 EnvironmentConfig

- 新增统一入口（示意）：
  - `EnvironmentConfig.current`
- 只允许业务代码依赖该对象，不直接读 `Bundle.main.infoDictionary`。

### 2.2 关键字段（建议）

- `appEnv`: `prod/qa`
- `distributionRegion`: `cn/global`
- `monetizationMode`: `ads/subscription/oneTimePurchase`
- `adProvider`: `none/gromore/admob/...`

## 3. 国内/海外差异化默认模式

### 3.1 判定优先级（从高到低）

1. 用户手动选择（设置页）
2. 构建默认值（Info.plist / xcconfig）
3. 首次启动兜底（Locale / Storefront）
4. （可选）远程配置：仅在未来引入服务端时启用

> 不建议仅依赖系统语言判断区域，应结合 App Store storefront 或账号地区。

### 3.2 推荐策略

- 国内版本默认：`monetizationMode = ads`
  - 对接国内平台（如穿山甲/优量汇），通过适配层封装。
- 海外版本默认：
  - 方案 A：`oneTimePurchase`
  - 方案 B：`subscription`
  - 或对接海外广告平台（AdMob/ironSource）。

### 3.3 架构约束

- 新建 `MonetizationProvider` 协议，国内/海外实现都走统一接口。
- UI 仅依赖“能力标识”（是否展示广告位、是否显示订阅入口），不依赖具体平台 SDK。
- 所有策略变更记录埋点，支持灰度观察（展示、点击、转化、退款）。

## 4. 发布与合规建议

- 中国大陆广告/隐私：
  - 必须补齐隐私政策、个性化广告同意、未成年人保护与数据最小化说明。
- 海外（GDPR/CCPA）：
  - 增加 Consent 管理（如 UMP），支持拒绝个性化广告。
- 若采用“同一个二进制多地区策略”（当前无服务端）：
  - 通过构建默认值 + 用户设置页切换实现；后续若引入服务端再增加远程配置层。
- 若采用“分包上架”：
  - 使用不同 bundle ID 和商品配置，策略清晰但维护成本更高。

## 5. 最小落地步骤（结合当前项目）

1. 创建 `GenPlayer QA` target，设置独立 bundleID 与图标。
2. 增加 `EnvironmentConfig` 与 `MonetizationProvider` 协议骨架。
3. 在设置页新增“商业化模式来源”只读诊断区（展示当前生效来源：手动/构建默认/兜底）。
4. 先接入一个国内与一个海外 provider 的 mock，实现可切换验证。
5. 若未来引入后端，再扩展“远程配置来源”并置于最高优先级。
6. 完成后在 `docs/tasks/dev-log/YYYY-MM.md` 记录最终落地结果与验证结论（月份索引：`docs/tasks/daily_dev_log.md`）。


## 6. Xcode 实操清单（同一套代码，不复制工程）

> 核心点：**代码只保留一套**，通过 target/config 注入不同参数。

### 6.1 在 Xcode 创建 QA Target

1. 选中项目 `GenPlayer.xcodeproj` -> TARGETS -> 右键 `GenPlayer` -> `Duplicate`。
2. 重命名为 `GenPlayer-QA`。
3. 在 `GenPlayer-QA` 的 `Signing & Capabilities` 中设置独立 Bundle Identifier（如 `com.acme.genplayer.qa`）。
4. 在 `General` 中设置不同 Display Name（如 `GenPlayer QA`）和 App Icon（如 `AppIcon-QA`）。

### 6.2 建立 Build Configuration 与 xcconfig

1. 在 PROJECT -> Info -> Configurations 中新增：
   - `Debug-QA`
   - `Release-QA`
2. 新建文件：
   - `Config/Base.xcconfig`
   - `Config/Prod.xcconfig`
   - `Config/QA.xcconfig`
3. 在 PROJECT -> Info -> 对每个 configuration 绑定对应 xcconfig。

示例（QA）：

```xcconfig
#include "Base.xcconfig"
APP_ENV = qa
APP_REGION_DEFAULT = cn
APP_MONETIZATION_DEFAULT = ads
APP_FEATURE_FLAGS = offline-first
```

示例（Prod）：

```xcconfig
#include "Base.xcconfig"
APP_ENV = prod
APP_REGION_DEFAULT = global
APP_MONETIZATION_DEFAULT = subscription
APP_FEATURE_FLAGS = offline-first
```

### 6.3 把 xcconfig 变量注入到 Info.plist

在目标 `Info.plist`（可共用同一个）中增加键值：

- `APP_ENV` = `$(APP_ENV)`
- `APP_REGION_DEFAULT` = `$(APP_REGION_DEFAULT)`
- `APP_MONETIZATION_DEFAULT` = `$(APP_MONETIZATION_DEFAULT)`
- `APP_FEATURE_FLAGS` = `$(APP_FEATURE_FLAGS)`（可选）

这样可保证“代码不分叉、参数分环境”。

### 6.4 代码读取方式（单一代码库）

建议新增 `EnvironmentConfig`（服务层单例）统一读取：

```swift
struct EnvironmentConfig {
    static let current = EnvironmentConfig()

    let appEnv: String
    let regionDefault: String
    let monetizationDefault: String

    init(bundle: Bundle = .main) {
        let info = bundle.infoDictionary ?? [:]
        self.appEnv = info["APP_ENV"] as? String ?? "prod"
        self.regionDefault = info["APP_REGION_DEFAULT"] as? String ?? "global"
        self.monetizationDefault = info["APP_MONETIZATION_DEFAULT"] as? String ?? "subscription"
    }
}
```

> 业务层只依赖 `EnvironmentConfig.current`，避免散落 `#if`。离线应用默认不依赖 `BASE_URL`。

### 6.5 国内/海外策略在同一套代码中的落地

- 首次启动：读取 `EnvironmentConfig.current.regionDefault` 作为初值。
- 用户在设置页手动切换后写入本地（优先级最高）。
- 未手动设置时，回落到构建默认值。
- 若未来接入服务端，可在此之上增加远程配置覆盖。
- 广告/付费具体实现通过 `MonetizationProvider` 注入：
  - `CNAdsProvider`
  - `GlobalSubscriptionProvider`

### 6.6 CI/CD 与 TestFlight 建议

- CI 产物拆分：
  - QA: `GenPlayer-QA` + `Release-QA`
  - Prod: `GenPlayer` + `Release`
- TestFlight 建议仅分发 QA target，App Store 正式包使用 Prod target。
- 两者可安装在同一设备并行验证（不同 bundle ID）。

### 6.7 回归验证清单（发布链路）

1. 同机安装 `GenPlayer` 与 `GenPlayer QA` 成功。
2. 两个包分别打印 `EnvironmentConfig`，值符合预期。
3. 在无服务端条件下，切换设置页模式后可立即生效。
4. 用户手动切换模式后，重启应用仍保持。
5. （可选）未来接入远程配置后，验证远程策略覆盖链路。


### 6.8 无服务端场景建议（当前项目适配）

- 本项目定位离线播放器，**可以完全不引入 `BASE_URL`**。
- 区域与商业化默认值使用 `xcconfig -> Info.plist -> EnvironmentConfig` 链路即可。
- 若担心后续扩展，可保留 `PolicyProvider` 抽象：
  - 当前实现 `LocalPolicyProvider`（只读本地配置 + 用户设置）
  - 未来可增加 `RemotePolicyProvider`，但不影响现有代码路径。


## 7. 结论：全手动实现 vs 需要改代码

### 7.1 可以“全手动（Xcode 配置）”完成的部分

- QA/Prod 同机安装（不同 Bundle ID、Display Name、Icon）。
- QA/Prod 使用不同构建默认值（`APP_REGION_DEFAULT`、`APP_MONETIZATION_DEFAULT`）。
- 通过不同 target 打出不同安装包（TestFlight / App Store）。

> 上述能力仅靠 Xcode Target + Build Configuration + xcconfig 即可生效，**不改业务代码也能跑**。

### 7.2 为了“产品可用”建议必须做的最小代码改动

1. 新增 `EnvironmentConfig` 统一读取入口（避免在各页面散读 Info.plist）。
2. 新增 `MonetizationProvider`（或 `PolicyProvider`）协议层，避免广告/订阅 SDK 直耦合到 UI。
3. 在设置页增加“商业化模式手动切换 + 当前生效来源展示”。
4. 持久化用户选择（本地存储），并在启动时按优先级决策：
   - 用户手动 > 构建默认 > Locale/Storefront 兜底。

### 7.3 推荐落地判断

- **如果只是临时并行安装测试**：可先走全手动，不改代码。
- **如果要正式上线国内/海外差异商业化**：建议按 7.2 做最小代码改造，否则后期维护成本高。
