# 模块 11：内嵌第二字幕（Embedded Secondary Subtitles）

## 1. 背景与目标

很多 MKV / MP4 / 远程媒体库片源会内嵌多条字幕，例如英文、简中、繁中、日文等。当前 GenPlayer 的 VLC 播放链路只能选择一条字幕轨显示，无法同时显示“英文 + 中文”这类学习场景常见的双字幕。

本设计的目标是：在不替换现有 VLC 播放内核的前提下，为 iOS 播放器补充“第二字幕”能力，优先支持容器内嵌的文字字幕轨，同时允许外挂文字字幕作为第二字幕来源，让用户可以在同一个视频中同时显示主字幕与第二字幕。

## 2. 设计原则

- **以内嵌字幕为主，外挂字幕可用**：第二字幕功能优先覆盖内嵌文字字幕，但用户手动导入或自动发现的外挂文字字幕也应能作为第二字幕候选。
- **保持现有 VLC 主字幕链路稳定**：主字幕继续由 `VLCPlaybackService` 通过 `mediaPlayer.currentVideoSubTitleIndex` 控制，不改变现有字幕自动选择、字幕延迟、外挂字幕导入与历史恢复语义。
- **第二字幕独立于 VLC 单字幕轨限制**：第二字幕由 GenPlayer 自己发现、抽取、解析、同步并在播放器 overlay 中显示。
- **先支持文字字幕**：第一阶段只承诺 SRT / WebVTT / ASS / SSA dialogue / mov_text 等文字字幕；PGS、VobSub、DVD bitmap、DVB subtitle 等图形字幕列为后续能力。
- **播放不中断**：第二字幕加载失败、抽取失败或格式不支持时，不能影响视频播放、主字幕显示、音轨切换与 seek。
- **iOS 14 兼容**：实现不能依赖 iOS 15+ Only API。

## 3. 非目标

- 第一阶段不承诺完整 libass 样式还原。ASS/SSA 先按 dialogue 文本解析，保留基础换行与可读性，不还原复杂定位、动画、字体附件、卡拉 OK、绘图命令等高级效果。
- 第一阶段不承诺 PGS / VobSub / Blu-ray bitmap 字幕作为第二字幕显示。
- 第一阶段不替换 VLC 为 mpv/libmpv，也不改变现有视频渲染、PiP、Now Playing 与远程控制链路。
- 第一阶段不把第二字幕写入视频帧。因此系统 PiP 或 sample-buffer PiP 是否能显示第二字幕，需要单独验证和后续适配。

## 4. 当前基础与限制

### 4.1 可复用基础

- `VLCPlaybackService` 已经统一管理播放状态、轨道切换、进度、字幕延迟与外部字幕候选。
- `PlayerView` 已经有 `SubtitleOverlayLayer()`，当前读取 `playbackService.currentSubtitleParts` 并叠加到视频区域上方。
- `SubtitleModel` 已有 SRT / VTT / ASS / SSA 文字解析能力，可以作为第二字幕解析器的基础。
- Jellyfin / Emby 的 `VideoFile` / `MediaItem` 已可携带 `serverMediaStreams`、`mediaSourceId`、`externalSubtitleCandidates` 等媒体流上下文。
- Jellyfin / Emby 服务层已有按 subtitle stream index 构造字幕流 URL 的经验，可扩展为“内嵌字幕导出”能力。

### 4.2 当前限制

- 现有 `PlayerState` 只有 `subtitleTracks` 和 `currentSubtitleTrackID`，对应一个主字幕轨。
- 现有 `MediaTrack` 只表达 VLC 轨道或外部字幕菜单项，没有区分主字幕轨与第二字幕轨。
- VLCKit 当前接入方式使用 `currentVideoSubTitleIndex`，表现为单字幕轨选择模型。
- 对本地 MKV / MP4 内嵌字幕，VLCKit 能列出和选择轨道，但没有给 GenPlayer 暴露“读取另一条内嵌字幕完整文本事件”的现成路径。

## 5. 总体架构

第二字幕链路拆为六层：

1. **发现**：从当前 `MediaItem` 中发现可作为第二字幕的内嵌字幕轨与外挂字幕文件。
2. **抽取**：把用户选中的内嵌字幕轨导出为文本字幕文件或直接解析为 cue timeline。
3. **解析**：复用或扩展 `SubtitleModel`，生成按时间排序的 `SubtitlePart` / cue timeline。
4. **同步**：根据 VLC 当前播放时间、seek、速率和第二字幕偏移计算当前可见字幕。
5. **显示**：由播放器 overlay 显示第二字幕，避免与主字幕重叠。
6. **持久化**：记住用户在当前媒体或同一剧集内选择的第二字幕偏好。

推荐新增一组独立组件：

```swift
public struct EmbeddedSubtitleTrack: Identifiable, Equatable, Codable {
    public let id: String
    public let source: EmbeddedSubtitleSource
    public let streamIndex: Int?
    public let codec: String?
    public let language: String?
    public let title: String?
    public let displayName: String
    public let supportLevel: EmbeddedSubtitleSupportLevel
}

public enum EmbeddedSubtitleSource: String, Codable {
    case localContainer
    case jellyfinMediaStream
    case embyMediaStream
    case cachedExtraction
}

public enum EmbeddedSubtitleSupportLevel: String, Codable {
    case textSupported
    case textBestEffort
    case bitmapUnsupported
    case unknownUnsupported
}

public struct SecondarySubtitleSelection: Codable, Equatable {
    public let trackID: String
    public let displayQuery: String?
    public let language: String?
    public let ordinal: Int?
}
```

服务层建议新增协议：

```swift
protocol EmbeddedSubtitleProvider {
    func discoverTracks(for item: MediaItem) async -> [EmbeddedSubtitleTrack]
    func loadTimeline(for track: EmbeddedSubtitleTrack, item: MediaItem) async throws -> SubtitleTimeline
    func cancel(for item: MediaItem)
}
```

其中 `SubtitleTimeline` 是解析后的只读时间轴，内部按 start/end 排序，并提供二分查找当前时间 active cues 的方法。

## 6. 字幕来源设计

### 6.1 Jellyfin / Emby 内嵌字幕导出

这是第一阶段优先级最高的实现，因为用户看到的是内嵌字幕，而 App 可以通过服务端按 stream index 导出文字字幕。

发现逻辑：

- 从 `MediaItem.serverMediaStreams` 或播放入口已获取的 media source 中读取 `Type == Subtitle` 的流。
- 不再只过滤 `isExternal == true`、`deliveryUrl` 或 `DeliveryMethod == External`。
- 对 `isExternal == false` 且 codec 属于文字字幕的 stream 也生成 `EmbeddedSubtitleTrack`。
- 对 PGS / VobSub 等图形字幕生成不可选或置灰项，避免用户以为功能坏了。
- 当前实现会把 PGS / VobSub 等不可解析图形字幕保留在第二字幕菜单中但禁用；这样用户能确认字幕轨已被发现，只是暂不能作为第二字幕 overlay 解析。

抽取逻辑：

- 优先使用服务端提供的 `DeliveryUrl`。
- 没有 `DeliveryUrl` 时，使用类似现有字幕 URL 构造方式：
  - `Videos/{itemId}/{mediaSourceId}/Subtitles/{index}/Stream.{ext}?api_key=...`
- `ext` 由 subtitle codec 映射：
  - `srt` / `subrip` -> `srt`
  - `webvtt` / `vtt` -> `vtt`
  - `ass` -> `ass`
  - `ssa` -> `ssa`
  - `mov_text` / `tx3g` -> `srt` 或服务端可导出的文本格式

缓存策略：

- 下载到 `Caches/Subtitles/Embedded/{mediaFingerprint}/{trackID}.{ext}`。
- 文件名不包含 token；token 仅用于请求。
- 缓存命中时优先复用，媒体源变化或 track codec/index 变化时失效。

### 6.2 本地文件内嵌字幕抽取

本地文件包括 Files 导入、下载中心完成文件，以及 App 可直接访问的本地 URL。

当前实现分两条本地读取路径：

- 支持可随机访问的 MP4 / MOV / M4V 本地文件中 `tx3g` / `mov_text` 这类文字字幕轨。
- 支持 MKV / WebM 中 Matroska 文本字幕轨：`S_TEXT/UTF8`、`S_TEXT/ASS`、`S_TEXT/SSA`、`S_TEXT/WEBVTT`。
- 选中第二字幕时在后台把对应文字轨导出为临时 SRT / ASS / VTT，再复用 `SubtitleModel` 解析和播放器 overlay 同步。
- 抽取结果只写入临时缓存目录，不改变原始视频文件，也不影响 VLC 主字幕轨选择。
- Matroska 路径为纯 Swift EBML 解析器，不新增 FFmpeg / mpv / libavformat 依赖；PGS / VobSub 等图形字幕仍只保留为已发现但不可作为第二字幕 overlay 解析。

后续完整实现建议：

- 继续演进 `LocalEmbeddedSubtitleExtractor`，必要时再封装 libavformat / FFmpeg 类能力补齐更多容器与边界格式。
- 只在后台队列打开媒体文件，不能阻塞播放器首帧。
- 先支持可随机访问的本地文件 URL。
- 使用 security-scoped resource 时，抽取期间必须成对调用 start/stop access。

抽取方式可分两档：

- **整轨导出**：播放开始后后台把指定 subtitle stream 抽成临时 SRT/VTT/ASS 文件，再交给解析器。实现简单，但远程或大文件可能慢。
- **时间轴索引**：直接读取 subtitle packet 并构建 `SubtitleTimeline`。体验更好，但实现复杂度更高。

MVP 建议先做整轨导出，配合加载状态；后续再优化为渐进索引。

### 6.3 SMB / WebDAV / FTP / SFTP / NFS 远程文件

远程文件直接抽取比本地复杂，因为同一个远程 URL 可能由 VLC 处理，但 App 层未必有同等可 seek 的文件句柄。

分阶段处理：

1. 若远程文件已经被正式下载，直接走本地抽取。
2. 若当前协议已有缓存副本，优先对缓存副本抽取。
3. WebDAV / HTTP 若支持 Range，可后续通过自定义读接口接入抽取器。
4. SMB / FTP / SFTP / NFS 先不承诺实时抽取，避免为了第二字幕拖慢播放启动。

### 6.4 外挂字幕

外挂字幕作为第二字幕的正式兼容来源：

- 用户手动导入或播放入口自动发现的外部字幕，可以选择为主字幕或第二字幕。
- 同一条字幕允许同时作为主字幕和第二字幕，便于对比 VLC 原生渲染与第二字幕 overlay 的显示效果；只有 PGS / VobSub 等暂不可解析的图形字幕继续置灰。
- 主字幕选择内嵌字幕时，外挂字幕应继续可作为第二字幕候选；主字幕选择外挂字幕时，内嵌字幕应继续可作为第二字幕候选。
- 第二字幕 overlay 负责解析外挂字幕并独立同步，不能要求 VLC 同时渲染两条字幕。
- 第二字幕若能映射到主字幕同一轨道或同一个外挂文件，菜单显示名应优先复用主字幕列表中的名称，避免同一条字幕在两个分区里显示成不同名字。
- 同一外部字幕若同时通过服务端 `MediaStream` 和外挂候选被发现，第二字幕候选必须按主字幕轨道 ID 或外挂文件 URL 去重，避免重复展示。
- 主字幕列表中已经由 VLC 暴露、且能反查到外挂文件 URL 的外部字幕轨，也应补入第二字幕候选，避免主字幕切换后其他外挂字幕从第二字幕列表消失。
- 内嵌字幕与外挂字幕混合时，服务端字幕流映射到 VLC 主字幕轨必须区分内嵌轨 offset 与外挂轨 URL；主字幕在内嵌 / 外挂之间切换后，第二字幕列表不应把不同字幕折叠成同一个名称，也不应因为当前主字幕变化而隐藏仍可作为第二字幕的另一条字幕。
- 第二字幕作为 Beta 功能默认关闭，设置入口放在高级设置的视频播放分组；关闭时播放器菜单与 overlay 回到原有单字幕体验，不显示“主字幕”分组标题。开启后才显示主字幕 / 第二字幕分区，第二字幕位置通过播放器画面内点击后拖动调整，不再提供独立位置预设菜单。

## 7. 支持格式边界

| 格式 | 第一阶段状态 | 说明 |
|------|--------------|------|
| SRT / SubRip | 支持 | 主要目标格式 |
| WebVTT | 支持 | 保留基础文本与换行 |
| ASS / SSA | Best Effort | 解析 dialogue，去除复杂样式与绘图命令 |
| mov_text / tx3g | 支持或导出为 SRT | 取决于抽取器和服务端导出能力 |
| PGS | 不支持 | 图形字幕，后续需 bitmap renderer 或播放内核级支持 |
| VobSub / DVD Subtitle | 不支持 | 图形字幕，后续再评估 |
| DVB / Teletext | 不支持 | 后续再评估 |

## 8. 播放器状态设计

`PlayerState` 建议新增第二字幕状态，避免污染主字幕字段：

```swift
public var secondarySubtitleTracks: [EmbeddedSubtitleTrack] = []
public var currentSecondarySubtitleTrackID: String? = nil
public var secondarySubtitleStatus: SecondarySubtitleStatus = .idle
public var secondarySubtitleParts: [SubtitlePart] = []
public var secondarySubtitleDelay: Double = 0.0
```

`VLCPlaybackService` 建议新增方法：

```swift
func refreshSecondarySubtitleTracks()
func setSecondarySubtitleTrack(_ trackID: String?)
func clearSecondarySubtitleTrack()
func setSecondarySubtitleDelay(_ seconds: Double)
```

约束：

- `setSecondarySubtitleTrack` 不能调用 `mediaPlayer.currentVideoSubTitleIndex`。
- 主字幕切换仍走现有 `setSubtitleTrack(_:)`。
- 如果用户把同一条轨同时选为主字幕和第二字幕，第二字幕菜单应禁用该轨或提示需要选择不同字幕。

## 9. 同步与渲染

### 9.1 时间同步

第二字幕显示使用 VLC 当前播放时间作为唯一时钟：

```swift
let effectiveTime = state.currentTime
    + AppSettings.shared.subtitleDelaySeconds
    + state.secondarySubtitleDelay
```

`SubtitleTimeline` 对 `effectiveTime` 做二分查找，返回当前 active cues。

触发时机：

- 播放时间刷新。
- seek 开始和 seek 完成。
- 选择第二字幕。
- 修改字幕延迟或第二字幕延迟。
- 播放列表切换下一集。

要求：

- seek 后立即刷新可见第二字幕，不能等下一次自然 tick。
- 第二字幕解析未完成时在第二字幕位置显示本地化 loading 文案，并复用第二字幕同款文字样式，不阻塞播放；缓存命中时直接显示结果。
- 后台解析任务必须在切换媒体时取消，避免旧媒体字幕回写到新播放项。

### 9.2 Overlay 布局

`PlayerView.SubtitleOverlayLayer()` 建议拆分为主/第二字幕 overlay：

- 主字幕：继续由 VLC 渲染，不进入 SwiftUI overlay。
- 第二字幕：使用 SwiftUI overlay，未手动调整时默认靠近视频区域底部；用户可点击第二字幕或 loading 文案附近进入调整模式，再上下拖动到想要的位置。

推荐默认策略：

- 主字幕在底部时，第二字幕未手动调整也默认靠近底部，但预留主字幕安全间距，避免直接压在主字幕上。
- 若用户关闭主字幕，只开第二字幕，第二字幕继续使用同一默认底部位置；如需更高位置由用户手动拖动。
- 控制层显示时，第二字幕位置不应漂移；用户可通过拖动避开实际遮挡区域。
- 第二字幕显示或加载中时，允许用户点击字幕所在区域进入位置调整模式，显示带安全 padding 的无描边轻量背景后可上下拖动，保存为视频区域内的自定义垂直比例；点击画面其他区域应收起调整框；未手动调整时默认靠近底部，不再提供独立位置预设菜单。
- 第二字幕默认视觉应接近 VLC 主字幕：白色文字、黑色描边与轻微阴影，不使用突兀的整条黑色背景；字号应与底部主字幕接近，避免在双字幕场景里抢占主视觉。
- 第二字幕 Beta 开关关闭时不应渲染第二字幕 overlay，也不应在播放器字幕菜单中暴露第二字幕选项。

后续可增加设置：

- 第二字幕位置：画面内点击后显示无描边轻量背景，随后上下拖动并持久化自定义垂直位置。
- 第二字幕字号：小 / 标准 / 大。
- 第二字幕背景：无 / 半透明描边 / 半透明底。

## 10. UI 设计

播放器字幕菜单建议从单列表升级为两段：

```text
Subtitles
  Primary
    Off
    English
    Chinese Simplified
    Load Subtitle File

  Secondary
    Off
    English
    Chinese Simplified
    Japanese
```

交互规则：

- “Primary” 使用现有 `subtitleTracks`。
- “Secondary” 使用 `secondarySubtitleTracks`。
- 当前主字幕已选中的同一轨，在第二字幕里置灰或显示为不可重复选择。
- 不支持的图形字幕可以显示为置灰项，副标题说明“Image subtitles are not supported yet”。真正实现时这类用户可见文案必须接入全量本地化。
- 第二字幕加载中时显示轻量状态，不打断菜单操作。

旧系统兼容：

- iOS 15 及以下继续走现有自管浮层菜单路径。
- 原生 `Menu` 与 legacy overlay 都要保持同一组选项与同一套服务层方法。

## 11. 偏好记忆

第二字幕偏好不能只保存 stream index，因为不同集、不同版本、不同媒体源里轨道顺序可能变化。

建议保存以下信息：

- `trackID`：当前媒体内唯一键，用于精确恢复。
- `displayQuery`：语言、标题、codec 组合，用于跨集匹配。
- `language`：ISO 语言码或服务端语言名。
- `ordinal`：同类轨道序号兜底。

当前实现保存 `displayQuery` + `ordinal`，并按媒体来源分区：

- Jellyfin / Emby：使用现有 `provider + serverId + series/item scope` 键，和主字幕 query 偏好保持兼容但不复用同一个字段。
- 本地文件 / 普通远程文件：使用媒体 URL 的稳定 key，避免把第二字幕误写入主字幕偏好。

恢复优先级：

1. 当前 URL / 当前 item 或同剧集的第二字幕 `displayQuery`。
2. ordinal 兜底。
3. 无匹配时保持第二字幕关闭。

持久化位置：

- 单媒体偏好：使用 App 设置持久化本地 media key，不改变旧历史模型。
- 剧集级偏好：复用现有剧集级音轨/字幕偏好思路，新增 secondary subtitle 维度；旧的主字幕 query 仍只代表主字幕。
- 不持久化带 token 的导出 URL。

## 12. 缓存与安全

- 第二字幕缓存只放在 Caches，不进入用户 Documents。
- 本地内嵌字幕整轨导出的 SRT / ASS / VTT 与远程 Jellyfin / Emby 字幕流缓存都使用稳定 hash 文件名，重复选择时优先复用。
- 已解析的 `SubtitleTimeline` 在当前播放进程中使用小型 LRU 缓存，切回同一第二字幕时不重复读文件和解析。
- 删除服务器、清理缓存或媒体源变化时，应允许清理对应字幕缓存。
- 远程服务 token 不写入缓存文件名和持久化偏好。
- 解析失败日志中不能打印完整带 token URL。
- 本地 security-scoped URL 抽取完成后必须释放访问权限。

## 13. 与 PiP / 截图 / 投屏的关系

第一阶段 overlay 第二字幕只保证 App 内全屏播放器可见。

风险：

- 系统 PiP 或自管 sample-buffer PiP 默认只拿到 VLC 视频帧，不一定包含 SwiftUI overlay。
- VLC snapshot / 截图若直接取视频帧，也可能不包含第二字幕。
- AirPlay / 外接显示是否包含 overlay 需要单独验证。

后续增强路径：

- 双语 ASS 合成：把两条文字字幕合成一个临时 ASS，由 VLC/libass 作为单字幕轨渲染。
- PiP frame compositor：在 sample-buffer PiP 帧输出前把第二字幕绘制进帧。
- VLCKit 双字幕升级：如果上游稳定支持第二字幕，优先交给播放内核渲染。

## 14. 分阶段落地计划

### Phase 0：验证样本与功能开关

- 准备测试样本：
  - MKV + English SRT + Chinese SRT 内嵌。
  - MKV + ASS / SSA 内嵌。
  - MP4 + mov_text 内嵌。
  - Jellyfin / Emby 内嵌文字字幕媒体。
  - PGS / VobSub 图形字幕媒体。
- 新增内部 feature flag，默认关闭第二字幕实现。
- 不改变现有主字幕菜单和播放行为。

### Phase 1：Jellyfin / Emby 内嵌文字字幕第二轨

- 新增 `EmbeddedSubtitleTrack` / `SecondarySubtitleSelection` / `SubtitleTimeline`。
- 新增 `ServerEmbeddedSubtitleProvider`。
- 从 `serverMediaStreams` 中发现内嵌文字字幕。
- 按 stream index 导出字幕文件并缓存。
- 复用 `SubtitleModel` 解析，驱动 `secondarySubtitleParts`。
- 播放器菜单增加第二字幕分区。

### Phase 2：本地文件内嵌文字字幕抽取

- 已接入 AVFoundation 本地 subtitle extractor，覆盖 file URL / 下载中心本地文件中的 MP4 / MOV / M4V `tx3g` / `mov_text` 字幕。
- 已接入纯 Swift Matroska 文本 subtitle extractor，覆盖 MKV / WebM 的 `S_TEXT/UTF8`、`S_TEXT/ASS`、`S_TEXT/SSA`、`S_TEXT/WEBVTT`，并继续把 PGS / VobSub 标记为不可解析图形轨。
- 后续若要覆盖更多容器、lacing 边界或图形字幕，可再评估 libavformat / FFmpeg 类本地 subtitle extractor。
- 切换媒体、seek、退出播放器时正确取消抽取任务。

### Phase 3：远程文件与缓存协同

- 对正式下载文件直接使用本地抽取。
- 对已有自动缓存副本使用本地抽取。
- WebDAV / HTTP Range 读取可单独验证。
- SMB / FTP / SFTP / NFS 视协议能力决定是否接入自定义读接口。

### Phase 4：高阶渲染

- 双语 ASS 合成模式。
- 第二字幕独立样式与位置设置。
- PiP / 截图 / 投屏中的第二字幕合成。
- 评估 VLCKit 上游双字幕 API 或 mpv/libmpv 双字幕内核。

## 16. 回归要求

实现阶段至少验证：

- 本地视频仍默认全屏播放器。
- 主字幕开关、主字幕切换、字幕延迟不回归。
- 外挂字幕导入仍可用。
- 第二字幕加载失败不影响播放。
- seek 后主字幕与第二字幕均能回到正确时间。
- Jellyfin / Emby 播放、切集、跨集字幕偏好不回归。
- PiP 进入/退出不崩溃；若第二字幕不可见，要在交付说明中明确列为未支持。
- PGS / VobSub 置灰或不可选，不误导为已支持。

## 17. 待决策问题

- 本地抽取底层选型：直接集成 libavformat/FFmpeg、封装独立 extractor，还是等待 VLCKit 上游双字幕能力。
- AVFoundation extractor 只覆盖 Apple 媒体栈可读取的文字字幕；MKV 等容器仍需确定 libavformat / FFmpeg 集成方式。
- 是否允许第二字幕与主字幕选同一轨：建议 UI 禁止。
- 第二字幕默认位置：顶部更适合中英双字幕，底部上方更接近传统双语字幕。
- 第二字幕偏移是否独立于现有字幕延迟：建议保留独立偏移，同时叠加全局字幕延迟。
- ASS 高级样式何时支持：第一阶段不支持，后续可通过 libass 或双语 ASS 合成推进。
## 18. 无对白时的位置调整（2026-09-13）

- macOS / iOS 选中第二字幕后，当前时间无字幕也保留原位置的命中区域；适用于普通第二字幕、生成字幕和翻译。关闭第二字幕或 Beta 后不保留命中区域。
- macOS 无对白区域仅在鼠标悬停或位置调整激活时显示既有轻量背景及“第二字幕”提示，不与播放控制层显示联动。iOS 保留点击或直接拖动空区域的行为，仅激活位置调整后显示提示背景，未调整时不随播放控制层显示空框（2026-09-14）。
- 沿用原拖动范围、位置持久化、横竖屏适配及调整提示自动隐藏；拖动中字幕出现/消失不应中断操作。iOS 锁定和菜单展示时继续禁用该命中层。需在获批后验证两端空白时段、恢复对白、关闭第二字幕及原 seek/音量手势。
