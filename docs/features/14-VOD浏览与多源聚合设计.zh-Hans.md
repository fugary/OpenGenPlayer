## 1. 数据语义与现状

当前 `VODResponse` 将 `class` 解码为分类，将 `list` 解码为影片数组。它们是同一响应的不同维度，不是两种影片榜单。

| 数据 | 含义 | 展示用途 |
| --- | --- | --- |
| `class` | 分类目录，含 `type_id/type_name/type_pid` | 分类导航、父子分类 |
| `list` | 本次请求命中的一页影片 | 首页内容、分类结果、搜索结果或详情 |
| `total/pagecount` | 当前查询总量、总页数 | 数量及分页，不以已加载条数替代 |
| `vod_play_from/vod_play_url` | 单部影片在一个站点内的线路与分集 | 线路、选集 |

现有 `fetchCategories` 请求 `ac=list`；`fetchList` 请求 `ac=detail&pg=…`，分类增加 `t`；搜索增加 `wd`；详情增加 `ids`。没有请求热度排序，也没有消费热度字段。因此首页列表称“全部内容”或“浏览”，不能称“热门”。只有确认源站排序能力后才称“最近更新”；仅把一页按时间重排不代表全库最新。

三端已有单站分类、分页、详情及站内线路选择，缺少跨站搜索与跨站版本聚合。分类已解析父级，但现有浏览器主要平铺分类。当前 `VODItem.id` 仅为站内 ID，不能直接用于多站混合结果。

参考：2026-09-19 查看 [LibreTV 当前仓库说明](https://github.com/LibreSpark/LibreTV)。其聚合搜索、跨源结果、换源与独立首页推荐值得借鉴；首页推荐与资源 API 列表是不同数据来源。本提案采用原生客户端架构，不依赖部署 LibreTV 服务。

## 2. 页面结构

### 单个资源站首页（macOS 已确认）

顶部保留服务器名称、原生搜索与直接刷新，沿用 Jellyfin 首页的按钮配置；不展示分类下拉或仅含刷新的更多菜单。移除顶栏下重复的快捷分类条；网格/列表切换只在分类与搜索结果页显示。

1. 轮播：默认 `list` 中去重后的最多八部影片，使用原比例竖海报与片名、元信息、简介并列；点击海报或“查看详情”进入详情。不标热门，也不将默认列表宣称为最新。当前模型没有独立横图字段，不伪造横图能力。
2. 一级分类分区：按源站一级分类顺序，每类横向展示最多十二张海报，并提供“查看全部”。动作、喜剧等二级分类不再分别铺满首页。分区卡片省略重复分类名，保留年份及更新角标。
3. 分类入口：通过每个一级分类分区的“查看全部”进入；空分类也保留分区标题与入口。异常父级或环路保持平铺可达，不无限递归。

轮播每七秒切换一次，支持前后按钮与暂停/播放。手动切换后暂停自动播放；悬停、隐藏、App 非活动或启用减少动态效果时停止自动切换。缺图使用占位，不放大模糊海报；只有一个候选时隐藏轮播控制。继续观看暂未接入，作为后续独立能力。

### 分类页与查询边界

进入一级分类后，顶部标签显示该分类名，筛选为“全部 + 该分类的二级分类”。“全部”对应当前一级分类 ID，不指向全站。返回首页可切换其他一级分类。数据返回后按既有网格/列表展示，进入详情返回保留页面实例；房子按钮回站点首页，退出才离开服务器。

列表与首页分区优先查询对应 `t`。当父分类首批为空或请求失败，且存在有效子分类时，转为叶子分类聚合。按源站顺序轮转，每批最多查询三个叶子分类、顺序执行；每个分类维护独立页码与结束状态，跨分类/跨页按站内 ID 去重，同批结果交错排列避免首个细分类占满预览。

聚合数量只显示“已加载 N 项”，不累加各分类总量冒充唯一影片总数，也不显示虚构页数；使用显式“加载更多”。失败子分类不推进游标，后续批次仍可重试；全批失败显示重试，部分失败保留成功内容。首批为空但还有其他分类未读取时，仍保留进入完整列表及继续加载入口。取消后不发起新的子分类请求，只有匹配当前请求身份的游标快照可提交。

### 布局、加载与去重

首页默认列表先显示，分类接近可见区域后排队加载；首页最多一个请求进行中，不一次加载所有分类的详情或全部分页。刷新保留已加载内容，单行失败提供本行重试。轮播与分类海报允许展示同一影片，避免轮播候选耗尽小分类；各分区内部仍去重。

海报固定 2:3、标题两行固定高度、元信息固定高度；缺图有稳定占位，列表整行可点击。保留首页与结果页实例以维持返回位置，隐藏页面禁用交互并取消数据任务。实际窗口缩放、原生菜单、滚动与轮播焦点仍须在获批后验证，不以构建替代 GUI 结论。

### 聚合入口

在“网络”页 VOD 区增加“搜索所有资源站”，保留每个已有服务器的直达入口；无需新增应用根 Tab。站内搜索默认“当前站点”，可显式切换“所有已启用站点”。只有一个站点时简化范围选择。

聚合入口以搜索和已有继续观看为主，不把所有站点默认列表拼成一个所谓热门榜。首期不跨站统一分类 ID，也不汇总各站 `total` 冒充去重影片总量。

```mermaid
flowchart LR
    N[网络 / VOD] --> S[单资源站首页]
    N --> A[搜索所有资源站]
    S --> C[分类 / 分页影片]
    S --> A
    C --> D[影片详情]
    A --> R[聚合结果：影片 + 来源数量]
    R --> D
    D --> P[资源站 → 线路 → 分集 → 播放]
```

### 搜索结果与详情

结果卡片示例：“示例剧 · 2024 · 3 个来源”；无法确定同一作品时分开显示并标注站点。点击后在详情顶部提供“资源站”选择，其下是该站点的“播放线路”，最后是选集。

来源列表显示站点名、年份/季信息、更新状态与线路数，便于识别版本差异。默认沿用用户为本作品明确选过的来源，其次采用服务器顺序；后台返回新结果不能改变当前选项或使卡片不断跳位。

单站详情提供“查找其他来源”，用户触发后再跨站搜索。第一阶段只有用户选择才换源，不因缓冲或短暂错误自动切换。

## 3. 多源模型与请求

### 配置复用

继续以 `AppNetworkService.shared.savedServers` 中 `.vod` 服务器为来源及顺序的唯一事实来源，不新增平行的服务器仓库。新增可选 `vodSearchEnabled`，旧配置缺字段默认为启用，但隐私站点锁定时不参与搜索、数量或海报展示。禁用聚合只影响跨源请求，单站浏览仍可用。

聚合模块每次执行读取当前可访问服务器快照，删除、禁用或重新锁定后取消相关请求并清除结果。服务器及凭据删除继续走现有级联流程。新偏好解码须向后兼容；失败恢复默认，不覆盖旧服务器配置。凭据仍仅入 Keychain。

### 身份与匹配

新增 `VODSourceItemKey(serverID, vodID)` 作为站点资源唯一身份；`VODSearchHit` 保存来源、影片与匹配依据；`VODAggregateItem` 只负责当前结果展示分组，不能取代历史/收藏的真实资源身份。

合并优先可靠的同体系外部作品 ID（当前模型没有，需后续适配）；否则使用规范化片名 + 年份 + 内容类型 + 明确的季/版本信息。规范化只清理空格、大小写及无语义标点，保留季数、上下部、导演剪辑版等差异。仅同名、字段缺失或互相矛盾时不自动合并；可在详情列为其他候选。每次选择继续保留原始站点详情，不混用不同来源的演员、简介和集表。

### 搜索执行建议

- 新增 VOD 专用聚合协调器，复用 `VODService.search`，不改 Jellyfin/Emby/Plex 搜索语义。
- 默认防抖 400ms，同时最多四个站点请求；首批每站仅第一页，结果逐站呈现。
- 每个站点独立维护页码、结束与失败状态；“加载更多”公平请求未结束来源的下一页。展示已加载去重数量，不能声称这是跨站总量。
- 单请求超时建议 10 秒；后续页面由用户触发，不一次遍历全部页码。不因一个源失败丢弃其他结果，也不无限自动重试。
- 状态区使用“已完成 4/6 个来源”，失败来源可单独重试；全部成功但无结果与全部请求失败分别呈现。
- 查询、范围或权限变化生成新请求身份并取消旧请求；迟到结果不得写入新结果集。
- 分类缓存按站点隔离；搜索缓存建议内存五分钟，键包含站点、查询、页码及配置版本，限制容量，隐私锁定即清理。
- 请求成功仅表示接口可用；播放能力需单独判断，不显示未经验证的“可播放”或把接口延迟称为播放速度。

### 接口适配

现有 endpoint builder 通过是否包含 `api.php` 判断补全路径，不能覆盖任意 API URL。接入多源前应区分“站点根地址”和“完整 API 地址”，保留完整地址、必要查询参数并按键替换请求参数，避免重复 `ac/pg/wd`。不同源的搜索动作差异由 VOD 适配层明确配置/探测，不扩大通用网络服务。

首期手动添加标准 HTTP(S) MacCMS JSON 源；之后可加入批量 JSON 导入及订阅更新。导入应预览增改项、识别重复、保留用户禁用与排序，订阅失效不自动删除已有源。LibreTV/TVBox 的具体格式必须按版本适配；网页地址、需要 JS/爬虫插件的源不能宣称直接兼容。

## 4. 换源与播放连续性

必须分清“资源站”（多个 API）与“播放线路”（同站的 `vod_play_from`）。首期详情支持手动选择站点与线路，选集后仍交给原 VLC 播放链路。

后续播放器换源时：先匹配作品版本，再按季号、集号与集名匹配；禁止按数组下标映射。特别篇、预告、上下集或缺集存在歧义时让用户选择，不能自动播放错误分集。

进度默认仅在原资源恢复。跨源进度只有分集和版本确认、时长接近且用户同意续播时迁移，提供从头播放选项；时间相近也不能保证剪辑一致。保留原资源记录，新增来源偏好用独立可丢弃存储，避免破坏旧历史身份。首期接受不同来源的历史独立显示。

切源/取消/退出让旧准备与回调失效，保留暂停状态。无需迁移无关平台加载策略。显式播放失败可提供手动换源；不把短暂缓冲视为失败。真实媒体 URL、重定向、请求头与格式仍需单独验证，API 搜索成功不能证明 VLC 可播放。

## 5. 平台适配与交付顺序

数据协议可共享，UI 分端实现与验证。iOS 使用原生导航搜索与范围选择；macOS 使用原生搜索和列表/网格；tvOS 使用按分类的横向海报列、显式行式焦点网格，遥控器确认才切换分类或来源，返回只退一级。搜索、分类、详情回退保留浏览现场。

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A | 单站首页分区、父子分类、术语区分 | 分类失败不阻断列表；分页数量正确；滚动与返回保留 |
| B | 多站搜索、来源标签、保守合并、详情手动换站 | 同 ID 不串站；同名不同年不误合并；慢源不阻塞；旧查询不回写 |
| C | 播放器换源、分集匹配及可选进度迁移 | 缺集/特别篇需确认；暂停与退出不被旧回调覆盖；旧历史可读 |
| D | 源列表导入/订阅、可选独立推荐 | 订阅失败保留配置；榜单标明来源；点推荐后实际查源 |

先完成 A+B 即可形成“更好浏览 + 类似 LibreTV 多源”的主要体验。外部热门榜单单独作为可选功能：需要明确提供商、缓存、失败降级与作品到资源站的匹配，不与 `list` 混同。

实现时所有新 App 文案同步八种发货语言。后续自动检查应覆盖分页、分组、请求取消、权限与迁移；纯构建按实际涉及平台执行。GUI 回归按 AGENTS.md 3.8 先获批准，按已实现范围抽样单源分类返回、跨源搜索与失败、换源分集和 tvOS 焦点。macOS 首版已通过纯构建、29 项首页及分类聚合状态断言、23 项既有 VOD 回归断言及 Shell 八语言一致性检查；没有真实源排序、播放、性能或 GUI 验证结论。

- iOS 首页未加载分区在标题下方的内容区域居中显示加载指示，避免把首次加载放在右侧“查看全部”的位置。
